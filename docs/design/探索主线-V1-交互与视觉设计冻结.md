## 一、设计目标与边界

探索主线用于串联用户明确关联的独立事项与复盘事实，形成一段可回看的长期行动历程。

```text
探索主线：学习拉二胡
├─ 事项：买一把二胡并尝试最简单曲子
│  └─ 复盘事实：购买完成；持琴姿势是主要卡点
├─ 事项：预约一次线下二胡体验课
└─ 事项：连续练习一周基础运弓
```

探索主线不是：

```text
类别
标签
项目
Todo 容器
计划
阶段看板
进度工具
```

本设计不改变既有事项状态机、复盘、方法、回收站、备份恢复或主线软删除语义。

当前运行事实：

```text
H5 → loopback API → Application → MySQL
MySQL = 当前 H5 运行数据源
```

当前 MySQL 快速接入 Sprint 未封板前，禁止探索主线的任何数据层、API 或前端编码。

## 二、一级导航

### 2.1 位置与层级

工作台采用以下一级导航：

```text
事项（默认、高频）｜探索主线（低频）｜设置
```

规则：

1. 默认仍进入「事项」。
2. 「探索主线」与「事项」「设置」处于同一全局导航层级。
3. 设置保持当前原位。
4. 探索主线不放入事项状态导航，不能与「想试试 / 已开始 / 已复盘」等事项状态并列。
5. 不展示主线数、事项数、完成率、进度、红点或待处理提示。

```text
┌───────────────────────────────────────────────────────────────────┐
│ Knowledge Base       [事项]  [探索主线]              搜索  设置   │
└───────────────────────────────────────────────────────────────────┘
```

### 2.2 视图切换

```text
事项视图 → 探索主线视图：保留此前事项状态筛选与选中事项。
探索主线视图 → 事项视图：恢复此前事项状态筛选与选中事项。
查看事项：例外，必须按真实事项状态重新定位并打开对应详情。
```

## 三、桌面端布局

### 3.1 列表—详情结构

桌面端采用：

```text
左侧：探索主线列表，负责定位
右侧：当前探索主线详情，负责理解、上下文捕获与历史回看
```

```text
┌──────────────────────────── 主线列表 ─────────────────┬──── 主线详情 ─────┐
│ 探索主线                                  [+ 新建]    │ 学习拉二胡         │
│                                                       │                    │
│ 学习拉二胡                                            │ 当前关联事项       │
│ 最近：预约一次线下二胡体验课 · 已开始                 │                    │
│                                                       │ 在此主线下记下想做 │
│ 学习 K8s                                              │ 的事               │
│ 最近：尝试本机安装 Minikube · 已复盘                  │                    │
│                                                       │ 探索历史           │
│ 建立晨跑习惯                                          │                    │
│ 暂无关联行动                                          │                    │
│                                                       │                    │
│ ──────────────────────────────────────────────        │                    │
│ 已删除主线                                            │                    │
└───────────────────────────────────────────────────────┴────────────────────┘
```

探索主线详情不复制完整事项操作面板。其职责是：

```text
回看长期过程
→ 在当前长期上下文内记下想做的事
→ 定位到某条真实事项
```

事项工作台仍负责：

```text
开始行动
开始复盘
暂停
放弃
编辑事项补充
查看完整复盘、方法与历史
```

### 3.2 主线列表

每条活跃主线显示：

```text
主线名称
最近关联事项标题 · 真实事项状态
```

没有关联事项时显示：

```text
暂无关联行动
```

列表排序只消费架构读模型：

```text
活跃主线按 updatedAt 倒序；同一时间按 id 升序。
```

前端不得按关联次数、事项标题、事项状态或复盘内容自行重新排序。

列表中禁止显示：

```text
事项数量
完成数量
完成率
进度条
连续天数
阶段目标
截止日期
优先级
```

### 3.3 已删除主线管理入口

左侧列表底部提供低强调入口：

```text
已删除主线
```

该入口的唯一读取来源为：

```text
GET /api/v1/exploration-tracks/deleted
```

规则：

- 仅展示软删除主线；
- 仅使用 API 返回的固定排序：`deletedAt DESC, id ASC`；
- 已删除主线不出现在正常活跃主线列表；
- 已删除主线不出现在任何主线选择器；
- 不显示已删除主线数量；
- 已删除主线管理为只读列表；
- 在该区域仅允许通过历史详情查看事实，以及恢复主线；
- 不提供改名、主线内捕获、事项关联调整或永久删除；
- V1 不提供永久删除。

已删除主线详情只允许使用：

```text
GET /api/v1/exploration-tracks/:id/history
POST /api/v1/exploration-tracks/:id/restore
```

不得从活跃主线列表中本地筛选已删除记录，也不得调用活跃主线选择器获取已删除主线。

## 四、主线详情

### 4.1 固定信息层级

右侧详情固定按下列顺序展示：

```text
主线名称与低频管理
→ 当前关联事项
→ 主线内上下文捕获
→ 探索历史
→ 已放弃记录（按需展开）
```

以上结构仅适用于活跃主线。

当主线详情读模型的 `lifecycle = deleted` 时，右侧进入只读模式：

```text
主线名称与已删除说明
→ 当前关联事项（只读）
→ 探索历史（只读）
→ 已放弃记录（只读、按需展开）
→ 恢复
```

已删除主线详情不得显示主线内捕获、改名、移入已删除主线、关联调整或永久删除操作。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 学习拉二胡                                            [更多 ▾]      │
│                                                                    │
│ 由独立行动与复盘组成；不代表计划或完成进度。                        │
│                                                                    │
│ 当前关联事项                                                       │
│ 已开始  预约一次线下二胡体验课                            [查看]  │
│ 开始时准备：联系附近的一家琴行                                     │
│                                                                    │
│ 在「学习拉二胡」下记下想做的事                                      │
│ [例如：预约一次线下二胡体验课_______________________________]     │
│ 自动归入：学习拉二胡  [调整]                                        │
│ [加入想试试]                                  [加入以后再说]       │
│                                                                    │
│ 探索历史                                                           │
│ 2026-07-20                                                        │
│ 已复盘  买一把二胡并尝试最简单曲子                       [查看]   │
│ 购买完成；练习中发现持琴姿势是主要卡点。                          │
│                                                                    │
│ 查看已放弃记录 ▾                                                   │
└────────────────────────────────────────────────────────────────────┘
```

### 4.2 主线头部与低频管理

头部说明固定为：

```text
由独立行动与复盘组成；不代表计划或完成进度。
```

`更多` 菜单仅包含：

```text
改名
移入已删除主线
```

禁止在主线头部增加：

```text
目标
描述
阶段
进度
完成率
计划
日期
提醒
自动下一步
```

### 4.3 当前关联事项

当前关联事项的唯一数据来源为主线详情接口：

```text
GET /api/v1/exploration-tracks/:id/history
→ currentAssociatedItems
```

前端不得从 `history`、`abandonedHistory`、本地缓存、标题、时间或状态文本中筛选、拼装或推断当前关联事项。

展示范围与固定阅读顺序为：

```text
doing
→ idea_to_try
→ idea_later
→ paused
```

用户侧对应文案为：

```text
已开始
→ 想试试
→ 以后再说
→ 已暂停
```

每个状态最多展示 API 返回的 3 条事项；条目顺序只使用 API 已冻结的：

```text
createdAt DESC, id ASC
```

上述为阅读顺序，不是系统优先级判断。

条目规则：

| 真实事项状态 | 显示信息 |
|---|---|
| `doing` / 已开始 | 状态、标题、非空启动动作、查看 |
| `idea_to_try` / 想试试 | 状态、标题、查看 |
| `idea_later` / 以后再说 | 状态、标题、查看 |
| `paused` / 已暂停 | 状态、标题、低强调“当前暂时停止投入”、查看 |

当 `currentAssociatedItems` 的所有四个状态组均为空时，显示：

```text
还没有关联行动。
```

当某个状态组仅由 API 返回：

```text
hasMore: true
+ moreLocator
```

时，显示：

```text
查看该状态下的事项
```

点击后必须：

```text
切回事项工作台
→ 使用 moreLocator 的真实 status 与 explorationTrackId
→ 调用 GET /api/v1/items?status=<status>&explorationTrackId=<trackId>
→ 按 API 返回的真实状态重新读取并展示事项
```

前端不得从主线历史、本地缓存或标题自行筛选、截断、排序或推断该状态下的事项；不得展示总数、剩余数、完成率、进度、计划或日期。

### 4.4 主线内上下文捕获

主线详情内提供上下文捕获：

```text
在「学习拉二胡」下记下想做的事
[例如：预约一次线下二胡体验课________________]

自动归入：学习拉二胡  [调整]

[加入想试试]                     [加入以后再说]
```

规则：

1. 该入口沿用既有快速捕获的单句输入、两种初始状态选择。
2. 不增加补充、日期、标签、优先级、计划或步骤。
3. 事项创建与关联当前主线必须由单次原子 Contract 完成。
4. 用户可通过「调整」改为另一条活跃主线或取消关联；默认不展开。
5. 成功后清空输入，新事项显示在当前主线的正确区域，且不跳转事项详情。
6. 创建失败时保留输入、关联选择和初始状态选择，并显示明确失败提示。

### 4.5 探索历史

探索历史是关联事项的事实时间线，不是任务清单、阶段树或进度轨道。

排序只使用架构冻结的可信事实：

```text
按事项 createdAt 倒序；同一创建时间按 id 升序。
回收站事项不进入主线历史。
```

历史中已复盘事项展示：

```text
2026-07-20

已复盘
买一把二胡并尝试最简单曲子                     [查看]

购买完成；练习中发现持琴姿势是主要卡点。
```

复盘摘要规则：

- 仅展示 Application 读模型返回的 `actualAction` / `result`；
- 最多两行，超出省略；
- 不得从事项标题、补充、方法名称或任意其他文本拼接；
- 没有可信结构化摘要时显示：

```text
复盘详情请在事项中查看。
```

### 4.6 已放弃记录

已放弃事项不混入主历史，默认收纳为：

```text
查看已放弃记录 ▾
```

展开后使用与历史一致的条目样式，显示真实状态、标题、可信复盘摘要或降级文案与查看入口。

不使用：

```text
红色失败态
删除线
未完成标签
羞耻化文案
```

### 4.7 空态、加载与读取失败

空主线详情：

```text
还没有关联行动。
你可以在这里记下一件想做的事，
它会自动归入「学习拉二胡」。
```

主线列表空态：

```text
还没有探索主线。

探索主线用于串联独立行动与复盘事实，
形成一段长期行动历程。

[新建探索主线]
```

加载中：

```text
正在载入探索历史…
```

- 保留已加载的主线列表和已选主线名称；
- 使用详情骨架，不显示“暂无关联行动”。

读取失败：

```text
暂时无法载入探索历史。
[重试]
```

- 不将读取失败伪装为主线空态；
- 不清空当前已选名称；
- 不清空用户正在输入的上下文捕获草稿。

## 五、主线创建、改名、删除与恢复

### 5.1 独立创建

入口：

```text
探索主线列表 → [+ 新建]
```

使用轻量 Modal：

```text
新建探索主线

名称
[学习拉二胡________________________]

[取消] [创建]
```

| 状态 | 设计行为 |
|---|---|
| 初始 | 创建按钮不可用，直至非空名称可提交 |
| 创建中 | 输入与按钮锁定；按钮显示“正在创建…” |
| 成功 | 关闭 Modal；新主线出现在活跃列表并被选中；右侧显示空主线详情 |
| 空白 | 行内显示“主线名称不能为空” |
| 超过 80 字符 | 行内显示“主线名称最多 80 个字符” |
| 同名冲突 | 保留输入；显示“已存在同名探索主线”；提供“查看已有主线”弱入口 |
| 一般失败 | 保留输入与焦点；显示“创建未完成，请重试。” |
| 未知写入结果 | 不自动重试；显示“无法确认是否已创建，请刷新列表确认。” |

同名冲突覆盖已删除主线。若已有主线处于删除状态，用户应通过“查看已有主线”进入已删除主线管理区恢复，不能创建同名副本。

### 5.2 改名

入口：

```text
主线详情 → 更多 → 改名
```

采用原位标题编辑：

```text
[学习拉二胡________________] [保存] [取消]
```

规则：

- 编辑期间保留详情上下文，其余内容弱化；
- `Esc` 或取消不写入，恢复原名称；
- 保存中禁止重复提交；
- 空白、超长、同名冲突或请求失败时保留输入并显示稳定错误；
- 成功后右侧标题和左侧列表即时更新；
- 改名不改写关联事项、复盘或历史事实。

### 5.3 软删除确认

入口：

```text
主线详情 → 更多 → 移入已删除主线
```

确认层：

```text
移入已删除主线？

「学习拉二胡」将不再出现在主线列表和选择器中。
关联事项、复盘和历史事实不会被删除或解除关联。

[取消] [移入已删除主线]
```

删除成功后：

```text
关闭当前详情
→ 选中下一条活跃主线
→ 若无活跃主线，显示主线列表空态。
```

不使用“清理数据”“已永久删除”等文案。

### 5.4 恢复确认

入口：

```text
已删除主线 → 选择主线 → [恢复]
```

确认层：

```text
恢复探索主线？

恢复后，仍关联这条主线的事项会重新在主线历史中可见。

[取消] [恢复]
```

恢复成功后：

```text
回到活跃主线列表
→ 选中已恢复主线
→ 展示恢复后的真实历史。
```

恢复失败：

- 保持在当前已删除主线详情；
- 显示结构化错误；
- 不自动改名、合并或新建替代主线；
- 若出现名称冲突，显示：

```text
无法恢复：存在同名探索主线。
```

## 六、快速捕获中的可选关联

### 6.1 默认态

快速捕获保持原有低阻力路径：

```text
[一句话输入____________________________]

[加入想试试]  [加入以后再说]
```

主线关联永远可跳过。

### 6.2 选择已有主线

按需展开入口：

```text
归入探索主线（可选） ▾
```

展开后：

```text
归入探索主线
[搜索主线______________________________]

学习拉二胡
学习 K8s
建立晨跑习惯

[+ 新建并归入]
```

选择已有主线后：

```text
归入：学习拉二胡  [移除]
```

选择器只显示活跃主线，按架构读模型提供的稳定名称顺序展示；不得显示已删除主线或按关联次数排序。

### 6.3 创建并归入

「新建并归入」只打开未提交的表单选择层：

```text
新探索主线名称
[学习拉二胡________________]

[取消] [确认选择]
```

在输入名称、切换选择、打开该选择层或点击“确认选择”时：

```text
不创建探索主线
不创建事项
不创建初始状态事件
不写入任何关联
```

确认选择后，快速捕获表单仅显示待提交选择：

```text
归入：新主线「学习拉二胡」  [移除]
```

此时新主线名称只是前端未提交表单数据。用户仍需明确点击：

```text
加入想试试
或
加入以后再说
```

只有该最终提交动作才发送一次：

```text
POST /api/v1/items
```

请求携带：

```text
explorationTrack: { type: 'new', name: '学习拉二胡' }
```

后端在单一原子事务中完成：

```text
创建主线
→ 创建事项
→ 创建初始状态事件
→ 写入事项与主线关联
→ 全部成功后提交
```

只有全部成功后，界面才显示事项创建成功与主线关联成功。

若任一步失败：

```text
不留下主线、事项、初始状态事件或关联半成品；
保留事项输入、新主线名称和初始状态选择；
显示明确失败提示，允许用户重试或修改。
```

若发生超时、断线、页面关闭或响应丢失等未知写入结果：

```text
不自动重试；
不根据本地表单推断成功或失败；
保留草稿；
提示“提交结果未确认，请重新获取真实数据后确认是否已生效”。
```

用户点击 `移除` 或在选择层点击 `取消` 时：

```text

```

独立入口：

```text

```

仍允许使用 `POST /api/v1/exploration-tracks` 创建空主线；它与快速捕获的“新建并归入”表单选择语义不同。

### 6.4 取消关联选择

后回到：

```text

```

这只清除尚未提交表单中的关联选择，不产生业务写入。

## 十一、异步与用户输入保护

1. 创建、改名、删除、恢复、归入、改归入、移除关联期间禁止重复提交。
2. 除用户明确取消外，所有失败态必须保留输入。
3. 未知写入结果不自动重试，只允许重新读取真实状态。
4. 切换主线、关闭页面或开启新请求后，旧请求晚返回不得覆盖当前列表、详情或输入。
5. 主线内捕获成功后，只清空已成功提交输入，不跳转事项详情。
6. 主线内捕获失败后，标题输入、关联选择和初始状态选择必须完整保留。
7. “创建事项 + 关联主线”只能使用单次原子 Contract；前端不得先创建事项、后补写关联。
8. 前端只消费 API / Application 的结构化读模型，不持久化业务镜像，不回退 IndexedDB，不补全关联。

## 十二、人工验收要点

### 导航与布局

1. 默认进入事项；探索主线可通过低频一级入口访问；设置位置不变。
2. 桌面端主线为左列表 / 右详情；两侧独立滚动。
3. 小屏为列表 → 全屏详情 → 返回列表，操作无需 hover。

### 主线生命周期

4. 可创建空主线；创建后显示空主线引导。
5. 空白、超长、同名、请求失败与未知写入结果均有稳定且诚实的反馈。
6. 改名成功同步更新列表与详情，不改变事项、复盘或历史。
7. 软删除主线不会删除、解除或改写关联事项与复盘。
8. 恢复主线后，仍关联的非回收站事项重新在历史中可见。
9. 不存在永久删除入口。

### 关联与捕获

10. 全局快速捕获不选主线时，既有行为不变。
11. 选择已有主线时，主线、事项、初始状态事件与关联以可信原子写入完成；选择新主线时，在最终点击“加入想试试”或“加入以后再说”前不产生任何主线写入。
12. 取消尚未提交的已有 / 新主线关联选择不产生写入；新主线选择只作为表单暂存。
13. 主线内捕获成功后停留在当前主线，失败时草稿完整保留。
14. 一条事项只能关联零或一条主线。

### 历史与降级

15. 当前关联事项仅来自 `GET /api/v1/exploration-tracks/:id/history` 的 `currentAssociatedItems`；固定按 `doing → idea_to_try → idea_later → paused` 展示，每状态最多 3 条。
16. 所有当前关联为空时显示“还没有关联行动。”；超出仅在 API 返回 `hasMore + moreLocator` 时显示“查看该状态下的事项”。
17. 该入口按 `moreLocator` 调用受限事项查询并重新读取真实事项；不得从历史或本地缓存筛选、截断、排序或推断。
18. 主线历史按真实事项创建时间展示；回收站事项不出现。
19. 已放弃事项默认收纳，展开后仍保留查看入口。
20. 已复盘摘要只使用结构化事实字段；缺失时显示“复盘详情请在事项中查看”。
21. 已删除关联显示真实已删除主线名称与“已删除”状态，不伪装为无关联；不显示调整、移除或选择器入口，不自动清空、重连或改归入。调整或移除请求须稳定拒绝且零副作用；恢复原主线仅可通过已删除主线管理区。
22. 不可用关联诚实显示不可用，不自动清空、重连或允许掩盖性调整。
23. 已删除主线列表仅来自 `GET /api/v1/exploration-tracks/deleted`，按 `deletedAt DESC, id ASC` 只读展示；不显示数量、不进入选择器且不提供永久删除。

### 定位与边界

21. 点击任一“查看”都返回事项工作台真实状态池，并重新打开真实事项详情。
22. 不出现进度、完成率、事项计数、计划、日期、提醒、子任务、看板、自动下一步、AI 推荐或多主线关联。
23. 所有数据只经现有 loopback API / Application / MySQL 链路读取；不出现 IndexedDB fallback、浏览器直连 MySQL 或前端关系推断。
