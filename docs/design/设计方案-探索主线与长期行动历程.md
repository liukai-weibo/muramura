# 设计方案：探索主线与长期行动历程

## 一、结论

为承接「学习二胡」「学习 K8s」「建立运动习惯」等长期发展方向，新增一个候选业务对象：

```text
探索主线
```

探索主线不是类别、标签、项目、Todo 容器或计划；它用于把多个独立事项及其复盘事实，串联为一条可回看的长期行动历程。

核心关系：

```text
探索主线：学习拉二胡
├─ 事项：买一把二胡并尝试最简单曲子
│  └─ 复盘：购买完成；持琴姿势是主要卡点
├─ 事项：预约一次线下二胡体验课
│  └─ 复盘：……
└─ 事项：连续练习一周基础运弓
   └─ 复盘：……
```

每条事项仍保持一事一记录，独立进入现有状态与复盘闭环。

探索主线不自动生成下一阶段灵感、不定义步骤、不追踪进度，也不要求事项必须归属某条主线。

---

## 二、用户问题

长期学习、习惯养成或持续探索通常由多轮独立行动构成：

```text
学习拉二胡
→ 买二胡并尝试简单曲子
→ 解决基础姿势
→ 连续练习一周
→ 学习第一首完整曲子
```

每轮行动都应：

```text
独立开始
独立结束
独立复盘
```

但用户回看时，也需要知道：

```text
这些行动属于同一个长期发展过程；
我在这条路上做过什么、遇到什么、如何调整。
```

单一长期事项会滑向子任务、勾选与进度管理；仅用类别或标签又无法表达可信的过程与证据关系。

---

## 三、目标

建立如下结构：

```text
长期层：探索主线
→ 我持续在探索、发展或验证什么？

行动层：事项
→ 我这次准备真实尝试什么？

判断层：方法
→ 从事实中，什么做法或判断值得复用、验证或修订？
```

其中：

```text
探索主线 = 长期发展脉络
事项 = 一次具体、可行动、可复盘的尝试
方法 = 基于事实形成的可复用判断
```

探索主线与方法不能互相替代：

| 对象 | 回答的问题 | 二胡案例 |
|---|---|---|
| 探索主线 | 我长期在走哪条路、做过哪些行动？ | 学习拉二胡 |
| 事项 | 我这次具体尝试什么？ | 预约二胡体验课 |
| 方法 | 从事实中学到什么可迁移做法？ | 先用一次线下校准解决姿势，再进入长期练习 |

---

## 四、核心业务定义

### 4.1 探索主线

定义：

```text
探索主线
= 用户主动定义的一条长期发展、学习、习惯养成或持续验证脉络。
```

它只表达：

```text
这些独立事项共同服务于同一个持续探索。
```

它不表达：

```text
预设计划
子任务清单
完成率
截止日期
优先级
提醒
阶段自动推进
自动生成下一条行动
```

### 4.2 事项与探索主线的关系

第一版推荐约束：

```text
一个事项 → 0 或 1 条探索主线
一条探索主线 → 0 到多条事项
```

一条事项最多关联一条主线，避免多重归属、重复投影和关系复杂度失控。

关联必须是用户明确建立的结构化关系；不得根据标题、时间、复盘次数、文案或相似度自动推断。

---

## 五、用户创建探索主线

用户必须可主动创建探索主线。创建信息第一版仅需：

```text
探索主线名称（必填）
```

不新增：

```text
描述
愿景
开始日期
结束日期
优先级
标签
目标数值
阶段计划
提醒
任务模板
```

### 5.1 独立创建入口

```text
探索主线
[+ 新建探索主线]

名称
[学习拉二胡________________]

[取消] [创建]
```

允许空主线存在：用户可先明确长期方向，之后再关联真实事项。

### 5.2 捕获事项时创建

在「归入探索主线」的选择器内提供：

```text
[+ 新建探索主线]
```

用户输入名称并明确点击：

```text
[创建并归入]
```

才会原子建立：

```text
探索主线
+ 新事项与该主线的关联
```

不得隐式创建，避免用户不知道系统新增了什么对象。

### 5.3 名称规则

推荐由 Application 层冻结：

```text
去除首尾空格后不能为空；
同一规范化名称不可重复；
名称长度有合理上限。
```

是否为重复不得由前端以模糊匹配自行猜测。

---

## 六、捕获与关联

### 6.1 全局快速捕获

快速捕获保持既有低阻力基线：

```text
[一句话输入________________________________]

[加入想试试]  [加入以后再说]
```

不可强制主线归类。

用户有需要时，才按需展开：

```text
归入探索主线（可选） ▾
```

展开后：

```text
归入探索主线
[搜索或选择已有主线________________]

学习拉二胡
学习 K8s
建立晨跑习惯

[+ 新建探索主线]
```

选中后显示紧凑摘要：

```text
归入：学习拉二胡 ×
```

然后用户仍自行选择：

```text
[加入想试试] / [加入以后再说]
```

### 6.2 主线详情内捕获

探索主线详情提供上下文捕获入口：

```text
在「学习拉二胡」下捕获一个想做的事
[例如：预约一次线下二胡体验课________________]

将自动归入：学习拉二胡  [调整]

[加入想试试]                     [加入以后再说]
```

在此入口创建事项时：

```text
事项创建
+ 写入当前探索主线关联
```

必须作为原子语义完成，不能先创建事项，再由前端异步补写关系。

自动绑定只发生在用户明确从某条主线详情发起创建时。用户可通过「调整」改为另一条主线或不关联主线。

### 6.3 后续调整关联

用户可能先捕获、后理解归属，因此应允许：

```text
捕获时未关联
→ 后续在事项详情中归入主线

捕获时关联了 A
→ 后续调整为 B 或移除关联
```

关联是用户对长期发展路径的当前判断，不应在捕获时强迫一次分类正确。

## 七、探索主线的位置与界面

### 7.1 工作台一级低频导航

探索主线进入工作台的一级低频导航，不进入左侧事项状态切换器，也不藏入设置页。

```text
工作台全局导航
├─ 事项（默认、高频）
├─ 探索主线（低频）
└─ 设置
```

原因：

```text
事项状态回答：这件事现在怎么样？
探索主线回答：这些不同事项共同服务什么长期方向？
```

探索主线不是事项状态。若把它放进「想试试 / 已开始 / 已复盘」等状态导航，会错误暗示它是另一种事项状态。

默认进入应用仍是「事项」视图；探索主线用于用户需要回看长期历程，或在既有长期上下文内继续记下一件想做的事时主动进入。

桌面端一级导航：

```text
┌───────────────────────────────────────────────────────────────────┐
│ Knowledge Base       [事项]  [探索主线]              搜索  设置   │
└───────────────────────────────────────────────────────────────────┘
```

### 7.2 总体布局：列表负责定位，详情负责理解与行动

点击「探索主线」后，沿用桌面端既有工作模式：

```text
左侧：探索主线列表
右侧：当前探索主线详情
```

```text
┌──────────────────── 主线列表 ────────────────────┬──────── 主线详情 ────────┐
│ 探索主线                              [+ 新建]   │ 学习拉二胡                │
│                                                   │                            │
│ 学习拉二胡                                         │ 在此主线下记下想做的事    │
│ 最近：预约体验课 · 已开始                          │ [______________________] │
│                                                   │ 自动归入：学习拉二胡      │
│ 学习 K8s                                           │ [加入想试试] [以后再说]   │
│ 最近：安装 Minikube · 已复盘                       │                            │
│                                                   │ 探索历史                  │
│ 建立晨跑习惯                                       │ …                          │
│ 暂无关联行动                                       │                            │
└───────────────────────────────────────────────────┴────────────────────────────┘
```

不在主线详情中复制一套完整事项操作面板。主线负责：

```text
回看长期过程
→ 在明确上下文内捕获新的事项
→ 定位到某条关联事项
```

事项视图负责：

```text
开始行动
暂停、放弃
开始复盘
编辑事项补充
查看完整复盘、方法与历史
```

### 7.3 探索主线列表

列表用于定位，不承载过程详情或任务管理。

每条主线显示：

```text
主线名称
最近一条关联事项的标题 + 当前状态
```

示例：

```text
探索主线                                      [+ 新建探索主线]

学习拉二胡
最近：预约一次线下二胡体验课 · 已开始

学习 K8s
最近：尝试本机安装 Minikube · 已复盘

建立晨跑习惯
暂无关联行动
```

排序规则建议：

```text
有近期关联事项的主线：按最近关联事项的创建或状态更新时间倒序；
空主线：置于有事项主线之后，按主线创建时间倒序。
```

该排序仅用于帮助定位，不表示优先级、进度、完成度或系统推荐。

列表中不显示：

```text
事项总数
完成率
进度条
连续天数
阶段目标
截止日期
主线状态
```

理由：事项数量不是探索价值，完成比例也不能表达长期学习或习惯养成是否正在形成。

列表交互：

```text
点击一条主线
→ 右侧切换其详情与探索历史；
→ 不影响用户此前在“事项”视图中选中的状态和事项。
```

### 7.4 主线详情

右侧详情固定采用以下层级：

```text
主线名称与低频管理
→ 主线内捕获
→ 探索历史
```

桌面端线框：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 学习拉二胡                                            [更多 ▾]      │
│                                                                    │
│ 由独立行动与复盘组成；不代表计划或完成进度。                        │
│                                                                    │
│ 在「学习拉二胡」下记下想做的事                                      │
│ [例如：预约一次线下二胡体验课_______________________________]     │
│ 自动归入：学习拉二胡  [调整]                                        │
│ [加入想试试]                                  [加入以后再说]       │
│                                                                    │
│ 探索历史                                                           │
│                                                                    │
│ 2026-07-24                                                        │
│ 已开始  预约一次线下二胡体验课                              [查看] │
│ 开始时准备：联系附近的一家琴行                                     │
│                                                                    │
│ 2026-07-20                                                        │
│ 已复盘  买一把二胡并尝试最简单曲子                        [查看] │
│ 购买完成；练习中发现持琴姿势是主要卡点。                           │
│                                                                    │
│ 2026-07-14                                                        │
│ 以后再说  连续练习一周基础运弓                            [查看] │
└────────────────────────────────────────────────────────────────────┘
```

主线标题旁的「更多」仅放置低频管理动作，例如：

```text
改名
删除 / 归档（具体语义待产品与架构冻结）
```

不得在主线头部增加目标描述、进度、阶段计划、日程、提醒或任务汇总。

### 7.5 主线内捕获

主线详情的捕获区是上下文创建入口：

```text
在「学习拉二胡」下记下想做的事
[例如：预约一次线下二胡体验课________________]

自动归入：学习拉二胡  [调整]

[加入想试试]                     [加入以后再说]
```

规则：

1. 该入口创建的事项自动、原子地关联当前主线。
2. 用户仍自行选择初始状态「想试试」或「以后再说」。
3. 用户可通过「调整」改为另一主线或取消关联；默认不展开。
4. 创建成功后清空输入，并将新事项显示在探索历史顶部；默认不跳转事项详情。
5. 创建失败时保留输入并明确提示，不能显示“已归入”的假象。
6. 该入口不是子任务输入框，不允许勾选、批量添加、拆分步骤或自动生成下一阶段。

### 7.6 探索历史：按事实时间串联，不按计划阶段编排

探索历史是该主线已关联事项的时间序列，不是待办清单、步骤树或进度轨道。

#### 历史排序

```text
按事项创建时间倒序分组展示；
同一日期内按创建时间倒序；
不根据状态、标题、复盘内容或“预估阶段”重排。
```

采用创建时间是因为它忠实表达“这条长期探索是如何被用户逐步发起”的过程，且不会把后续状态变化误伪装成新的行动发生时间。

若架构已有可信的“最近一次有效业务事件时间”读模型，可作为未来备选；第一版不得由前端自行根据文本或状态事件猜测。

#### 每条历史记录的最小信息

| 事项状态 | 历史中显示 | 不显示 |
|---|---|---|
| 想试试 / 以后再说 | 状态、事项标题、创建日期 | 虚构的下一步、优先级或进度 |
| 已开始 | 状态、事项标题、开始时准备（非空才显示） | 执行日志或任务清单 |
| 已暂停 | 状态、事项标题、低强调“当前已暂停” | 暂停原因猜测 |
| 已复盘 | 状态、事项标题、复盘事实摘要（最多两行） | 成功率、奖励或情绪评分 |
| 已放弃 | 默认不进入主线主历史；按需从“查看低频记录”展开 | 红色羞耻化展示 |
| 回收站 | 不进入主线历史 | 已删除事项的伪历史 |

已复盘事项的摘要必须来自结构化复盘读模型；没有摘要或关联缺失时诚实降级为：

```text
复盘详情可在事项中查看。
```

不得由前端截取补充、标题或方法名称伪造复盘摘要。

#### 低频记录收纳

为避免主线历史被“已放弃”或“已暂停”淹没，默认历史展示：

```text
想试试
以后再说
已开始
已暂停
已复盘
```

其中 `已暂停` 采用低强调状态文本，不应隐藏其真实过程。

`已放弃` 在历史底部通过按需入口承接：

```text
查看已放弃记录（N） ▾
```

展开后按相同时间样式显示，并明确其是停止投入的判断历史，不等同于删除或失败。

回收站事项不进入探索历史；恢复后若可信关联仍存在，才重新回到对应主线的历史中。

#### 查看事项与回到事项工作台

每条历史记录提供弱操作：

```text
[查看]
```

点击后：

```text
切回“事项”视图
→ 自动选择该事项真实所属状态
→ 在右侧打开该事项详情
```

例如：

```text
学习拉二胡
→ 点击「预约一次线下二胡体验课 · 已开始」
→ 事项视图
→ 已开始
→ 右侧展示该事项详情
```

这样主线页面不复制事项详情操作，也不会让用户在两套页面中维护同一个事项。

### 7.7 空态、加载与异常

#### 空主线

```text
学习拉二胡

还没有关联行动。
可以在这里记下一件想做的事，
它会自动归入「学习拉二胡」。
```

不显示：

```text
进度 0%
暂无任务
完成 0 项
```

#### 加载中

保留标题与页面骨架，显示：

```text
正在载入探索历史…
```

不显示“暂无关联行动”，避免请求尚未完成时误导用户。

#### 读取失败

```text
暂时无法载入探索历史。
[重试]
```

已加载的主线名称和用户输入不得被错误清空；前端不能把读取失败降级成空历史。

### 7.8 小屏降级

小屏使用单列层级：

```text
[事项] [探索主线]

探索主线列表
→ 点击主线
→ 全屏主线详情
→ 返回列表
```

主线详情的内容顺序不变：

```text
名称与更多
→ 主线内捕获
→ 探索历史
```

事项记录与复盘摘要仍为纵向时间列表；点击「查看」切回事项视图并定位。不得把探索主线设计成底部 Tab、横向卡片墙或项目看板。

## 八、关键交互规则

1. 主线内创建后：
   - 清空输入；
   - 新事项显示在当前行动历程的相应位置；
   - 默认不跳转到新事项详情，避免打断连续捕获。

2. 空输入：

   ```text
   创建按钮不可用；
   不产生空事项或空关联。
   ```

3. 创建失败：

   ```text
   保留用户输入；
   明确提示创建未成功；
   不得显示“已归入主线”的假象。
   ```

4. 主线关联不改变事项状态机：

   ```text
   想试试 / 以后再说 / 已开始 / 已暂停 / 已放弃 / 已复盘 / 回收站
   ```

5. 主线不定义事项完成条件；不得以主线中的事项数量、状态或顺序推断进度。

6. 主线不自动创建后续事项。复盘后的下一轮行动必须由用户主动发起。

## 九、方法与探索主线的边界

探索主线不能替代现有「方法」。

```text
探索主线
= 我长期在走哪条路、做过哪些行动？

方法
= 从已有事实中，什么做法或判断值得在后续行动采用、验证或修订？
```

例如：

```text
探索主线：学习拉二胡

事项历程：
- 买二胡并尝试简单曲子
- 预约二胡体验课
- 连续练习一周基础运弓

方法：
新技能先用一次线下校准排除基础动作错误，
再决定是否进入长期练习。
```

若方法没有被后续事项采用、验证或修订，它会退化成低频整理；这应通过真实使用证据判断是否需要优化“方法应用”入口，而不是将方法与探索主线直接合并或删除。

```text
阶段模板

```

## 十一、数据生命周期与异常边界

探索主线及其关系必须覆盖：

```text
主线创建、改名、删除或归档
事项创建、调整关联、移除关联
事项状态流转
已放弃
移入回收站与恢复
主线删除或恢复
JSON 备份与恢复
旧备份降级
缺失关联的诚实展示
```

推荐原则：

```text
删除主线不删除关联事项及其复盘事实。
```

但主线删除是解除关联、进入回收站、归档还是其他策略，必须由产品与架构共同冻结；前端不得自行决定。

---

## 十二、验收标准

1. 用户可创建名称必填的探索主线。
2. 用户可先创建空主线，后续再关联事项。
3. 快速捕获保持单句输入与两按钮基线；主线关联永远可跳过。
4. 用户可在全局捕获时按需关联已有主线或创建并归入新主线。
5. 用户可在主线详情内直接创建事项，且该事项原子自动关联当前主线。
6. 用户可后续调整或移除事项关联。
7. 一条事项第一版最多关联一条探索主线。
8. 主线详情按时间展示关联事项及复盘摘要，形成真实行动历程。
9. 事项仍独立开始、暂停、放弃、复盘；主线不改变其状态机或完成条件。
10. 前一事项复盘后，不自动生成下一条事项。
11. 主线界面不出现子任务、完成率、进度条、日期、提醒或连续天数。
12. 删除、回收站、恢复及 JSON 备份恢复时，关联不丢失、不虚构，断裂关系诚实降级。

## 十三、待产品经理裁决

1. 正式用户名称是否定为「探索主线」，还是采用「长期探索」等替代名称。
2. 是否允许空主线。
3. 是否允许主线改名。
4. 是否在第一版定义主线自身状态：

   ```text
   探索中 / 已暂停 / 已结束 / 已放弃
   ```

   推荐第一版暂不引入，避免与事项状态重复和进度化。

5. 主线删除策略：解除关联、回收站或归档的最终业务语义。
6. 探索主线的工作台位置已确定为一级低频导航；默认仍进入「事项」视图，主线列表与详情用于回看历程、上下文捕获与定位事项。

## 十四、待架构评审

此能力涉及新增对象、关系、读模型与完整数据生命周期，架构师需评估：

```text
探索主线实体与事项 0..1 关联的最小数据模型；
MySQL Schema、Migration 与旧数据兼容；
JSON 备份与恢复格式及降级策略；
主线 → 事项 → 复盘的可信聚合读模型；
主线改名、删除、回收站、恢复时的关系语义；
事项删除、恢复、关联缺失时的稳定降级；
名称规范化与唯一性校验位置；
“创建事项 + 写入主线关联”的原子写入能力；
Application / Repository 契约、自动化测试与允许修改范围。
```
