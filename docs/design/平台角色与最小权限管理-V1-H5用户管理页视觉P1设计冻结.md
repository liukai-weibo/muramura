# 平台角色与最小权限管理 V1—H5 用户管理页视觉 P1 设计冻结

日期：2026-07-31

状态：最小视觉设计冻结完成；待产品经理签发前端修复授权；当前禁止编码

## 一、结论

真实 UAT 已证明用户管理功能链存在，但当前桌面页面的字号、按钮、搜索区、四列表格和分页呈现失控，不能作为可交付界面。本次只冻结用户管理页的视觉排版与 Taro H5 宿主样式，不改变既有产品、状态机或数据语义。

本文件是 `docs/design/平台角色与最小权限管理-V1-切片4-H5管理入口设计冻结.md` 的视觉 P1 补充。两者冲突时，仅视觉尺寸、排版、颜色与响应式规则以本文件为准；权限、交互、错误、operationId、写锁及 unknown-outcome 仍以原冻结文档为准。

## 二、范围与非目标

### 2.1 本次允许冻结的视觉范围

- 用户管理页标题、说明、表头、用户名、注册时间、角色标签、用户总数和分页文字。
- 刷新、搜索、清除、上一页、下一页、更多、确认及危险操作按钮的可见样式。
- 搜索输入框与按钮的桌面比例、对齐和小屏降级。
- 用户表格四列宽度、行高、对齐与当前账号标识。
- 紧凑分页布局。
- 用户管理页范围内原生 `button` 与 Taro H5 `taro-button-core` 的等价视觉规则。
- 桌面端与小屏人工视觉验收。

### 2.2 保持不变

- 用户列表、固定每页 20、字面量用户名搜索和稳定排序。
- `member` 与 `platform_admin` 的角色语义与标签映射。
- 当前账号不可调整自己的角色、不可从管理页撤销自己的会话。
- 角色调整、会话撤销、operationId、目标级写锁、旧请求保护和 unknown-outcome 流程。
- 401、403、404、409、503、requestId 与既有错误文案。
- API、Contracts、Application、Repository、Migration、Schema、数据库和运行环境。
- 不新增字段、筛选、批量操作、用户详情或业务能力。

## 三、页面骨架与桌面节奏

- 页面内容最大宽度保持 `1120px`，水平居中。
- 桌面页面内边距固定为 `24px`。
- 页面背景 `#FFFDF9`，边框 `1px solid #E1D9CC`，圆角 `12px`。
- 标题区与搜索区间距 `18px`；搜索区与表格间距 `16px`；表格与分页间距 `12px`。
- 桌面标题区单行左右布局：左侧标题与说明，右侧刷新按钮。
- 刷新按钮不得拉伸占满标题区，不得挤压标题，也不得离开可视区域。

- 字体缩放或浏览器默认样式不得使“注册于”与日期拆成异常大号多行。

## 五、按钮视觉规范

### 5.1 桌面基础尺寸

- 普通按钮高度 `40px`，最小宽度 `72px`，水平内边距 `14px`。
- “清除”最小宽度 `64px`；“刷新”“搜索”“上一页”“下一页”最小宽度 `72px`。
- 分页按钮桌面高度可收敛为 `36px`，但最小宽度仍为 `72px`。
- 圆角统一 `8px`，边框 `1px`，按钮内容水平垂直居中。
- 按钮文字必须单行，不允许透明、裁切、偏出宿主盒或被伪元素覆盖。

### 5.2 普通按钮

- 文字：`#413C35`。
- 背景：`#FFFDF9`。
- 边框：`#CFC4B5`。
- hover：背景 `#F4F0E9`，边框 `#B8AEA0`。
- active：背景 `#E9E2D8`，边框 `#A99E90`。

适用于刷新、清除、上一页、下一页、更多、取消和普通重读按钮。

### 5.3 主要按钮

- 文字：`#FFFDF9`。
- 背景与边框：`#5B554D`。
- hover：背景与边框 `#49433D`。
- active：背景与边框 `#37322D`。

适用于搜索与非危险确认操作。

### 5.4 禁用按钮

- 文字：`#6F675E`。
- 背景：`#EEEAE4`。
- 边框：`#DDD4C8`。
- `opacity: 1`，不得用整体半透明隐藏文字。
- cursor 为 `not-allowed`，且不可触发点击。
- 只有原生 `:disabled` 或 Taro 宿主 `[disabled='true']` 才可进入禁用态；`disabled='false'` 必须保持启用样式与命中能力。

### 5.5 危险按钮

危险确认按钮：

- 文字：`#FFFDF9`。
- 背景与边框：`#A14F3F`。
- hover：背景与边框 `#873E32`。
- active：背景与边框 `#713328`。

菜单或行内危险入口采用低强调样式：

- 文字：`#7D3023`。
- 背景：`#FFF6F2`。
- 边框：`#B86D5C`。

### 5.6 焦点与可见性

- 键盘焦点：`2px solid #817568`，外偏移 `2px`。
- 启用按钮的文字与背景对比度不低于 `4.5:1`。
- 禁用按钮文字仍须清晰可辨，不能以“看不见”表达不可用。
- 状态不得只依赖颜色；禁用同时依赖属性和不可点击行为。

## 六、Taro H5 宿主冻结

真实 H5 中 Taro `Button` 的视觉与命中宿主是 `taro-button-core`。用户管理页必须对原生 `button` 与 `taro-button-core` 应用同一规范，且只在 `.platform-administration` 内生效。

实现必须满足：

- 两类宿主均显式获得 `box-sizing`、display、align-items、justify-content、width、height/min-height、margin、padding、font-size、font-weight、line-height、color、background、border 和 border-radius。
- 桌面 `taro-button-core` 默认 `width: 100%` 必须在用户管理页内被覆盖为 `width: auto`；只有本文件规定的小屏满宽控件可以恢复 `width: 100%`。
- `taro-button-core` 的文字节点必须继承宿主的字号、行高、字重和颜色。
- 原生 `button::after` 与 `taro-button-core::after` 的框线或遮罩均须在用户管理页内清除。
- Taro 基础样式优先级高于页面规则时，可以在该页面的精确选择器上使用 `!important`；不得修改全局 Taro 按钮。
- 禁用选择器必须精确为原生 `:disabled` 和 Taro `[disabled='true']`，禁止使用会误伤 `disabled='false'` 的 `[disabled]` 存在选择器。
- 启用态必须 `pointer-events: auto`；禁用态才可 `pointer-events: none`。
- 刷新、搜索、清除、分页和确认层按钮在真实 Chromium 的可点击中心点，命中栈顶必须是按钮宿主自身。

## 七、搜索区冻结

### 7.1 桌面端

- 搜索区靠左，整体最大宽度 `680px`，不得缩成截图中的短小输入框。
- 使用单行布局：输入框、可选“清除”、主要“搜索”。
- 间距统一 `8px`。
- 输入框高度 `40px`，基础宽度使用弹性占位，桌面最小宽度 `320px`、建议可见宽度 `420–520px`。
- 输入框内边距 `0 12px`，字号 `14px`、行高 `20px`。
- 输入文字 `#413C35`，placeholder `#91897E`。
- 背景 `#FFFFFF`，边框 `#CFC4B5`，圆角 `8px`。
- focus 边框 `#817568`，并显示 `0 0 0 3px rgba(129,117,104,.14)`。
- 清除按钮仅在有输入时出现，但不得改变输入框高度或搜索按钮对齐。

### 7.2 小屏降级

在 `≤ 768px`：

- 输入框独占第一行，宽度 `100%`、高度 `44px`。
- 第二行为按钮区；有“清除”时两按钮等宽，无“清除”时“搜索”占满一行。
- 按钮高度 `44px`，间距 `8px`。
- 不允许输入框、按钮或文字横向溢出。

## 八、用户表格冻结

### 8.1 四列比例

桌面 `> 768px` 固定四列：

| 列 | 宽度 | 最小宽度 | 对齐 |
| --- | ---: | ---: | --- |
| 用户名 | `34%` | `220px` | 左对齐 |
| 角色 | `20%` | `140px` | 左对齐 |
| 注册时间 | `28%` | `190px` | 左对齐 |
| 操作 | `18%` | `148px` | 右对齐 |

- 列间距 `16px`，左右内边距 `16px`。
- 表头高度 `40px`，背景 `#F8F4EC`。
- 普通用户行最小高度与视觉基准高度均为 `64px`。
- 行内存在 unknown-outcome、错误或成功提示时，可在四列下方扩展，不得挤压基础四列。
- 行分隔线 `1px solid #E1D9CC`。
- 操作按钮靠右，不能因按钮默认满宽侵占注册时间列。

### 8.2 角色与当前账号标识

- 角色标签高度 `26px`，水平内边距 `10px`，圆角 `999px`。
- 成员：背景 `#EEEAE4`，文字 `#6F675E`。
- 平台管理员：背景 `#E9EFF4`，文字 `#4F687D`。
- 当前账号标识高度 `26px`，水平内边距 `10px`，背景 `#EEEAE4`，文字 `#6F675E`。
- 当前账号行不显示更多按钮；标识位于操作列并右对齐。

## 九、分页区域冻结

- 分页区位于表格下方 `12px`，最小高度 `40px`。
- 桌面单行：左侧“共 N 位用户”，右侧“上一页 / 第 N / M 页 / 下一页”。
- 左右整体对齐，不允许页码逐字纵向换行。
- 控件间距 `8px`。
- 页码区域最小宽度 `96px`，文本居中且不换行。
- 分页按钮桌面为 `72px × 36px`。
- 首页与末页按钮仍显示文字，只进入冻结的禁用样式。
- 不添加页码输入、页码列表、每页数量选择或无限滚动。

在 `≤ 768px`：

- 用户总数独占一行。
- 分页控件占下一行，三段横向排列。
- 上一页与下一页高度 `44px`，可等宽伸展；页码保持单行居中。
- `360px` 宽度下不得横向滚动或裁切。

## 十、小屏用户卡片

在 `≤ 768px` 隐藏桌面表头，用户行降级为卡片：

- 卡片内边距 `16px`，边框 `1px solid #E1D9CC`，圆角 `12px`。
- 用户名 `15/22px`、最多两行；角色标签与用户名同一视觉首行区域。
- 注册时间 `12/18px`，位于第二信息层。
- 操作按钮最小高度 `44px`。
- 当前账号标识不可被挤出卡片。
- 卡片间距 `12px`，无横向溢出。

## 十一、人工视觉验收标准

### 11.1 桌面端

分别在 `1440×900` 与 `1280×720`、浏览器缩放 `100%` 下验收：

1. 页面标题为 `24/32px`，说明为 `14/22px`，两者层级明确且不拥挤。
2. 刷新按钮文字完整可见，按钮约 `72×40px`，位于标题区右侧且中心点在视口内。
3. 搜索输入框可见宽度不低于 `320px`，与清除/搜索按钮同高、同轴对齐。
4. 搜索、清除、刷新、上一页、下一页按钮的文字均完整可见；启用、禁用、主要和危险状态可清晰区分。
5. 原生 button 与 `taro-button-core` 的同类按钮在字号、颜色、尺寸、边框和圆角上无肉眼差异。
6. 用户名为 `15/22px`，注册时间为 `13/20px`，不得出现截图中的异常放大与多行断裂。
7. 四列表头与每行内容严格对齐；普通行视觉高度为 `64px`。
8. 当前账号标识处于操作列右侧，不显示自操作入口。
9. 用户总数与分页处于同一紧凑层级；“第 N / M 页”单行显示。
10. 分页禁用按钮仍能读出“上一页”或“下一页”，但不能点击。
11. 页面无横向溢出、按钮满宽挤压、文字透明、文字裁切或异常大字号。
12. 本轮修改不得改变任何读取、写入、权限、operationId、写锁或 unknown-outcome 行为。

### 11.2 小屏

分别在 `390×844` 与 `360×800`、浏览器缩放 `100%` 下验收：

1. 标题区、搜索区、用户卡片和分页无横向滚动。
2. 刷新、搜索、清除、分页与操作按钮高度至少 `44px`，文字居中可见。
3. 搜索输入框独占一行；按钮区换到下一行，比例均衡。
4. 用户表格降级为卡片，用户名最多两行，角色、注册时间和操作均完整可见。
5. 用户总数与分页分两行，页码不纵向拆字。
6. 当前账号无更多操作入口；角色和会话交互语义与桌面一致。
7. 确认层、错误态和 unknown-outcome 提示不被遮挡或挤出视口。

## 十二、前端最小修复验收清单

- 只修复用户管理页的视觉样式及其直接视觉回归，不修改业务状态和请求行为。
- 所有规定字号、行高、颜色、尺寸、列宽、间距均有页面范围内的直接样式约束。
- 原生 `button` 与 `taro-button-core` 均被直接覆盖；不存在只覆盖原生 button 的规则缺口。
- Taro 启用宿主 `disabled='false'` 不匹配禁用规则。
- Taro 按钮桌面宽度不再继承全局 `100%`，小屏指定控件仍可满宽。
- 搜索输入框桌面最小宽度、按钮尺寸、四列比例、64px 行高和紧凑分页均有直接回归断言。
- 不通过缩放整个页面、隐藏文字、缩小到不可读字号或改变 DOM 文案规避问题。
- 不修改 API Client、权限门、列表请求、搜索提交、分页逻辑、角色映射、确认流程、operationId、目标锁或 unknown-outcome。
- 不修改 API、Contracts、Application、Repository、Migration、数据库、配置、服务或运行环境。
- 前端实现后必须执行直接视觉测试、既有用户管理 H5 回归、typecheck、build:h5、git diff --check，并进行上述桌面与小屏人工截图验收。

## 十三、流转与授权边界

本设计冻结完成后转产品经理。产品经理只可签发“用户管理页视觉 P1 最小前端修复”授权，并需精确限定前端样式文件、必要的直接视觉测试和验收记录。

设计建议的最小实现范围是用户管理页对应的局部 SCSS 与直接视觉回归；是否需要任何 TSX 调整，必须由产品经理基于前端事实另行裁决，不能由本设计文档自动扩大。

产品授权前不得开始前端编码、真实联调、服务重启、Migration 或运行库操作。
