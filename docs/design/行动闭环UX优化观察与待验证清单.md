# 行动闭环 UX 观察与待验证清单

> 最后更新：2026-07-27
>
> 状态：设计观察资产，不是 PRD、开发排期或编码任务书。当前运行路径、数据源、阶段和禁止事项以 `docs/product/当前运行事实.md` 为准。

## 当前结论

探索主线 V1 已封板；V1.1 已完成阶段性 Git 快照。本文件只保留尚需真实使用或人工复验的体验观察，不重新打开已封板范围，也不授权任何功能开发。

当前 H5 通过 loopback API 使用 MySQL；浏览器不直接访问数据库。任何体验优化都不得以 IndexedDB、SQLite、localStorage、双写、同步、fallback 或前端猜测业务关系作为实现前提。

## 已确认的体验基线

| 主题 | 当前基线 |
|---|---|
| 快速捕获 | 一句话输入；用户明确选择进入“想试试”或“以后再说”。不要求日期、优先级、标签、提醒、Todo 或方法。 |
| 行动闭环 | 事项通过真实状态迁移推进；先记录事实复盘，再决定是否形成、验证或修订方法。 |
| 探索主线 | 真实关联、已删除关联和不可用关联稳定区分；已放弃事项只读，不得调整、移除或归入主线。 |
| 探索刷新 | 已有列表或历史在后台更新时保留旧内容；首次读取才显示加载态，读取失败不伪装为空态。 |
| 探索历史 | 正常探索历史与已放弃记录共用右侧列表区；切换主线后默认回到探索历史。 |
| 主线列表 | 活跃主线左栏每页固定 9 条；刷新保留真实选中项并定位到所在页；分页栏保持底部对齐。 |
| 事项定位 | 状态写入经真实刷新确认成功后，左侧事项池切换到目标状态并选中该事项；失败、Abort、503 或结果未知时不伪造定位。 |
| 改名 | 改名仅在保存按钮或编辑区外首次 pointer 点击时单次提交；外部点击只保存，不补执行原动作；失败或结果未知保留草稿。 |
| 回收站 | 已删除探索主线统一在“数据与设置 → 回收站 → 探索主线”查看和恢复，不在探索模块重复提供入口。 |
| 方法工作台 | 保持左侧列表、右侧详情的双栏工作台；不因视觉调整改变方法、证据、版本或行动语义。 |

## 待人工体验验证

以下项目不是缺陷结论。只有在真实使用中重复出现摩擦，才进入产品评审；不得仅凭本表安排开发。

| 观察项 | 要观察的真实摩擦 | 进入评审的证据 | 当前禁止扩张 |
|---|---|---|---|
| 首次进入探索主线 | 首次加载是否清晰表达读取中，完成后是否能理解列表、详情和历史区域。 | 用户连续多次误判为空态、重复点击或无法理解当前选中主线。 | 不新增引导页、教程流程或全局状态。 |
| 主线分页与详情切换 | 九条分页、选中态、底部分页栏是否便于连续浏览。 | 明确、重复的定位困难或误切换记录。 | 不改每页条数、不引入无限滚动、搜索或新路由。 |
| 改名低摩擦交互 | 外部首次点击被消费后，用户能否理解“已保存，需要再点一次目标入口”。 | 多次发生非预期离开、误以为切换已执行或保存结果不清楚。 | 不使用 blur、timer、卸载或自动重试写入。 |
| 事项状态迁移后的定位 | “想试试 / 以后再说 / 已开始 / 已暂停 / 已放弃”互转后，用户是否能立即找到事项。 | 真实刷新成功后仍反复出现找不到刚迁移事项的体验证据。 | 不依赖本地乐观状态、旧列表或文案推测位置。 |
| 方法双栏阅读密度 | 桌面端列表与详情的留白、滚动和主要行动是否舒适。 | 持续出现阅读受阻、详情难扫读或列表难浏览的反馈。 | 不改变方法、证据、版本历史或开始行动语义。 |
| 轻量完成反馈 | 保存或完成后，用户是否明确知道动作已经落地。 | 重复出现“不确定是否保存/完成”的真实反馈。 | 不引入积分、等级、连续天数、排行、强刺激动画。 |

## 明确不做

```text
日程、截止日期、提醒、计划、拖拽排期
Todo、子任务或第二套任务系统
按月流转、跨月自动归档或任何时间驱动的状态迁移
根据标题、时间、版本、计数或文案猜测业务关系
在执行中直接形成方法，或根据单次行动自动生成方法
把已放弃与回收站合并
浏览器直连 MySQL，或 IndexedDB / SQLite / MySQL 双写、同步、回填、fallback
积分、等级、连续天数、排行榜、经验值或目标压力系统
跑马灯、持续滚动文案、循环背景动画或强刺激完成特效
复制既有 IP 的角色、场景、构图或标志性视觉语言
```

## 设计优先级

```text
快速捕获
> 找到当前事项
> 开始 / 暂停 / 完成行动
> 事实复盘
> 方法处理
> 低频的探索历史、已放弃记录与回收站
```

视觉和交互调整必须保持：高频操作清晰、危险操作有明确确认、加载/失败/unknown-outcome 不伪造成功，并在小屏降级时不改变业务语义。

## 流转规则

- 真实且重复的摩擦先进入 `docs/product/需求池.md`，由产品经理判断是否立项。
- 涉及布局或交互时，再由设计输出实施说明。
- 涉及字段、状态机、关系、跨模块定位契约、API、数据库、Migration、备份或恢复时，产品冻结后必须先经架构评审。
- 未获得独立书面授权前，本文件任何观察项都不得进入编码。
