# 行动闭环 UX 优化观察与待验证清单

> 状态：设计观察资产，不是 PRD、开发排期或实现任务书。
>
> 目的：区分已经验收的体验基线、尚待真实证据验证的假设，以及明确禁止提前扩张的边界。任何待观察项都不得仅凭本文件进入开发。

## 一、行动闭环边界图

```text
快速捕获
一句话记录
        │
        ├── 想试试 ──→ 开始执行 ──→ 进行中 ──→ 完成行动
        │                                             │
        └── 以后再说                                  ↓
                                                  事实复盘
                                                  结果 + 信号
                                                       │
                                      ┌────────────────┴───────────────┐
                                      ↓                                ↓
                                  已复盘                       可选方法处理
                                                         形成 / 验证 / 修订

已放弃：低频决策证据档案，不进入日常主路径
回收站：数据清理与恢复，不等同于放弃
```

## 二、已确认的体验基线

以下已由产品决策和验收行为确认。后续设计与实施必须保持，不得借优化之名回退或扩张。

| 主题 | 当前基线 | 状态 |
|---|---|---|
| 快速捕获 | 一句话输入，用户明确选择“加入想试试”或“加入以后再说”。 | 冻结 |
| 捕获低阻力 | 不要求补充说明、日期、优先级、标签、提醒、Todo 或方法。 | 冻结 |
| 捕获输入 | 顶部与行动模块入口共用浮层；浮层打开后主输入自动聚焦。 | 已验收 |
| 创建后定位 | 系统按新事项真实状态定位；“全部事项”仅由用户主动进入。 | 已验收 |
| 复盘顺序 | 先完成事实复盘，后决定是否处理方法。 | 冻结 |
| 过程信号 | 可选、多选、按需展开补充说明；不替代事实记录。 | 已验收 |
| 方法处理 | 可选，不阻塞事实复盘。 | 冻结 |
| 方法结构 | 方法名、具体步骤、补充说明分层；名称显式填写，步骤不再派生名称。 | 已验收 |
| 已放弃 | 低频决策证据档案；活跃记录存在时从“更多状态”主动查看。 | 已验收 |
| 回收站 | 数据清理与恢复；与日常状态和已放弃严格隔离。 | 冻结 |

## 三、待观察假设

以下是有价值的设计假设，而不是已批准功能。只有出现重复、真实的使用摩擦后，才可进入产品评审。

| 假设 | 需要观察的真实摩擦 | 触发评审的证据 | 当前禁止事项 |
|---|---|---|---|
| 灵感后需补充上下文 | 用户重看“想试试”时常忘记记录原因。 | 高频修改说明、标题明显被写成长段上下文，或明确反馈无法理解当时为何捕获。 | 不在快速捕获中追加说明字段。 |
| 开始执行时需要“第一步” | 想试试长期积压，或用户开始后立即暂停。 | 用户重复表达“不知道从哪里开始”，且现有记录显示相同阻力。 | 不新增下一步字段、Todo、子任务或计划。 |
| 已放弃需记录原因 | 用户回看已放弃事项时，无法理解当时止损依据。 | 已放弃列表被真实复盘使用，且多次出现缺少决策证据的摩擦。 | 不新增放弃原因字段，不从文案或历史推断原因。 |
| 执行中需查看方法 | 用户执行时高频跨模块查看方法步骤。 | 可重复观察到行动页与方法页之间的高频往返，或用户明确提出找不到执行依据。 | 不在行动中自动形成方法，不自动绑定或猜测方法。 |
| 复盘需更具体引导 | 用户反复只写“已完成”等无事实信息。 | 多次复盘缺少有效事实，且用户明确不知道如何记录。 | 不把复盘扩成问卷、打卡或强制长文本。 |
| 外观主题与氛围 | 用户因当前工作台缺少个人归属感而降低打开、捕获或持续使用意愿。 | 用户明确、重复表达希望切换视觉环境，且在不影响核心操作理解的前提下能说清所需氛围。 | 不直接复制吉卜力或其他现有 IP 的角色、场景、构图、笔触或标志性风格；不让主题改变状态语义、按钮层级或危险操作可识别性。 |
| 轻量完成反馈 | 用户完成捕获、行动或复盘后，无法确认闭环已完成，或希望获得克制的完成感。 | 重复出现“我不确定是否已保存/完成”的反馈，或轻反馈原型经使用验证能提高确认感且不诱发无价值操作。 | 不新增积分、等级、连续天数、排行榜、经验值、可兑换奖励或强刺激动画。 |
| 句子库环境提示 | 用户希望在进入行动工作台时获得低干扰的个人提示或灵感，而非持续消费内容。 | 用户主动使用、切换或保留静态提示，并明确反馈其有助于开始行动而非分散注意力。 | 不默认使用跑马灯、自动滚动、持续动画或在捕获、复盘、方法处理、回收站和危险确认中展示；未定义来源与管理语义前，不新增可管理的句子库对象。 |
各项本月的，不附带上月的，然后可以选月份，这样，然后上月的应该可以流转到下月，这样吧。。。



## 四、明确不做

以下能力不能因页面空白、表单完整性或暂时的想象摩擦而提前引入：

```text
日程、截止日期、提醒、计划或拖拽排期
Todo、子任务或第二套任务系统
在执行中直接形成方法
根据一次行动自动生成方法
把已放弃与回收站合并
统计打卡、连续天数、KPI、积分、等级、经验值、排行榜或目标压力系统
以“下一步”名义偷渡计划字段
默认跑马灯、持续滚动文案、循环背景动画或强刺激完成特效
直接复制或近似复刻现有 IP 的主题、角色、场景、构图或标志性视觉风格
根据标题、时间、版本、计数或文案猜测业务关系
```

## 五、设计优先级规则

未来桌面端与小屏端的设计都应保持下列优先级：

```text
快速捕获
> 找到当前事项
> 开始 / 暂停 / 完成行动
> 事实复盘
> 方法处理
> 低频历史、已放弃与回收站
```

语义表现规则：

| 语义 | 表现原则 |
|---|---|
| 高频捕获 | 一级主操作，随时可达，输入最少。 |
| 当前行动 | 页面唯一主操作，如开始、完成行动或完成复盘。 |
| 可选补充 | 文本入口、折叠区或低强调容器。 |
| 方法处理 | 第二阶段，不压过事实复盘。 |
| 已放弃 | 中性低强调，不表达为失败。 |
| 回收站 | 弱警示，仅在数据治理语境出现。 |
| 危险操作 | 明确确认层，不与日常状态迁移并列。 |

## 六、治理与流转

- 本文档归属设计观察层，位于 `docs/design/`。
- 已确认、可排期的产品结论应进入 `docs/product/需求池.md`，再按需要经过设计、架构与研发流转。
- 若待观察项涉及字段、状态机、关系、Schema、Migration、备份或恢复，产品冻结后必须先转架构评审。
- 没有真实、重复摩擦证据时，不得以本文档作为开发依据。
