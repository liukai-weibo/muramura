# 平台角色与最小权限管理 V1—切片 4 H5 管理入口设计冻结

日期：2026-07-30
状态：产品与交互设计冻结完成；待前端架构评审；未授权编码

## 一、设计结论

切片 4 采用管理员专属的独立“用户管理”入口，将切片 3 已验收的用户分页、用户名搜索、平台角色调整和撤销全部会话能力映射为克制的 H5 管理页面。

本设计不新增角色、权限、字段、路由、数据来源或写入语义，不提供用户详情、删除、禁用、重置密码、业务数据查看、审计查看、批量操作或自定义权限。

当前 `knowledge_base` 与 `knowledge_base_uat` 均为 Schema 5。切片 4 完成前端架构冻结并取得产品编码授权前，不得编码、真实联调、重启或替换 API、部署真实 006、操作运行库或改变运行环境。

## 二、设计依据与冻结边界

设计基于以下已验收事实：

- 管理员用户列表固定每页 20，支持用户名字面量子串搜索，排序固定为 `createdAt DESC, userId ASC`。
- 列表只返回 `id`、`username`、`roles`、`createdAt`；`id` 只用于操作定位。
- 角色只接受 `['member']` 或 `['member', 'platform_admin']`。
- 管理员可以调整其他用户的 `platform_admin` 角色，不能调整自己的角色。
- 管理员可以撤销其他用户全部有效会话，不能通过管理接口撤销自己的会话。
- 每次明确写操作由前端生成新的规范 UUID `operationId`。
- 角色写入明确成功后返回服务端真实重读的 `PlatformUserSummary`；会话撤销明确成功后返回 `revokedSessionCount`。
- 写入结果未知时不得推断成功或失败、不得自动重试、不得复用 operationId。
- 管理页面不得展示密码、哈希、Cookie、会话详情、审计内容、邮箱、用户业务数据、Backup 内容或业务数量。
- `platform_admin` 不获得跨用户业务数据权限。

## 三、入口位置与信息架构

### 3.1 桌面端入口

在左侧导航底部的系统工具区增加独立入口“用户管理”，与“设置与数据”同组但不嵌入其页面内部。

原因：用户管理属于平台级安全操作；设置与数据属于当前用户的个人数据管理。两者混入同一页面会弱化权限边界。

入口规则：

- 仅当当前认证事实中的 `roles` 包含 `platform_admin` 时显示。
- `member` 不显示入口。
- 不根据本地缓存、用户名、页面历史或旧列表推断管理员身份。
- member 通过历史地址或直接路径进入时，不得先渲染旧列表、骨架或管理操作，再等待 403。
- 任意管理请求返回 403 后，立即卸载管理页面、确认层、搜索条件、列表与待处理写状态，隐藏入口并返回安全默认页面。
- 401 时清除管理页面内存状态并进入既有登录门。

### 3.2 页面信息层级

页面只包含以下层级：

1. 页面标题“用户管理”。
2. 辅助说明“管理平台管理员角色与用户登录会话”。
3. 右上角显式“刷新”按钮。
4. 用户名搜索区。
5. 用户列表：用户名、平台角色、注册时间、操作。
6. 底部分页：用户总数、上一页、当前页/总页数、下一页。

不增加角色筛选、用户详情页、批量选择、审计入口或业务数据入口。

## 五、搜索与分页

### 5.1 搜索

- 搜索对象仅为用户名。
- 输入最长 80 个 JavaScript 字符单元；达到上限后阻止继续输入。
- 按 Enter 或点击“搜索”才发起读取，不做逐字搜索或自动防抖读取。
- 输入 trim 后为空等同于未筛选。
- 新搜索固定回到第 1 页。
- 搜索输入有内容时显示清除入口；清除后显式读取第 1 页完整列表。
- 请求失败后保留用户输入，避免重复输入。
- 不提供邮箱、角色、用户 ID 或业务内容搜索。

### 5.2 分页

- 每页固定 20，不提供 pageSize 选择器。
- 控件为“上一页 / 第 N 页（共 M 页）/ 下一页”。
- 首页禁用上一页，末页禁用下一页。
- 翻页时保留当前搜索条件。
- 不提供跳页输入或无限滚动。
- 超过末页且服务端返回空 `items` 时，诚实显示当前页无用户并允许返回上一页；不得把空页伪装为 404。

## 六、角色标识与操作菜单

### 6.1 角色标识

- `['member']` 显示中性标签“成员”。
- `['member', 'platform_admin']` 显示强调标签“平台管理员”，不重复叠加“成员”。
- 未知角色、缺少 member 或角色事实不可读属于整次读取失败，不在前端降级为成员。
- 当前登录用户额外显示“当前账号”。该行不显示操作菜单。

### 6.2 操作菜单

其他用户的单行操作菜单固定为：

- 目标为成员：`授予管理员`、分隔线、`撤销全部会话`。
- 目标为平台管理员：`撤销管理员`、分隔线、`撤销全部会话`。

不得出现编辑用户名、删除、禁用、重置密码、查看业务数据、查看会话、查看审计、自定义角色或批量操作。

## 七、确认交互与危险等级

### 7.1 授予管理员

危险等级：高权限变更，非破坏性警示。

- 标题：`授予“{username}”平台管理员权限？`
- 说明：`授予后，该用户可以进入用户管理、调整其他用户的平台管理员角色，并撤销他人的登录会话。不会获得查看其他用户业务数据的权限。`
- 按钮：`取消`、`确认授予`。
- 确认按钮使用深色主按钮，不使用危险红色。

### 7.2 撤销管理员

危险等级：高风险权限撤销。

- 标题：`撤销“{username}”的平台管理员权限？`
- 说明：`该用户仍保留成员身份及自己的业务数据，但之后不能继续进入用户管理。此操作不会撤销其登录会话。`
- 按钮：`取消`、`撤销管理员`。
- 确认按钮使用危险红色。
- 不提供“同时撤销会话”复选框，不合并两次写操作。

### 7.3 撤销全部会话

危险等级：高风险会话操作。

- 标题：`撤销“{username}”的全部登录会话？`
- 说明：`该用户当前所有有效登录会话都会失效，需要重新登录。角色、账号和业务数据不会改变。`
- 按钮：`取消`、`撤销全部会话`。
- 确认按钮使用危险红色。
- 明确成功且 `revokedSessionCount > 0` 时提示：`已撤销 N 个登录会话。`
- 明确成功且 `revokedSessionCount = 0` 时提示：`当前没有需要撤销的有效会话。`
- 不把会话数量、设备、时间或状态作为列表常驻信息。

### 7.4 operationId 生成时机

- 打开、关闭确认层时不生成 operationId。
- 只有最终点击确认按钮时，才为该次明确操作生成一个新的规范 UUID。
- 一次点击只生成一个 operationId。
- 明确失败后再次确认属于新的用户操作，必须生成新的 operationId。
- unknown-outcome 后不得复用原 operationId。

## 八、加载、空态与错误状态

### 8.1 初次加载

- 页面主体显示 6 行骨架。
- 搜索、刷新、分页和操作暂时不可用。
- 只有管理员权限事实有效且列表读取成功后，才展示真实列表。

### 8.2 搜索、翻页与刷新中

- 已有列表保持可见，并显示“正在读取最新用户信息”。
- 禁止重复触发同一读取。
- 旧请求响应不得覆盖较新的搜索、页码或刷新结果。
- 不自动定时刷新。

### 8.3 空态

- 未搜索且 `total = 0`：`暂无用户。`
- 不提供“创建用户”入口。

### 8.4 搜索无结果

- 文案：`没有找到匹配“{query}”的用户。`
- 提供“清除搜索”。
- 不把搜索无结果呈现为平台无用户。

### 8.5 401 UNAUTHORIZED

- 立即清除管理页面内存状态和确认层。
- 进入既有登录门。
- 不保留或重新展示此前用户列表。

### 8.6 403 FORBIDDEN

- 隐藏“用户管理”入口。
- 卸载用户列表、搜索条件、确认层和待处理状态。
- 提示：`你的管理员权限已变化，无法继续访问用户管理。`
- 展示服务端既有错误中的 requestId。
- 返回安全默认页面，不自动重试管理请求。

### 8.7 404 NOT_FOUND

- 用于操作目标用户不存在。
- 结束本次提交中状态，但保留写入前旧列表。
- 展示服务端既有错误文案及 requestId。
- 提供“刷新列表”，不自动刷新或自动移除该行。

### 8.8 409 CONFLICT

- 展示服务端既有冲突文案及 requestId。
- 不把 operationId 冲突解释为前一次已成功。
- 保留旧列表并提供显式刷新。
- 目标角色异常时，不尝试在前端修复或改写角色。

### 8.9 503

- 初次读取失败：显示整页错误态、既有错误文案、requestId 和“重新加载”。
- 已有列表刷新失败：保留旧列表并明确标记“以下为刷新前内容”。
- 写请求返回 503 时按结果未知处理，不推断成功或失败，不自动重试。

## 九、unknown-outcome 与显式刷新

### 9.1 通用规则

- Abort、断线、超时、响应丢失或写入 503 后，保留写入前列表与角色标签。
- 显示局部警示：`操作结果尚未确认。`
- 不显示成功或明确失败提示。
- 不自动重试、不自动生成新 operationId、不按请求体改写界面。
- 在结果未知期间锁定该目标用户的全部写操作，防止叠加不明确写入。

### 9.2 角色操作结果未知

- 提供“刷新用户列表”。
- 只有用户显式触发 GET 且成功返回最新角色事实后，才能解除目标用户写锁。
- 刷新结果必须以服务端返回的 `roles` 更新角色标签。
- 刷新失败时保留旧列表、未知提示和写锁。

### 9.3 会话撤销结果未知

- 提示：`无法确认会话撤销是否完成。`
- 当前用户列表 API 不包含会话状态，刷新列表不能证明会话撤销是否已经提交。
- 不新增会话状态标签、会话数量或会话查询入口。
- 管理员如决定再次撤销，必须再次明确触发操作、重新阅读确认层，并生成新的 operationId。

角色 unknown-outcome 可通过列表显式刷新确认；会话撤销 unknown-outcome 不能由现有列表 API 确认。前端不得抹平二者差异。

## 十、操作中与防重复提交

- 最终确认后，确认按钮立即进入加载态。
- 提交中禁用取消、关闭、遮罩关闭和重复确认。
- 同一目标用户在写请求结束前锁定全部操作入口。
- 明确角色成功后，只使用响应中的 `PlatformUserSummary` 更新目标行。
- 明确会话撤销成功后，只使用响应中的 `revokedSessionCount` 展示结果；列表结构不变。
- 明确成功后不自动重新读取整页；工具栏保留显式“刷新”。
- 页面离开、组件卸载或浏览器关闭不得自动提交、补偿或重试。
- 管理列表不得写入 localStorage 或作为跨登录缓存保留。

## 十一、窄屏降级

在 `≤ 768px` 时：

- “用户管理”进入既有导航抽屉，仍只对管理员显示。
- 页面标题、说明与刷新按钮分为两行。
- 搜索输入和搜索按钮允许上下排列。
- 桌面表格降级为用户卡片，不使用横向滚动表格。
- 卡片只显示用户名、角色、注册时间与操作。
- 当前账号卡片显示“当前账号不可操作”，不显示更多菜单。
- 操作菜单使用底部操作面板；确认层使用底部确认面板。
- 分页保持上一页、页码与下一页，不改为无限滚动。
- unknown-outcome 与错误提示放在对应卡片上方，不依赖 hover 或 tooltip。
- `≤ 360px` 时用户名最多两行，角色标签不可被挤出屏幕。

窄屏卡片结构：

```text
┌────────────────────────────────┐
│ username          平台管理员   │
│ 注册于 2026-07-30               │
│                          [更多] │
└────────────────────────────────┘
```

## 十三、前端实施验收清单

### 13.1 权限与入口

- member 看不到“用户管理”，也不能通过直接入口观察管理列表或旧状态。
- platform_admin 可看到并进入独立“用户管理”入口。
- 401 进入登录门；403 卸载管理页面并隐藏入口。
- 当前账号无角色调整和会话撤销入口。

### 13.2 数据展示

- 列表固定每页 20，展示用户名、角色与注册时间。
- 不展示密码、哈希、Cookie、会话详情、审计、邮箱、业务数据、业务数量或内部 userId。
- 两种冻结角色数组稳定映射为“成员”和“平台管理员”。
- 未知或不完整角色事实不在前端降级展示。

### 13.3 搜索与分页

- 搜索仅按用户名，最长 80；Enter 和搜索按钮均可提交。
- 空 query 等同未筛选；新搜索回到第 1 页。
- 分页固定 20，不出现 pageSize、跳页或无限滚动。
- 搜索、翻页与刷新具备旧请求保护，旧响应不能覆盖新上下文。

### 13.4 操作与确认

- 其他用户菜单只包含与当前角色对应的角色操作和“撤销全部会话”。
- 三类确认层的目标用户名、影响说明和危险等级符合本设计。
- operationId 只在最终确认时生成；每次确认均为新 UUID。
- 双击、重复点击或遮罩操作不能产生第二次提交。
- 明确角色成功只采用响应用户摘要；明确会话成功只采用响应计数。

### 13.5 错误与 unknown-outcome

- 404、409、503 展示服务端既有文案和 requestId，不自行映射为成功。
- 角色 unknown-outcome 保留旧角色、锁定目标写操作、不自动重试，并通过显式刷新确认。
- 会话 unknown-outcome 不伪装为可由列表确认，不复用 operationId。
- 初始加载、保留旧列表刷新、空平台、搜索无结果和读取失败状态可明确区分。

### 13.6 响应式与非目标

- 桌面表格和窄屏卡片均能访问全部既有操作，无横向溢出。
- 小屏确认层和操作菜单可通过键盘、触控与返回操作关闭；提交中除外。
- 不出现删除、禁用、重置密码、用户详情、业务数据、审计、自定义权限或批量操作。
- 不新增接口、字段、路由、角色、Schema、Migration、缓存或数据源。
- 不进行真实页面联调、服务重启、Schema 6 部署或运行库操作。
