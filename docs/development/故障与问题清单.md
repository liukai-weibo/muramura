用于记录已确认的工程故障、根因、修复范围和预防措施。每日贡献记录只记录当日实际改动，不替代本文档。

## 2026-08-13：桌面端圈圈 AI 无法聊天

- 现象：桌面端发送消息后显示“暂时无法获取回复”，错误为 `AI 流请求未能连接本地 API：Failed to fetch`；普通页面和普通 API 请求正常。
- 影响范围：Tauri 桌面端圈圈 AI 的流式回复；H5 普通接口不受影响。
- 根因：AI SSE 路由直接返回原生 `Response`，没有继承请求中间件写入的 `access-control-allow-origin`、`access-control-allow-credentials` 等 CORS 响应头。桌面 WebView 因此阻止读取流响应，并将其统一表现为 `Failed to fetch`。
- 修复：在 `apps/api/src/hono/routes/ai.ts` 的 AI 流响应中回写桌面请求来源对应的 CORS 响应头；同时保留 AI 路由认证链和客户端详细错误透传。
- 预防：以后新增原生 `Response`、SSE、文件下载或流式接口时，必须验证桌面来源的预检和实际响应均包含 CORS 头；不要只验证普通 JSON 请求。
- 验证：本地 API `127.0.0.1:32146` 健康状态为 `ready / Schema 18`，`typecheck` 与 `git diff --check` 通过，桌面端恢复聊天。
