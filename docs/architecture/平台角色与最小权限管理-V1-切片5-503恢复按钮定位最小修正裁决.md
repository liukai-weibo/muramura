## 一、事实与根因

- 多目标 `role-unknown` 生产 P1 已由真实 A/B 交错链关闭。
- 503 写入已正确进入带 `requestId` 的目标级 `role-unknown`。
- 生产 DOM 中，unknown 正文与恢复入口位于同一目标行的不同区域：
  - `.platform-target-notice`：冻结提示正文及 `requestId`；
  - `.platform-user-actions`：`lock === 'role-unknown'` 时渲染真实“刷新用户列表”控件。
- 当前 E2E 使用 `notice503.getByText('刷新用户列表').click()`。由于未使用 exact 且范围被限定在 notice，它匹配正文“请显式刷新用户列表确认真实角色。”中的文本节点，不是恢复控件。
- 点击正文不会发出 GET，随后等待管理按钮超时是测试定位错误，不是 503、role-unknown、读协调或恢复语义失败。

`target503Row.locator('.platform-user-actions').getByText('刷新用户列表', { exact: true }).click()`
