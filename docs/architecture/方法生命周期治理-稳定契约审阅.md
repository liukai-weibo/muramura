# 方法生命周期治理 — 稳定契约审阅记录

> 审阅日期：2026-07-21  
> 依据：QA「方法生命周期治理第二阶段」数据完整性与备份恢复验收报告。  
> 结论：**数据层稳定契约审阅通过，允许转交前端实施。**

## 【技术结论：可行】

QA 已验证：真实 Dexie v6 → v7 迁移、软删除 / 恢复、到期永久清理及事务回滚、墓碑最后引用回收、v1 / v2 备份恢复与严格校验均通过。当前 Contracts、Application / Repository 契约已足以让前端诚实实现方法生命周期体验，不需要前端接触 IndexedDB、补写数据关系或猜测历史。

本结论只授权前端消费稳定契约，实现已冻结的详情页更多操作、统一回收站和历史状态展示；不授权前端变更数据模型、备份、迁移或业务写入语义。

## 【已审阅的稳定契约】

### 方法生命周期命令

```ts
MethodLifecycleApplicationService.moveToTrash(methodId)
MethodLifecycleApplicationService.restore(methodId)
TrashApplicationService.listTrashEntries(filter)
```

- 移入回收站只写 `Method.deletedAt`；不改写版本、证据、应用、事项或复盘；
- 恢复只移除 `deletedAt`；不创建新版本、不重连关系；
- 统一回收站在读取前清理过期事项与方法，返回按删除时间倒序的 `TrashEntry`；
- 30 天剩余时间由前端按 `deletedAt` 和统一规则展示，不持久化，也不自行触发永久清理。

### 历史方法应用上下文

前端必须调用：

```ts
MethodApplicationService.getContextResultForItem(itemId)
```

不得使用遗留的：

```ts
getContextForItem(itemId)
```

后者只对 `available` 返回值，不能区分回收站、墓碑、异常断裂与无关联，不满足可信展示要求。

冻结状态：

| status | 前端可展示的事实 | 行动 / 验证 / 修订资格 |
|---|---|---|
| `no-association` | 本次事项未关联方法 | 正常流程允许用户自行选择 |
| `available` | 关联方法与实际冻结版本可读 | 正常流程允许 |
| `method-in-trash` | `关联方法：{title}（已移入回收站）` | 禁止 |
| `method-purged` | `关联方法：{title}（已永久清理）` | 禁止 |
| `unavailable` | 历史关联不可用，按 `reason` 说明 | 禁止 |

所有非 `available` 的状态都不允许将旧关联自动选为验证 / 修订方法。`no-association` 只是没有来源关联，并不妨碍用户主动选择正常可用方法。

### 方法证据与版本历史

`MethodEvidence.relation` 和 `MethodEvidence.methodVersion` 是形成、验证、修订的唯一历史判定依据。

前端可以展示：

```text
formation / validation / revision / unknown
methodVersion（若契约提供）
```

禁止根据 `sourceReviewId`、时间、标题、当前版本号或文案反推关系。对 `unknown` 必须诚实降级，不得改写为验证、形成或修订。

## 【当前页面的实施缺口】

现有 `apps/client/src/pages/index/index.tsx` 已调用 `getContextResultForItem()`，但当前仅明确处理：

```text
available
unavailable
```

`method-in-trash` 和 `method-purged` 尚未形成用户可见的专门展示；由于它们不是 `available`，现有页面也不会提供正确的历史说明。这是前端 Sprint 的首要必做项，不能以“无关联”或通用失败消息代替。

此外，当前页面已有的 `clearMethodDraft()` 仅可在 `unavailable` 时调用。前端实施时必须保证：

- 异步返回 `method-in-trash` / `method-purged` 时，禁止默认选择来源方法；
- 不得覆盖用户已输入的事实复盘草稿；
- 如存在以旧来源方法为默认的未提交方法处理草稿，只能清理该方法处理选择，且应按现有草稿保护交互处理，不得无提示清空事实复盘内容；
- 切换事项、旧请求返回、恢复方法后的刷新不得覆盖用户明确选择。

## 【前端最低验收】

1. 方法详情仅在活跃方法上提供 `更多操作 → 移入回收站 → 二次确认`；
2. 移入后不强制跳转回收站，当前页面稳定回落到正常方法列表状态；
3. `数据与设置 → 回收站 → 全部 / 事项 / 方法` 使用 `listTrashEntries()`，按类型恢复；
4. 回收站条目展示名称、删除时间、剩余可恢复时间和恢复操作；
5. `method-in-trash` 与 `method-purged` 使用冻结文案，且无行动、验证、修订、编辑或正文恢复入口；
6. `unavailable` 保持“历史关联不可用”，不伪装为“未关联”；
7. 正常搜索、行动发起、验证 / 修订候选不展示回收站方法或墓碑；
8. 对异步返回、切换事项、关闭确认层、恢复后刷新执行人工回归；
9. 不改变 QA 已通过的数据层测试与备份恢复结果。
