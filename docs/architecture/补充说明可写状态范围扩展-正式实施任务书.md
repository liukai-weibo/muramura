> 状态：**产品已冻结；授权 Application / Repository 工程师实施最小守卫调整与自动化测试。前端等待数据层验证通过后实施。**
> 前置条件：`Item Repository` 并发读改写一致性 P0 已关闭。
> 关联评审：`补充说明可写状态范围扩展-技术评审.md`。

## 【技术结论：可行】

产品确认：全部未删除事项均可添加、编辑或主动清空既有 `Item.content`；回收站事项只读。

本任务是对已存在的 `updateContent()` 写入守卫做最小放宽。数据模型、更新命令、事务一致性、备份语义和状态机均无需变化。

最终规则：

```text
Item 不存在或 deletedAt 存在
→ 拒绝：事项不存在

其余所有 ItemStatus
→ 允许 trim(content)
→ 仅更新 content 与 updatedAt
→ 不写 ItemStatusEvent
```

适用的未删除状态：

```text
idea_to_try
idea_later
doing
paused
waiting_review
reviewed
archived_no_review
abandoned
```

## 【一、最小实现范围】

### Contracts

不修改。

继续使用既有专用契约：

```ts
interface UpdateItemContentInput {
  content: string
}

ItemRepository.updateContent(id, input): Promise<Item>
ItemApplicationService.updateItemContent(id, content): Promise<Item>
```

禁止新增通用 `updateItem()`。

### Application

不修改。

继续由 `ItemApplicationService.updateItemContent()` 转发已冻结的专用 Repository 命令。

### Repository

仅修改 `IndexedDbItemRepository.updateContent()` 事务内守卫：

```text
保留：
!item || item.deletedAt
→ throw new Error('事项不存在')

删除：
item.status !== 'idea_to_try'
→ throw new Error('仅可为想试试事项补充说明')
```

其余事务语义必须原样保留：

```text
transaction(rw, items)
→ 事务内 items.get(id)
→ 校验存在且未删除
→ input.content.trim()
→ items.put({ ...current, content, updatedAt })
→ 返回更新 Item
```

不得把读取移回事务外；不得重建 P0 已关闭的旧快照覆盖风险。

## 【二、业务与数据边界】

补充说明持续只表达：

```text
背景
范围
上下文
为什么值得做
```

本次修改绝不允许 `content` 承载或改写：

```text
复盘事实
执行进度
暂停、放弃或归档原因
当前第一步
方法步骤
状态迁移事实
```

所以所有状态更新内容时，不得：

```text
修改 Item.status
修改 title / createdAt
创建、删除或修改 ItemStatusEvent
修改 Review
修改 Method、MethodVersion、MethodEvidence、MethodApplication
修改 ItemLink
```

在 `waiting_review`、`reviewed`、`archived_no_review`、`abandoned` 中更新内容，只是更新背景文本；复盘、方法证据、归档 / 放弃决策与流转历史继续是独立且优先的事实。

## 【三、失败与并发语义】

| 情况 | 结果 |
|---|---|
| Item 不存在 | 抛出 `事项不存在` |
| Item 在回收站 | 抛出 `事项不存在` |
| 任意未删除状态 | 允许保存（包括空字符串） |
| IndexedDB 写入失败 | 透出失败，数据不应部分写入 |

- 空内容合法，表示主动清空；
- 写入仍在事务内重新读取当前对象，因此不能回滚并发已提交的状态或删除标记；
- 若保存事务读取时事项已删除，必须拒绝，不能意外恢复；
- 两个并发内容保存仍遵循当前单用户显式保存模型：最后提交内容为准；本任务不引入文本合并或乐观锁。

## 【四、搜索、列表与备份】

- 搜索继续直接读取 `Item.content`，更新后自然可搜索，清空后旧关键词不再命中；
- `updatedAt` 更新会按既有列表规则影响排序；该现有语义已由产品接受；
- 完整 JSON 备份与恢复直接复用现有 `Item.content` / `updatedAt`，不升级格式或版本。

## 【五、自动化测试】

最低新增 / 调整范围：

1. 上述八种未删除状态均能保存非空内容，并返回更新后的 `content / updatedAt`；
2. 上述八种未删除状态均能显式保存空字符串；
3. 回收站事项保存拒绝 `事项不存在`，且不意外恢复；
4. 不存在事项保存拒绝 `事项不存在`；
5. 每个成功写入仅改变 `content / updatedAt`；
6. 每个成功与失败路径均不新增或改写 `ItemStatusEvent`；
7. `waiting_review`、`reviewed`、`archived_no_review`、`abandoned` 保存内容后：
   - 状态不变；
   - Review、方法证据、方法应用与状态历史查询结果不变；
8. 更新后搜索命中新内容；清空后旧关键词不再命中；
9. 导出 → 解析 → 新库恢复后内容与 `updatedAt` 保持；
10. 保留并运行 Item P0 并发一致性测试：
    - 内容与状态交错；
    - 内容与删除 / 恢复交错；
    - purge / restore 交错；
    - 状态事件与复盘事务回滚。
11. 全量回归：状态机、回收站、备份恢复、复盘、方法应用、方法生命周期与墓碑。
