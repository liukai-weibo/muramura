# 平台角色与最小权限管理 V1—切片 5 P1 真实渲染诊断与第二次最小修复架构裁决

## 技术结论

可行，但上一轮“增加 inline-flex、局部层级和 pointer-events”结论不足，现由真实 Chromium 几何证据替代。P1 不是父容器主动拦截事件，而是以下三项叠加：

1. Taro H5 基础样式对 `taro-button-core` 设置 `width: 100%`；上一轮 `flex: 0 0 auto` 没有覆盖该宽度，反而使按钮按 100% 宽度不可收缩。
2. Taro DOM 对启用按钮也输出 `disabled="false"`；当前 `.platform-administration button[disabled]` 按属性是否存在匹配，因而把启用按钮计算为 `pointer-events: none`。
3. 桌面端 `.app-main` 使用 `overflow: clip`，仅设置模块被允许滚动；管理页内容高于视口时没有可用滚动容器，`scrollIntoView` 不能改变 `scrollTop`。

不得继续增加 z-index。诊断证明局部 z-index 已为 1 时问题仍存在，真正需要修正的是宿主宽度、disabled 精确匹配和管理页滚动资格。

## 诊断方式与可信边界

使用当前 `apps/client/dist` 构建产物、Playwright 1.58.2 和默认 1280×720 隔离 Chromium：

- 随机 loopback 静态文件服务仅提供现有 dist 文件，完成后关闭。
- 浏览器内拦截 `/api/v1/**`，只返回内存中的最小认证与用户列表读模型。
- 未连接、启动或重启现有 API；未连接 MySQL；未创建 database、账号、Cookie 持久化、证据文件或项目文件。
- 这是实际构建 CSS、Taro DOM 与 Chromium hit testing 的只读几何诊断，不替代随机 Schema 6 完整 E2E。

## 修复前真实证据

两个宿主元素均为 `taro-button-core`，属性均明确为 `disabled="false"`：

| 事实 | 搜索 | 刷新 |
|---|---:|---:|
| bounding box | x=456, y=1334.55, 954×40 | x=329, y=707.77, 954×40 |
| 中心点 | (933, 1354.55)，视口外 | (806, 727.77)，视口外 |
| computed width | 954px | 954px |
| computed pointer-events | none | none |
| 父容器 | 954×40 | 954×1181.56 |

布局因果：刷新按钮占满父容器 954px 且不可收缩，把标题列压至 40px，标题逐字换行使 header 高达 1181.56px；搜索按钮同样占满 954px，使父容器横向内容宽于自身并将搜索区推至 y=1334.55。

滚动事实：`.app-main` 为 1060×720，`scrollHeight=1923`，computed overflow 为 `clip/clip`，`scrollTop=0`；调用 `scrollIntoView` 后仍为 0。搜索/刷新中心均在视口外，因此没有可采集的视口内 hit stack。

匹配规则事实：

- Taro 基础规则：`taro-button-core { width: 100%; display: block; ... }`。
- 当前局部规则虽改为 `display:inline-flex; flex:0 0 auto; pointer-events:auto`，但没有覆盖 `width:100%`。
- 当前 disabled 规则包含 `.platform-administration taro-button-core[disabled]`，会匹配 `disabled="false"`，最终覆盖为 `pointer-events:none`。

## 第二次最小修复

仅在 `apps/client/src/pages/index/index.scss` 完成三项修正：

1. header/search 直接 `taro-button-core` 的基础规则增加 `width:auto`；保留 `inline-flex`、内容居中、`box-sizing:border-box` 和 `flex:0 0 auto`。删除上一轮无证据价值的 `position:relative`、`z-index:1`，不得继续叠加层级。
2. 将管理页 disabled 样式从属性存在选择器 `[disabled]` 收敛为精确 `[disabled='true']`；启用态 `disabled="false"` 不得匹配禁用样式。已有局部 exact-true 规则可合并去重，不得以 `!important` 覆盖错误选择器。
3. 在既有桌面 `@media (min-width:981px)` 的 `.app-main` 滚动规则中，只为“当前存在且可见的 `.platform-administration:not(.platform-administration-hidden)`”增加 `overflow-y:auto`；其他模块继续保持原有 overflow 语义。不得给页面、body 或全部 `.app-main` 无条件开放滚动。

保留小屏 `@media (max-width:768px)` 中管理按钮 `width:100%` 的既有降级；本修复的 `width:auto` 是桌面基础布局，不能删除小屏覆盖。
