# 事项池方法来源行 — 稳定契约审阅

> 状态：**数据层契约稳定，允许前端实施事项池来源行与普通事项详情的信息层级调整。**
> 前置文档：`docs/architecture/事项池方法来源行-轻量技术评审.md`。
> 审阅日期：2026-07-22。

## 【技术结论：可行】

`MethodApplicationService.listSourceDisplaysForItems(itemIds)` 已实现为事项池专用的批量、只读、结构化展示读模型。它以 `MethodApplication.itemId`、冻结的 `methodId + methodVersion`、Method、MethodVersion 与 MethodTombstone 为唯一事实来源，能够可靠区分无关联、正常关联、回收站、永久清理及历史关联断裂。

该契约已通过 QA 定向验收和全量回归，可作为前端事项池来源行的稳定数据来源。前端不得再逐项调用单事项上下文、拼接底层表或猜测关系。

## 【稳定前端 Contract】

```ts
itemApplication.listSourceDisplaysForItems(
  itemIds: string[],
): Promise<ItemMethodSourceDisplay[]>
```

```ts
type ItemMethodSourceDisplay =
  | { status: 'no-association'; itemId: string }
  | { status: 'available'; itemId: string; title: string }
  | { status: 'method-in-trash'; itemId: string; title: string }
  | { status: 'method-purged'; itemId: string; title: string }
  | { status: 'unavailable'; itemId: string; title?: string }
```

### 输入与返回不变量

```text
输入 itemIds
→ 空字符串过滤
→ 重复 ID 去重
→ 空输入返回 []
→ 每个去重后的 ID 返回一个带 itemId 的结果
→ 不存在且无关联的 ID 返回 no-association
```

前端必须以 `itemId` 建立映射；不得依赖返回数组位置与当前分页、筛选或异步刷新后的条目位置一致。

## 【状态与展示映射】

| Contract 状态 | 可信标题来源 | 前端事项池文案 |
|---|---|---|
| `no-association` | 无 | 不显示来源行 |
| `available` | `Method.title` | `方法：{title}` |
| `method-in-trash` | 回收站 `Method.title` | `方法：{title}（已移入回收站）` |
| `method-purged` | `MethodTombstone.title` | `方法：{title}（已永久清理）` |
| `unavailable` 且有 `title` | 现存 `Method.title`，否则冻结 `MethodVersion.title` | `方法：{title}（已不可用）` |
| `unavailable` 且无 `title` | 无可信名称 | `关联方法已不可用` |

`unavailable` 绝不等同于 `no-association`。前端不得因缺少标题而隐藏已断裂的历史关联。

## 【已确认的数据可信边界】

Repository 在单个 Dexie 只读 transaction 中读取：

```text
methodApplications
methods
methodVersions
methodTombstones
```

查询不修改 Item、MethodApplication、Method、MethodVersion 或 MethodTombstone。标题严格来自真实结构化记录：

```text
available / method-in-trash
→ Method.title

method-purged
→ MethodTombstone.title

unavailable
→ 尚存 Method.title；否则尚存冻结 MethodVersion.title；否则无标题
```

禁止：

```text
根据事项标题、方法 ID、时间、当前版本号、Review 文案、证据计数或字符串相似度推断来源
把断裂关联自动连接到其他方法
把该展示模型用于验证、修订、发起行动或任何写入
```

## 【前端实施约束】

### 允许实现

1. 在事项池条目中，标题下、时间上展示低强调来源行；
2. 普通事项详情移除“本次行动使用的方法”大卡片；
3. 保留 `waiting_review`、`reviewed` 中真实的复盘、验证、修订和证据上下文；
4. 回收站事项同样可消费读模型，但仅只读展示；
5. 视觉截断仅作用于渲染文本：

```text
最多 10 个 Unicode code point
超出追加 …
单行、不换行、不横向滚动
```

建议使用 `Array.from(title)` 计数，避免截断 emoji 等代理对。原始 `title` 不得被改写、回写或缓存为截断值。

### 禁止实现

```text
逐项调用 getContextResultForItem()
直接查询 IndexedDB / Dexie 表
来源行点击跳转
来源行筛选、标签化、编辑或方法管理入口
前端猜测、补全或重连关联
在普通事项详情以大卡片重新展示方法来源
```

## 【异步与页面状态保护】

前端调用批量命令时：

```text
当前可见事项 ID 集合变化
→ 发起一轮批量查询
→ 只接受最新请求结果
→ 按 itemId 更新来源展示映射
```

切换状态筛选、分页、搜索结果、模块、回收站或刷新列表时，旧请求返回不得覆盖新集合。失败时不伪造任何来源；可暂时隐藏来源行并以页面已有非阻断错误反馈处理，但不得把读取失败显示为“无关联”。
