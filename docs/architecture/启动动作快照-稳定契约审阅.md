# 启动动作快照 — 稳定契约审阅

> 结论状态：**数据层稳定；允许前端按本文件接入。当前页面仍是旧临时提醒实现，必须替换，不得将其视为已完成。**
> 前置依据：`docs/architecture/启动动作快照-正式实施任务书.md`、QA“启动动作快照”数据层定向验收报告。
> 审阅日期：2026-07-21。

## 【技术结论：可行】

`startAction` 已以 Item 可选字段、专用 `startExecution()` 命令和同事务状态事件写入实现。QA 已验证原子性、失败回滚、备份恢复、旧数据兼容及既有 Item 并发 P0 回归。

数据层契约可作为前端唯一可信写入边界。前端可以开始实现启动确认层的持久化接入与只读展示，但不能直接写 Repository、不能复用旧的“仅 changeStatus”首次启动路径，也不能扩张为 Todo 或可编辑的下一步能力。

## 【已审阅的稳定契约】

### 1. Contracts

```ts
interface Item {
  // existing fields
  startAction?: string
}

interface StartItemExecutionInput {
  startAction?: string
}

interface ItemRepository {
  startExecution(id: string, input?: StartItemExecutionInput): Promise<Item>
}
```

字段语义固定为：首次由 `idea_to_try` 进入 `doing` 时可选记录的、不可编辑的历史启动动作快照。

- `undefined`、空字符串和纯空白输入：不持久化字段；
- 非空输入：Repository `trim()` 后持久化；
- 不设置独立长度上限；前端不得自行添加 `maxlength`；
- 不新增 `updateStartAction`、`clearStartAction`、`replaceStartAction` 或通用 `updateItem`。

### 2. Application 命令

```ts
itemApplication.startExecution(itemId, startAction?)
```

该命令是首次启动的唯一正常写入路径：

```text
有非空输入
→ startExecution(itemId, input)
→ 原子写入 startAction、doing 与状态事件

无输入
→ startExecution(itemId)
→ 原子写入 doing 与状态事件，但不写 startAction
```

`changeStatus(itemId, 'doing')` 保留给既有普通状态迁移，尤其是 `paused → doing`。在启动确认层中，它只能用于用户在“保存启动动作”失败后，明确选择“**不保存，直接开始**”的降级分支。

### 3. Repository 原子性与不可改写保护

`IndexedDbItemRepository.startExecution()` 已在单个 `readwrite(items, itemStatusEvents)` 事务内：

```text
事务内读取当前 Item
→ 校验事项存在且未删除
→ 校验 idea_to_try → doing 合法
→ 拒绝已有 startAction 的重写
→ 规范化输入
→ 写入 Item
→ 写入 ItemStatusEvent
→ 一起提交或一起回滚
```

已确认以下不变量：

```text
startAction（非空时）
+ idea_to_try → doing
+ 唯一状态事件
→ 同时成功或同时回滚
```

`items.put()` 或状态事件写入失败均不会留下部分状态。现有 `updateContent()`、状态迁移、删除、恢复与永久清理继续维持事务内重新读取规则，不会因启动动作而回退已关闭的 Item 并发一致性 P0。

### 4. 备份与兼容

不涉及 Dexie Schema、Dexie version、Migration、备份集合或 `BackupDocument.version` 变更。

- 新备份会随 `Item` 原样导出和恢复 `startAction`；
- 历史备份缺失该字段合法，恢复为无快照；
- `startAction` 存在但不是 `string` 时，`parseAndValidate()` 必须拒绝导入；
- 不得根据标题、`content`、状态事件、时间、Review 或方法关系猜测补填历史启动动作。

## 【当前页面实现差异：必须在前端实施时修正】

当前 `apps/client/src/pages/index/index.tsx` 已有启动确认层，但它仍是被产品否决的旧语义：

```text
输入仅作为临时提醒
→ confirmStart() 调用 changeStatus(itemId, doing)
→ 提示“不会保存到事项中”
```

并且当前输入控件带有 `maxLength={300}`。这与稳定契约冲突：

```text
旧实现：不保存、普通 changeStatus、前端 300 字限制
稳定契约：可选持久化、首次启动必须 startExecution、无独立长度上限
```

因此，**允许前端接入不等于当前页面已验收**。前端必须替换该确认层的提交路径、文案与失败分流，才可进入 H5 验收。

## 【前端实施冻结约束】

### 启动确认层

仅在未删除的 `idea_to_try` 事项触发“开始执行”时打开确认层。

正常态：

```text
可选输入：此刻准备先做什么？
取消 / 开始推进
```

- 有输入：调用 `itemApplication.startExecution(itemId, prompt)`；
- 无输入：调用 `itemApplication.startExecution(itemId)`；
- 取消、点击遮罩或 Esc：只关闭确认层，不写任何数据；
- 取消时丢弃该次临时输入，不自动保存为草稿或补充说明；
- 删除现有 `maxLength={300}`，不得另设未冻结长度限制；
- 更新提示文案，不得再出现“不会保存到事项中”。

### 保存失败后的分流

只有“用户输入非空启动动作”且 `startExecution()` 失败后，才显示：

```text
重试保存
不保存，直接开始
```

- **重试保存**：保留原输入，再调用 `startExecution(itemId, prompt)`；
- **不保存，直接开始**：用户明确丢弃本次输入，再调用 `changeStatus(itemId, 'doing')`；
- 无输入启动失败：仅显示可重试的失败反馈，不展示“不保存，直接开始”；
- 不存在、已删除或状态已变化：保留输入，刷新当前事项；不得覆盖新状态、不得宣称开始成功；
- “启动动作已存在，不能重写”：刷新并展示已保存快照；不得提供覆盖入口；
- 所有异步结果仅更新对应 `itemId`；切换事项、关闭确认层或请求返回后，均不得覆盖其他事项的选择或草稿。

### 只读展示

仅当 `startAction` 有值时展示“启动动作”。

| 位置 | 展示层级 |
|---|---|
| `doing` | 低于补充说明，高于操作按钮 |
| `paused` | 作为恢复上下文 |
| `waiting_review` | 低于待复盘任务和复盘入口 |
| `reviewed` | 低于复盘事实、方法证据和状态历史 |
| `archived_no_review` / `abandoned` | 低于终局状态事实和流转历史 |
| 回收站 | 只读展示 |
| `idea_to_try` / `idea_later` | 不显示空占位 |

禁止表现为：

```text
待办复选框
当前下一步
完成按钮
进度条
可编辑输入框
可替换 / 清空 / 追加入口
```

## 【风险与保护策略】

1. **前端继续调用普通 `changeStatus()`**：会绕开有输入时的原子快照写入。首次启动正常分支必须调用 `startExecution()`。
2. **异步结果覆盖用户意图**：前端需用 `itemId`、当前确认层状态和请求中状态保护草稿与选中事项；失败不清输入，成功只更新对应事项。
3. **语义膨胀为 Todo**：不增加编辑、完成、勾选、进度、多个动作或后续替换。
4. **历史数据伪造**：旧备份缺字段即无快照，绝不推断。
