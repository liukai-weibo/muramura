# 平台角色与最小权限管理 V1—切片 5 P1 管理顶部按钮命中区域最小修复架构裁决

日期：2026-07-31
状态：架构冻结完成；尚未获得前端修复与完整复测授权

## 技术结论

可行。真实 H5 中 Taro `Button` 的命中元素为 `taro-button-core`，但管理页顶部的通用布局和按钮命中盒规则主要使用原生 `button` 选择器。现有样式未完整约束 `.platform-administration-header` 与 `.platform-administration-search` 内实际 Taro 元素的显示盒、flex 占位和指针命中层，真实 Chromium 因而命中父级 `taro-view-core`。

该问题只需补齐管理页顶部两个区域的 H5 元素选择器和命中盒，不需要修改 JSX、事件、搜索状态或任何后端能力。

## 最小修复

只在 `index.scss` 为以下实际元素增加局部规则：

- `.platform-administration-header > taro-button-core.platform-administration-refresh`
- `.platform-administration-search > taro-button-core`

规则仅可完成以下目的：

1. 将启用按钮建立为明确的 `inline-flex` 命中盒，并在盒内居中现有内容。
2. 固定 `box-sizing: border-box`、`flex: 0 0 auto`，避免 Taro 自定义元素的默认显示方式使可见内容与可点击盒错位。
3. 以局部 `position: relative` 和最小局部层级保证按钮自身位于对应父容器的命中层；不得创建覆盖页面其他区域的绝对定位或全局 stacking context。
4. 启用态保持 `pointer-events: auto` 和既有 pointer cursor；既有 disabled 规则必须同时覆盖 `taro-button-core[disabled='true']` 并继续 `pointer-events: none`。
5. 复用现有尺寸、颜色、边框和响应式规则，不改变视觉布局；若现有原生 `button` 选择器需并列补充 `taro-button-core`，只能限定在 `.platform-administration` 内。

禁止通过给父容器设置 `pointer-events: none` 解决：这会破坏搜索 input、子按钮事件和响应式交互。禁止扩大按钮透明覆盖层、使用负 margin、绝对定位、JavaScript 转发点击或父容器代理点击。

## 数据、状态与交互边界

- 搜索输入仍只更新 `queryDraft`，只有真实点击“搜索”或既有 Enter 才提交 `appliedQuery`。
- “搜索”和“刷新”每次真实点击各只调用一次既有列表 GET；不得通过 pointer/mouse/click 多事件重复绑定。
- 不修改清除、分页、固定每页 20 条、搜索字面量、稳定排序和旧请求保护。
- 不修改 401/403 卸载、权限预门控、operationId、目标级写锁以及角色/会话两类 unknown-outcome。
- 刷新仍是 unknown-outcome 的既有显式事实重读入口，不增加自动重读、自动重试或成功推断。
- 不涉及 Schema、Migration、Backup、API、DTO、Contracts、Application、Repository 或运行库。
