# 回收站永久删除与批量操作：架构评审

日期：2026-08-09

## 结论

有条件可行。新增 API 与 Application 能力，但不新增表、字段、Migration 或备份格式。

## 实现边界

- H5 通过现有回收站完整筛选结果完成跨分页选择。
- MySQL 使用当前用户 scope，在单个事务中按稳定顺序处理批量记录；任一失败整批回滚。
- 事项复用既有关联清理语义；方法写入既有 `method_tombstones` 并清理版本；探索主线锁定后检查是否存在关联事项，有关联即拒绝。
- API 为 `DELETE /api/v1/trash/{type}/{id}` 与 `POST /api/v1/trash/purge`，不修改既有恢复接口。

## 风险

永久删除不可逆，前端必须二次确认；跨用户 ID 必须按 owner scope 视为不存在，不泄露记录。
