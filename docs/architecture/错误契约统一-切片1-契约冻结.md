## 问题

项目同时存在三套失败码：

1. `BusinessErrorCode`（事项/方法/复盘/探索主线/备份）
2. Application 内联认证短码（`invalid-credentials` / `username-taken`）
3. 平台管理 Application / Repository 短码（kebab）

API `mapFailure` 按 `instanceof` 分叉，整体不可读，也不利于后续扩展。

## 契约结论

1. **一套码表**：认证、平台管理并入 `BusinessErrorCode`（`AUTH_*` / `PLATFORM_ADMIN_*` / `BACKUP_OWNERSHIP_CONFLICT`）。
2. **分类补齐**：`BusinessErrorCategory` 增加 `unauthorized` / `forbidden`。
3. **外泄白名单**：`publicBusinessErrorCodes` + `isPublicBusinessErrorCode`；API 响应 `businessCode` 类型收窄为 `PublicBusinessErrorCode`。登录失败码不得入白名单。
4. **迁移对照表**：保留旧短码 → 统一码、Repository kebab → 统一码的映射，供后续切片改 Application / API 接线。
5. **本切片不做**：删除 `AuthenticationError` / `PlatformAdministrationApplicationError`、改仓储抛错字符串、改 H5 分支逻辑。
