# 错误契约统一 — 切片 2：消灭翻译层

> 状态：已实施
> 日期：2026-08-02

## 原则

```text
同一失败原因 → 一个 BusinessErrorCode
仓储 / Application 直接 fail(code, message)
BusinessError 的 category 只由中央码表派生，调用点不得传入
API 只按 category 映射 HTTP + 白名单决定 businessCode
翻译次数默认 0
```

## 已删除

- `AuthenticationError` / `PlatformAdministrationApplicationError` / `PlatformAdministrationRepositoryError`
- `AuthRepositoryError` / `BackupOwnershipConflictError` / `InitialOwnerClaimError`
- 各类 kebab 仓储失败码、Failure kind、旧短码→统一码对照表
- Application 内 `callPlatformAdministrationRepository` 等手动翻译包装

## 保留

- 统一 `BusinessError` + `fail` / `businessFailure`
- `businessErrorCategoryByCode`
- 区分认证参数格式失败 `AUTH_CREDENTIALS_FORMAT_INVALID` 与认证校验失败 `AUTH_INVALID_CREDENTIALS`
- `publicBusinessErrorCodes`（登录失败码不外泄）
- MySQL 连接、Schema 未就绪等非业务基础设施故障的独立处理边界

## 验证

- 错误契约、Application、认证角色、事项标题与 SQLite 备份五组定向测试共 22 项通过。
- `typecheck`、H5 build 与 `git diff --check` 通过。
- 全量测试未出现错误契约统一相关新增失败；现存失败仍为浏览器依赖缺失、沙箱监听限制及既有断言偏差。
