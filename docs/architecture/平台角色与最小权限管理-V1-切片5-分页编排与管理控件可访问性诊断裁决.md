# 平台角色与最小权限管理 V1—切片 5 分页编排与管理控件可访问性诊断裁决

日期：2026-07-31
状态：只读诊断与范围冻结完成；尚未获得测试/生产修正及完整复测授权

## 技术结论

两个剩余失败必须分开裁决：

1. `member_a` 定位失败属于 E2E 编排与冻结分页不一致，不是生产分页或角色写入缺陷。
2. 新目标“管理用户名”定位失败属于生产可访问语义缺口，不是 currentUserId、targetLocks、几何或指针命中缺陷；`taro-button-core` 有 accessible name 但没有 button role。

切片 5 仍不通过，但不得把这两项合并成角色写入 P1，也不得通过 CSS locator 绕过第二项。

## 分页编排裁决

冻结事实为每页 20 条，排序 `createdAt DESC → userId ASC`。搜索/分页测试创建 24 个用户并最终停在第 1 页；早期创建的 `member_a` 必然不在当前页。后续直接等待该行没有合法前置条件。

最小修正采用既有冻结搜索，不硬编码“第 2 页”：

- 在角色测试操作 `member_a` 前，将管理搜索草稿设为其完整 username，使用既有明确搜索提交，等待唯一目标行后再调用既有管理动作。
- 创建会话撤销目标后，同样用完整 username 搜索并等待唯一目标行，再执行撤销会话。
- unknown-outcome 测试开始前，通过既有清除搜索或空查询明确恢复未筛选第 1 页，再创建/刷新新目标；不得继承上一测试的 query/page。
- 测试内每次跨目标操作都必须先建立“目标在当前读模型”的可见前置条件，不从创建顺序猜测页码。

禁止改变生产 pageSize、排序、分页状态、自动翻页或前端定位逻辑。禁止直接把 `member_a` 插到第 1 页、减少用户数或通过 API 直写页面状态。

## 管理控件只读诊断

诊断使用当前 dist、随机 loopback 静态服务、内存认证/用户列表读模型和隔离 Chromium；未连接现有 API/MySQL，未创建 database、账号或持久化浏览器状态。actor 与 target 使用明确不同的诊断 ID。

### 身份与锁分支

- `currentUserId=diagnostic-actor`。
- `targetId=diagnostic-target`，两者不相等。
- 目标行无“当前账号”标记。
- 目标行无 role-unknown 的“刷新用户列表”，也无 sessions-unknown 的“再次撤销会话”。
- `.platform-more-button` 已渲染。依照唯一渲染分支 `!current && !locked`，可以稳定反证目标不是当前账号，且 `targetLocks[targetId]` 的有效状态为 `idle`/无条目。

上一轮真实临时库已 finally 清理，内部 React state 未持久化，不能追溯其随机 ID 或直接读取已销毁实例；本次结论以同一生产构建和相同状态分支的可观察 DOM 为依据，不伪造已清理运行的内部值。

### DOM、几何与命中

目标控件真实 DOM：

`<taro-button-core aria-label="管理diagnostic-target" class="platform-more-button" type="">更多</taro-button-core>`

- `.platform-more-button` 数量：1。
- `disabled` 属性：不存在；不是禁用态。
- computed：`display:block`、`pointer-events:auto`、`visibility:visible`、`opacity:1`。
- bounding box：x=1031.125、y=405.375、178.875×40，中心在视口内。
- `elementsFromPoint` 中心点栈顶：该 `.platform-more-button` 自身。
- CSS locator 数量 1；`getByLabel('管理diagnostic-target')` 数量 1。

因此不存在“控件未渲染、被锁隐藏、位于视口外或被其他元素拦截”的生产状态证据。

### 可访问树

- DOM 无显式 `role`。
- CDP 可访问树将 `aria-label="管理diagnostic-target"` 暴露为 name，但 role 为 `generic`，不是 `button`。
- Playwright `getByRole('button', { name: '管理diagnostic-target' })` 数量为 0。

裁决：现有 E2E 对一个产品意图明确的管理按钮使用 role+name 定位是合理的，不应改成 CSS 或 `getByLabel` 掩盖语义缺口。生产组件需要为该单一自定义宿主显式补充 `role='button'`；这不改变点击、锁、菜单、权限或写入行为。

## 最小生产修正

仅允许在 `apps/client/src/pages/index/platform-administration.tsx` 的 `.platform-more-button` 上增加显式 `role='button'`，保留现有 `aria-label`、文本、onClick 和条件渲染不变。

本切片不扩张为全站可访问性改造，不新增 tabindex、键盘语义、aria-haspopup/expanded、DOM 包装或 Button 组件替换；若产品希望完整键盘可访问性，须另行立项，不能混入当前 P1 闭环。
