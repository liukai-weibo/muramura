# 平台角色与最小权限管理 V1—切片 5 P1 搜索输入最小修复架构裁决

日期：2026-07-31
状态：架构冻结完成；尚未获得前端修复与定向复测授权

## 技术结论

可行。该 P1 是 H5 搜索输入事件的生命周期缺陷：事件处理函数把 `event.currentTarget.value` 留到 React 状态 updater 执行时才读取，真实 Chromium 中 updater 执行时 `currentTarget` 已失效。修复不需要也不允许改变搜索、分页、权限、API 或数据语义。

## 最小修复

仅将搜索框 `onInput` 调整为以下等价时序：

1. 在事件处理函数同步读取一次 `event.currentTarget.value`，保存为局部不可变字符串。
2. 将该字符串传入既有 `setQueryDraft` updater。
3. updater 继续调用既有 `acceptPlatformUserQueryDraft(current, capturedValue)`，保留当前合法草稿与 80 code unit 边界。

状态 updater、Promise、timer、effect 或其他延迟回调中均不得再次读取事件对象。输入本身仍只更新 `queryDraft`，不得发起 HTTP；只有既有 Enter、搜索按钮或既有明确提交动作可以更新 `appliedQuery` 并发起冻结 GET。

## 数据与契约边界

- 不涉及 Schema、Migration、Backup 或运行库。
- 不修改 API、DTO、Contracts、Application、Repository、认证或授权。
- 不修改用户名搜索的字面量语义、请求参数、最大长度、固定每页 20 条、稳定排序或分页状态。
- 不修改 401/403 页面卸载、operationId、目标级写锁、旧请求保护及角色/会话两类 unknown-outcome。
- `%_=` 只作为本地搜索草稿同步接收；明确提交后仍由既有 API 按已冻结字面量搜索契约处理。

## 竞态与失败保护

- 同一次输入只采样一个字符串值，后续状态计算只能使用该值，避免事件失效和跨事件错读。
- 不增加网络请求、自动提交、debounce、自动重试或全局异常吞噬。
- 不改变 `queryDraft` 与 `appliedQuery` 分离；输入、提交、清除、翻页和刷新继续沿用现有 read generation、fact generation、Abort 与认证上下文保护。
- 修复失败时不得通过 Error Boundary、重新挂载工作台或刷新页面掩盖问题。
