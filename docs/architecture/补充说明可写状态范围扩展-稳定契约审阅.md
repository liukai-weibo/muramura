# 补充说明可写状态范围扩展 — 稳定契约审阅记录

> 审阅日期：2026-07-21
> 依据：数据层 QA 验收通过；定向测试 3 文件 / 11 项通过；全量测试 19 文件 / 74 项通过；typecheck、H5 build 与 diff 检查通过。
> 结论：**稳定契约审阅通过，允许前端开放所有未删除事项的补充说明编辑入口。**

## 【技术结论：可行】

实际 `IndexedDbItemRepository.updateContent()` 已与产品最终裁决一致：

```text
transaction(rw, items)
→ 事务内 items.get(id)
→ 不存在或 deletedAt 存在：事项不存在
→ trim content
→ 仅写 content / updatedAt
→ 返回更新后的 Item
```

该操作不再按 `Item.status` 拒绝，因此全部八种未删除状态均可保存或主动清空补充说明；回收站仍只读。

已复盘、归档、放弃等状态更新补充说明时，复盘、证据、方法应用和状态历史均不被改写。P0 并发一致性修复继续保留，内容更新不会以旧快照回滚并发状态或删除标记。

## 【冻结的前端契约】

### 唯一写入入口

```ts
itemApplication.updateItemContent(itemId, content)
```

前端不得直接调用 Repository 或 IndexedDB，也不得把此能力泛化为标题、状态、日期、标签或其他字段编辑。

### 可写范围

```text
所有 deletedAt 不存在的事项：
idea_to_try
idea_later
doing
paused
waiting_review
reviewed
archived_no_review
abandoned
```

```text
所有 deletedAt 存在的事项：
只读；不显示编辑入口；保存会稳定失败“事项不存在”
```

### 更新不变量

每次成功保存只允许改变：

```text
Item.content
Item.updatedAt
```

必须保持不变：

```text
Item.id
title
status
createdAt
ItemStatusEvent
Review
Method
MethodVersion
MethodEvidence
MethodApplication
ItemLink
```

空字符串是合法的显式保存结果，表示用户主动清空补充说明。

## 【历史状态的前端信息层级】

允许编辑不等于提升内容为事实层。

| 状态 | 页面必须优先的内容 | 补充说明位置 |
|---|---|---|
| `waiting_review` | 待复盘任务与事实复盘入口 | 次级、不得阻碍复盘 |
| `reviewed` | 复盘事实、方法证据、状态历史 | 位于事实之后 |
| `archived_no_review` | 归档状态与流转历史 | 位于状态说明之后 |
| `abandoned` | 放弃决策与流转历史 | 位于决策说明之后 |

`content` 永远只表达背景、范围、上下文和“为什么值得做”；不得在 UI 文案或结构中暗示它是复盘、进度、暂停 / 放弃 / 归档原因、第一步或方法步骤。

## 【前端异步与草稿保护】

前端须继续遵守既有草稿保护，不因范围扩展而降低：

1. 草稿按 `itemId` 隔离，仅存页面生命周期内；
2. 用户显式点击保存才调用写入；取消不调用；
3. 保存成功仅更新对应 ID 的详情与列表项，按 `updatedAt` 既有规则重排，保持 `selectedId`；
4. 保存失败时保留对应草稿；
5. 已删除 / 已进入回收站导致的 `事项不存在` 必须可解释展示，不能自动恢复或自动重试；
6. 切换事项、搜索刷新、列表刷新或旧请求返回不得串写其他事项的详情、编辑态或草稿；
7. 当前编辑中发生状态迁移不再阻止保存，只要事项未删除即可保存；
8. 若搜索结果浮层正在展示，保存成功后应刷新当前查询或关闭旧结果，避免陈旧 `content` 摘要。

## 【前端最低 H5 验收】

1. 八种未删除状态均有添加 / 编辑 / 主动清空补充说明入口；
2. 回收站只读，且不显示编辑入口；
3. `waiting_review`、`reviewed` 中说明区低于复盘入口和复盘事实；
4. `archived_no_review`、`abandoned` 中说明区低于状态决策与流转历史；
5. 显式保存、取消、空内容保存、失败保留均正确；
6. 删除 / 移入回收站后再保存，草稿保留且显示“事项不存在”；
7. 切换事项、保存中状态迁移和异步返回不串写草稿；
8. 保存后详情、列表、当前搜索结果一致；
9. 窄屏下操作层级、长文本和保存反馈可用；
10. 前端验证后执行相关测试、typecheck、build:h5，并交 QA 人工 UAT。
