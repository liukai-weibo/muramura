# 平台角色与最小权限管理 V1—H5 用户管理页分页禁用展示标记最小扩展授权

日期：2026-07-31

状态：产品已授权单点 TSX 展示标记修复；完成后回流原视觉 P1 独立 QA

## 产品裁决

真实 Chromium 已证明 Taro H5 对分页按钮的 `disabled` 序列化不足以承担视觉判定：首页业务禁用的“上一页”与末页业务启用的“上一页”均可能输出 `disabled=""`，且属性、结构、尺寸和命中宿主相同。CSS 无法在不误伤启用按钮的前提下区分二者。

因此授权为两个分页按钮增加由既有禁用布尔表达式直接生成的页面局部展示 class。该 class 只为 SCSS 提供可信视觉标记，不成为新的业务状态，不替代或改变既有 `disabled`、点击保护或分页行为。

## 唯一允许实现

- 两个分页按钮都固定拥有基础 class：`platform-pagination-button`。
- “上一页”仅在既有表达式 `page <= 1 || refreshing` 为真时附加 `platform-pagination-button-disabled`。
- “下一页”仅在既有表达式 `page >= pageCount || refreshing` 为真时附加 `platform-pagination-button-disabled`。
- 现有两个 `disabled={...}` 表达式必须保持原样；不得删除、替换或改为新的判断来源。
- 现有 `onClick={() => changePage(...)}`、`changePage` 防卫、页码计算、请求与状态更新必须保持原样。
- SCSS 只在 `.platform-administration-pagination` 内以 `.platform-pagination-button-disabled` 应用设计冻结的禁用视觉：文字 `#6F675E`、背景 `#EEEAE4`、边框 `#DDD4C8`、`opacity:1`、`cursor:not-allowed`、`pointer-events:none`。
- 基础 class 不得改变启用按钮已有视觉、尺寸、hover、active、focus 或命中能力。
- 既有原生 `:disabled` 与 Taro `[disabled='true']` 规则继续保留，兼容其他正常序列化宿主；禁止新增 `[disabled]`、`[disabled='']`、位置、文案、页码或 `:first-child/:last-child` 推断。

不得使用 `aria-disabled` 作为本次唯一视觉来源，避免再次依赖自定义元素属性序列化；可访问语义仍由既有 `disabled` 和事件保护承担。本次只授权 class。

## 直接测试与 QA

直接测试必须精确断言：

- 两个分页按钮都有基础 class；
- 上一页 disabled class 只来自 `page <= 1 || refreshing`；
- 下一页 disabled class 只来自 `page >= pageCount || refreshing`；
- 两个原 `disabled` 表达式与两个 `onClick/changePage` 调用保持不变；
- SCSS 禁用 class 仅位于分页作用域，冻结颜色、背景、边框、opacity、cursor 与 pointer-events；
- 不存在 `[disabled='']`、`[disabled]`、位置或文案推断。

修复后必须重新执行：

- 直接视觉测试；
- 既有用户管理 H5 回归与完整 H5 回归；
- typecheck、`build:h5`、`git diff --check`；
- 原四视口 `1440×900`、`1280×720`、`390×844`、`360×800` 的完整截图复验。

真实 Chromium 必须证明首页禁用“上一页”和末页禁用“下一页”采用冻结禁用样式且不可点击；首页启用“下一页”、末页启用“上一页”保持普通样式、`pointer-events:auto`、中心命中宿主自身并各只触发一次既有列表 GET。中间页两个按钮均保持启用，不得被 class 误判。
