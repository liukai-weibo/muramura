## 执行门

- 测试默认跳过，仅在 `KB_PLATFORM_V1_SLICE5_E2E=1` 与 `KB_PLATFORM_V1_SLICE5_ALLOW_TEMP_DDL=YES-I-UNDERSTAND` 同时满足时运行。
- MySQL host/port 必须精确为本机 `127.0.0.1:3306` 或等价 `localhost:3306`；环境由 QA 在项目外安全注入，不得读取 `.env`/`.env.uat`。
- `apps/client/dist/index.html` 必须来自本轮 `build:h5`。
- 标准执行顺序仅为先构建 H5，再串行运行切片 5 单文件 E2E；环境秘密不得回显到命令、日志或报告。

## 测试拓扑与权限

- 仅创建随机 `kb_platform_v1s5_*` 临时 database、独立 app/migrator 账号和随机密码。
- app 账号仅拥有目标临时 database 的 `SELECT, INSERT, UPDATE, DELETE`。
- migrator 账号仅拥有目标临时 database 的 `SELECT, INSERT, CREATE, ALTER, INDEX, REFERENCES`。
- 禁止 `DROP`、全局权限、`GRANT OPTION` 和其他 database 权限；root 仅用于临时资源生命周期、权限核对及两运行库只读快照。
- API、fault API、H5 只监听操作系统分配的随机 `127.0.0.1` 端口；不得监听 `0.0.0.0` 或占用/停止 10086、32146、3306。
- 每个用户使用独立、无持久化、headless Chromium context，禁止复用个人 profile、storageState 或已有 Cookie。

## 必须覆盖

- 同一临时库仅执行 001–005 时 Schema 5 监听前拒绝；执行未经修改的 006 后 Schema 6 启动成功且 health 指向随机临时 database。
- 初始管理员 CLI、真实 Cookie、旧会话角色实时刷新和 H5 管理入口完整闭环。
- 用户列表、搜索、分页、角色授予/撤销和全部会话撤销。
- member 统一 403、管理员目标 404、operationId 409、actor 事务内降级和双管理员并发互撤。
- 角色与会话两类 unknown-outcome、503、Abort、响应丢失及各自冻结的显式恢复路径；每次目标写请求仅一条且无自动重试。
- `platform_admin` 仍不能绕过十个业务集合及 Backup owner scope。
- 敏感信息扫描、两运行库 PRE/POST 只读深度快照、临时资源 finally 清理和零残留。

## 禁止范围

- 禁止修改 `apps/api/src/**`、`apps/client/src/**`、`packages/**`、`migrations/**`、`scripts/**`、任何 `package.json`、lockfile、`.env`、Docker 或配置。
- 禁止修改既有测试文件、生产注入点、路由、DTO、日志或错误映射。
- 禁止停止、替换或重启现有 API/H5/MySQL，禁止修改容器、mysql-data、现有账号权限或运行库。
- 禁止在 `knowledge_base`、`knowledge_base_uat` 执行 DDL/DML、Migration、注册、登录、Backup、claim 或业务 API。
- 发现需要生产代码或配置变更时必须立即阻断并回架构/产品重新评审，不得在本授权内修复。

## 安全与验收门

- 密码、password_hash、Cookie value、会话秘密/摘要、operationId 原文和私有配置值不得输出、落盘或进入证据。
- 禁止 Playwright trace、HAR、video、storageState 和包含原始 headers/body 的附件。
- 所有临时 database、账号、连接、随机进程、端口、browser context 和临时证据必须按任务书 finally 顺序清理。
- 清理失败即 QA 不通过；只允许按 manifest 与 runId/正则双重校验清理本轮精确资源，不得扩大清理范围。
- `knowledge_base` 与 `knowledge_base_uat` PRE/POST 必须分别 `SNAPSHOTS_IDENTICAL`，并继续保持 15 表、Schema 5、平台表 0。
- 切片 5 QA 通过只构成 V1 最终产品验收输入，不自动授权真实 006、真实管理员授予、服务重启部署或运行库接入。
