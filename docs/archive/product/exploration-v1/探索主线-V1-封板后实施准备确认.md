## 【已确认的实施边界】

- `004_add_exploration_tracks.sql` 只新增主线表、事项可空外键、索引和全生命周期名称唯一约束；日常库与 UAT 库分别迁移；不修改既有 migration，不为正式库提供回滚脚本。
- `BackupDocumentV3` 增加 `explorationTracks`；V1 / V2 安全降级为空主线关系；V3 的断裂引用在事务前整体拒绝，十个业务集合零写入，`system_metadata` 保持隔离。
- 事项与主线保持可信 `0..1` 关系；创建事项并关联既有或新主线保持单一 MySQL 事务，失败无半成品；不得由 API、前端或多个公开 Repository 调用拼接。
- 主线软删除、恢复、关联调整、`unavailable` 降级、当前关联事项读模型、已删除主线管理、受限状态定位查询均与 API 契约一致。
- API 仅实现已冻结矩阵、DTO、错误码与 unknown-outcome 策略；无幂等键时不得自动重试或依据草稿判断写入结果。
- 日常 `knowledge_base` 与 UAT `knowledge_base_uat` 保持同容器双库隔离；破坏性 reset、恢复与故障注入只允许触及 UAT。
- 实施顺序固定为 S1 Schema / Contracts → S2 Repository / Application → S3 Backup / API；每个切片必须通过相应测试门后才进入下一切片；H5 接入仅在 S3 后进行。

- 不得引入双写、同步、回填、fallback、浏览器直连 MySQL、真实 IndexedDB 历史迁移或远程访问。
