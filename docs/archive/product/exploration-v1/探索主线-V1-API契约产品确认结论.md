# 探索主线 V1 API 契约产品确认结论

> 确认日期：2026-07-24
>
> 结论：**API 路由矩阵、DTO、稳定错误码与未知写入结果策略确认；设计稿须按确认契约修订；当前禁止编码。**
>
> 依据：`当前运行事实.md`、`探索主线-Sprint-产品范围冻结与实施计划.md`、`探索主线-V1-产品评审结论.md`、`探索主线-V1-设计冻结验收结论.md`、`../architecture/探索主线-V1-API路由矩阵与DTO补充冻结.md`。

## 【结论】

确认架构补充矩阵是探索主线 V1 后续实施的 API 契约冻结依据。它补齐了设计冻结验收中的三项阻断：快速捕获的原子“创建并归入”、主线详情的当前关联事项读模型、已删除主线的受限管理列表。

本确认不改变现有产品范围、状态机、复盘语义、回收站规则、备份冻结取舍或当前阶段门。

## 【确认的 API 契约】

### 1. 快速捕获“创建并归入”

确认不新增独立“创建并归入”写接口；扩展既有 `POST /api/v1/items` 的 `explorationTrack` 可选选择对象。

- 选择新主线时，名称仅为前端未提交表单暂存；不得在输入名称或选择名称时创建主线。
- 用户点击“加入想试试”或“加入以后再说”时，才发起一次写请求。
- 选择既有主线时，单一事务完成：锁定活跃主线、创建事项、创建初始状态事件、写入关联。
- 选择新主线时，单一事务完成：创建主线、创建事项、创建初始状态事件、写入关联。
- 任一步失败必须整体回滚，不留下主线、事项、状态事件或关联半成品。
- 失败保留事项输入、新主线名称和初始状态选择；取消选择零写入。
- 独立“新建探索主线”入口仍允许创建空主线。

### 2. 当前关联事项读模型与真实定位

确认使用 `GET /api/v1/exploration-tracks/:id/history` 内嵌 `currentAssociatedItems`，不新增独立当前事项聚合路由。

- 状态范围和展示顺序固定为：`doing` → `idea_to_try` → `idea_later` → `paused`。
- 每个状态最多返回 3 条，排序固定为 `createdAt DESC, id ASC`。
- 所有当前关联事项为空时，详情页显示“还没有关联行动。”。
- 超出上限仅返回 `hasMore` 与真实 `moreLocator`；禁止返回事项总数、剩余数、完成率、进度、计划或日期。
- “查看该状态下的事项”固定调用 `GET /api/v1/items?status=<status>&explorationTrackId=<trackId>`；仅返回真实关联、未删除、真实处于该状态的事项，排序固定为 `updatedAt DESC, id ASC`。
- 前端不得从主线历史、本地缓存或标题、时间、状态文案自行筛选、排序、截断或推断关系。

### 3. 已删除主线管理

确认新增 `GET /api/v1/exploration-tracks/deleted` 作为已删除主线的受限只读列表。

- 只返回软删除主线，排序固定为 `deletedAt DESC, id ASC`。
- 不显示数量，不提供永久删除，不进入活跃主线列表或任何主线选择器。
- 已删除主线仅允许通过 `GET /api/v1/exploration-tracks/:id/history` 查看事实，并通过 `POST /api/v1/exploration-tracks/:id/restore` 恢复。
- 删除和恢复均不得改写关联事项、复盘、方法、事项关系或状态事件。

### 4. 错误码与未知写入结果

确认以下稳定错误语义：

- `400 VALIDATION_FAILED`：名称空白或超过 80 字符、非法主线选择、非法状态或定位参数。
- `404 NOT_FOUND`：主线或事项不存在，或当前生命周期操作不允许。
- `409 CONFLICT`：名称冲突，包含软删除主线和并发唯一键竞争。
- `503 MYSQL_SCHEMA_NOT_READY` / `MYSQL_UNAVAILABLE`：Schema 未就绪或 MySQL 确实不可用。
- `500 INTERNAL_ERROR`：未分类且脱敏的内部异常。

所有主线写操作及扩展后的 `POST /api/v1/items` 不使用幂等键。超时、断线、页面关闭或响应丢失均视为未知写入结果：

- 禁止自动重试；
- 禁止根据本地表单推断成功或失败；
- 仅允许重新读取真实 API 数据确认事实；
- 保留草稿并提示“提交结果未确认，请重新获取真实数据后确认是否已生效”。

## 【设计冻结修订要求】

确认设计稿第 6.3 节必须改为：

```text
输入新主线名称
→ 仅作为未提交表单选择暂存
→ 用户提交“加入想试试”或“加入以后再说”
→ 单一原子请求创建主线、事项、初始状态事件和关联
→ 全部成功后才显示创建成功
```

设计稿还须引用已冻结的 `currentAssociatedItems` 与已删除主线受限列表契约；设计修订不得新增产品语义。

## 【阶段门与实施授权】

当前 MySQL 快速接入 Sprint 尚未完成浏览器级完整主流程、JSON 导出—清库—恢复、API / MySQL 重启后的页面验证，以及写入失败阻断的根因修复与复验。

因此：

- 当前仍只允许表述“MySQL 是当前 H5 运行数据源”；
- 探索主线当前仍禁止任何数据层、API 或前端业务编码；
- API 矩阵可作为后续数据 / Application / Repository 实施任务书的冻结依据，但仅在当前 MySQL Sprint 正式封板、设计稿修订完成、架构补齐 004 Migration、Backup V3、自动化测试任务书后方可实施；
- 前端继续等待数据 / Application / Repository 能力、API 契约和修订后的设计交付完成。
