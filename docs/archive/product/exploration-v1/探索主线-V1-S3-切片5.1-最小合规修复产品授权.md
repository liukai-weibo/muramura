# 探索主线 V1 S3 切片 5.1：最小合规修复产品授权

> 授权日期：2026-07-26
>
> 裁决：**可编码；仅限三项合规修复。切片 5 UAT 不通过，探索主线 V1 不得封板。**

> 依据：`当前运行事实.md`、`探索主线-V1-S3-可信运行时接入产品范围冻结.md`、`../architecture/探索主线-V1-S3-最小架构任务书.md`、架构复审结论。

## 已授权修复

1. UAT 清理改为通过既有 Backup V3 的合法空文档恢复；不得 DROP/CREATE DATABASE。恢复只在单一 MySQL DML transaction 中清理十个业务集合，且不得导出、清理、恢复或覆盖 `system_metadata` 与 `schema_migrations`。
2. V3 导入中的断裂 `explorationTrackId` 必须映射为既有 `400 VALIDATION_FAILED`，并以自动化回归证明十个业务集合零写入。
3. 前端仅移除或改正“尚未接入真实数据能力”的失实 P2 文案；不得以文案修复引入新入口、交互或数据能力。

## 允许修改范围

- 既有 UAT 清理脚本及其直接测试：`scripts/**`、`tests/**`；
- V3 验证错误映射所必需的 `packages/application/src/**`、`apps/api/src/**` 及直接测试；
- 失实 P2 文案所在的 `apps/client/src/**` 及直接测试；
- 必要的架构、QA、产品验收记录和当天贡献记录。

## 禁止项

- 任何 migration、DDL、DROP/CREATE DATABASE、`mysql-data`、MySQL 容器/端口/权限修改；
- 修改 Backup V3 的业务语义、十集合范围、`system_metadata` 或 `schema_migrations` 隔离；
- 新增业务对象、字段、状态、关系、API 路由、DTO、筛选、计数、幂等、重试、fallback 或前端能力；
- 非 UAT 库写入、真实 IndexedDB/SQLite 资产操作、远程或非 loopback 入口。

## 验收门

- 合法空 V3 恢复后的 UAT 清理不执行 DDL，十个业务集合清空，`system_metadata` 与 `schema_migrations` 保持不变；
- V3 断裂 `explorationTrackId` 返回 `400 VALIDATION_FAILED`，且十个业务集合零写入；
- P2 文案准确反映当前真实 API 接入状态；
- 通过相关自动化测试、typecheck、`build:h5` 与 `git diff --check`，并更新当天贡献记录；
- QA 在合规基线重建后完整重做浏览器 UAT，随后转架构师复审。未经新的 QA 通过、架构复审和产品最终验收，不得封板。
