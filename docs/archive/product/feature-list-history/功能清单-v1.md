# 个人系统 Web 项目功能清单 v1

> 目标：把 KKK 的个人知识库和行动闭环做成一个可视化、可长期使用、可完整迁移的个人 Web 系统。

## 一、必须先明确的产品原则

1. **本地优先**：初期数据保存在自己的电脑，不依赖第三方平台才能使用。
2. **一件事只有一条主记录**：想法变成执行、执行进入复盘时，只改变状态，不复制出多份内容。
3. **过程可以追溯**：每次状态变化、关键修改和复盘结果都有记录。
4. **先跑通闭环，再追求大而全**：第一版先完成“想法 → 执行 → 复盘 → 方法”。
5. **随时可以完整导出**：不能把数据锁死在系统里。
6. **可视化服务判断与行动**：不是为了画面炫酷，而是让人一眼看见当前状态和下一步。

## 二、第一版必须实现（MVP）

### 1. 总览页

- 显示当前正在做的事
- 显示等待复盘的事
- 显示想试试的想法
- 显示当前不做、未来想试试的想法
- 显示最近形成或更新的做事方法
- 每个区域可以进入对应列表

### 2. 想法与待验证

- 新建想法
- 填写为什么想到、当前猜测、想验证什么、最小验证方式
- 状态分为：
  - 想试试
  - 当前不做、未来想试试
- 可以把想法转为“正在做的事”

### 3. 正在做的事

- 显示所有进行中的事项
- 填写为什么现在做、阶段目标、当前做法、下一步、检查日期、停止条件
- 可以从想法转入，也可以直接新建
- 执行结束后选择：
  - 需要复盘
  - 不需要复盘，直接归档
- 支持暂停、恢复和放弃

### 4. 复盘

- 待复盘列表
- 已复盘列表
- 复盘内容至少包括：
  - 实际做了什么
  - 结果怎样
  - 哪些地方有效或舒服
  - 哪些地方不兼容
  - 原因判断
  - 下次怎么调整
  - 产生了什么新想法
- 完成复盘后可以：
  - 新建一条待验证想法
  - 新建或关联一个做事方法
  - 只归档，不继续处理

### 5. 我的做事方法

- 新建、编辑、查看方法
- 记录适用情况、不适用情况、具体步骤、验证次数和当前版本
- 关联形成该方法的复盘记录
- 方法可以产生新的待验证想法
- 方法更新时保留版本或修改历史

### 6. 搜索和基础筛选

- 按标题和正文搜索
- 按状态、类型、标签筛选
- 按创建时间、更新时间排序
- 可以查看一个事项的完整流转历史

### 7. 数据导出

- 一键导出完整数据库备份
- 导出 Markdown + JSON
- Markdown 目录尽量对应当前个人知识库结构
- 导出内容包含正文、状态、关联、时间和历史记录
- 导出后生成清单和校验报告

## 三、第二阶段实现

### 1. 关于我

- 记录相对稳定的自我认识
- 可以关联支持或推翻该认识的复盘证据
- 标记为：稳定特点、正在建设、风险模式

### 2. 我想过怎样的生活

- 记录长期方向、阶段方向和明确不做的方向
- 当前项目可以关联它所服务的长期方向
- 可以查看“当前行动是否服务长期方向”

### 3. 我想学的人和东西

- 记录人物、书籍、文章、方法和生活方式
- 填写欣赏什么、为什么适合我、准备怎样验证
- 可以从外部内容生成一条待验证想法

### 4. 年、月、周计划

- 年计划、月计划、周计划使用同一套计划结构
- 上级计划可以拆成下级计划
- 执行事项可以关联到年、月、周计划，而不是复制三份
- 周计划服务月计划，月计划服务年计划
- 计划结束后可以进入复盘
- 未完成事项必须重新判断：继续、暂停、放弃，而不是自动滚动

### 5. 基础可视化

- 状态看板：想法、执行、待复盘、已复盘
- 流转时间线：一件事经历过哪些状态
- 计划树：年 → 月 → 周 → 执行事项
- 关联图：复盘如何形成方法，方法又产生哪些新想法

## 四、以后再考虑

- AI 帮助总结复盘、发现重复模式
- Obsidian 或现有 Markdown 双向同步
- 云端同步和多设备访问
- 手机端或桌面客户端
- 图片、音频和附件管理
- 提醒与日历集成
- 更复杂的统计图表
- 自由画布和脑图
- 多用户、协作和权限

## 五、第一版明确不做

- 不做多用户和社交功能
- 不做复杂权限系统
- 不先做完整年、月、周计划系统
- 不先做自由拖拽画布
- 不先做 AI 功能
- 不先做云同步
- 不追求同时兼容所有知识管理方法
- 不把现有 128 篇资料一次性全部导入新数据库

## 六、第一版完成标准

能够完整演示下面这条路径：

1. 新建“我想练瘦金体”的想法
2. 将它转成正在做的事
3. 填写执行过程并结束执行
4. 选择进入待复盘
5. 完成复盘
6. 从复盘中形成“我的写字方式”
7. 从方法中产生一个新想法
8. 在时间线上看见全部流转记录
9. 将这些内容完整导出为 Markdown + JSON
10. 删除本地数据后，可以使用备份恢复

只要这十步稳定可用，MVP 才算完成。
