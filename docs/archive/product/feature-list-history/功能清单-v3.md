# 个人系统功能清单 v3

> 状态：当前有效产品基线，已同步至 Layout Sprint 2 封板行为。`功能清单-v1.md` 与 `功能清单-v2.md` 保留为历史设计记录；当其与本文件或已验收产品行为冲突时，以本文件为准。

## 一、第一阶段目标

建立稳定、可追溯、可恢复的个人行动闭环：

```text
想法
→ 执行
→ 复盘
→ 形成 / 验证 / 修订方法
→ 用方法发起新行动
→ 搜索定位
→ 周期观察
→ 从仪表盘下钻到具体记录
```

产品原则：

1. 本地优先，不依赖外部服务才能使用。
2. 一件事一条主记录，通过状态迁移而非复制推进。
3. 复盘优先于方法沉淀；默认不沉淀方法，多次真实证据积累后再主动形成或修订方法。
4. 捕获和复盘保持低阻力，字段只保留能推动判断与行动的内容。
5. 核心数据必须完整备份、可靠恢复，不能锁死在系统内。
6. 可视化只服务判断、定位和下一步行动。

## 二、第一阶段有效功能

### 1. 总览与定位

- 系统仪表盘支持 7 天、30 天和全部时间窗口。
- 展示新增事项、进入执行、完成复盘、方法形成、验证、修订和方法发起行动。
- 指标支持下钻到对应事项或方法。
- 展示当前堵塞状态和方法复利信息。

### 2. 想法

- 使用“一句话标题 + 补充说明（可选）”快速捕获。
- 只填写补充说明时，第一行自动成为标题。
- 可进入“想试试”或“以后再说”。
- 页面刷新或重新进入时默认查看“想试试”。

### 3. 执行

- 想法可以开始执行。
- 支持暂停、恢复和放弃。
- 执行完成后进入待复盘。
- 状态迁移写入独立事件日志。

### 4. 复盘

复盘表单包含：

- 结果怎样（唯一默认必填文本）
- 有效 / 舒服（勾选后必填）
- 阻力 / 不舒服（勾选后必填）
- 产生新想法（勾选后必填，完成后自动进入“想试试”）

方法发起的事项进入待复盘时，默认建议“验证已有方法”，并默认选择其来源方法；默认仅验证，不强制修订。用户可以取消建议、切换验证其他方法或选择形成新方法；两项都不选择即不处理方法。取消默认建议后，在当前页面会话内按事项记住该明确操作，浏览器刷新后可重新应用建议。

### 5. 方法

- 复盘时仅提供“形成新方法”与“验证已有方法”两个互斥选择；两项均未选择即不处理方法。
- 对方法来源事项，复盘默认建议验证来源方法；用户可以取消建议或改选其他方法，原方法应用关系不改变。
- 新建和修订表单只包含“具体步骤（必填）+ 补充说明（可选）”。
- 方法名称取具体步骤首行；修订时沿用原方法名称。
- 方法模块采用左侧列表、局部搜索与右侧详情工作台；局部搜索排除当前选择时清空详情选择。
- 方法详情展示来源与验证证据、版本历史；证据关系由结构化读模型提供，包含形成、验证、修订和历史证据。历史关系未知时必须明确显示“关系类型无法从旧数据中确定”，不得推断。
- 可从方法发起新的行动事项，并冻结实际使用的方法版本。

### 6. 搜索、筛选与历史

- 全局搜索事项、复盘、当前方法及方法历史版本。
- 支持状态筛选、回收站和仪表盘下钻定位。
- 事项详情以右侧浮动抽屉按需展示完整状态流转历史；抽屉不进入正文文档流，支持关闭、Esc 关闭及切换事项自动关闭。
- 当前列表默认按更新时间倒序；自定义排序和标签延后到出现真实管理痛点后决定。

### 7. 删除与恢复

- 删除事项进入回收站，保留 30 天。
- 支持从回收站恢复。
- 到期清理同时清理对应关系数据。

### 8. 数据备份与恢复

第一阶段正式数据安全格式为完整 JSON：

- 包含事项、复盘、方法、证据、版本、方法应用、状态事件和来源关系。
- 包含格式版本、应用版本和导出时间。
- 导入前校验格式、版本、唯一 ID、状态和跨表引用。
- 恢复前自动下载当前数据安全备份。
- 安全备份交付失败时禁止覆盖。
- 数据替换在单个 IndexedDB 事务中完成；失败时保留原数据。

Markdown + ZIP 定位为“人类可读导出”，不是灾难恢复格式，不阻塞第一阶段封板。是否实现由实际迁移、离线阅读或外部知识库使用需求触发。

### 9. 工程交付

- Windows 本地 H5 开发可运行。
- TypeScript 类型检查、自动化测试和 H5 构建稳定。
- Docker 镜像可构建和访问。
- SPA 刷新可用，提供健康检查。
- Application / Repository 分层成立，页面不直接操作 Dexie。
- 代码、设计文档和个人运行数据保持 Git 隐私边界。

## 三、第一阶段完成标准

1. 新建想法并选择“想试试”或“以后再说”。
2. 将想法转为执行，支持暂停、恢复和结束。
3. 结束执行后进入待复盘并完成复盘。
4. 复盘可以产生新想法。
5. 复盘可以形成或验证方法；两项均未选择即不处理方法。方法来源事项进入待复盘时默认建议验证来源方法，用户可取消或改选。
6. 方法可以发起新行动，并保留使用版本与来源关系。
7. 可搜索并定位事项、复盘和方法。
8. 可查看单事项完整状态流转历史。
9. 可从仪表盘观察周期事实并下钻到记录。
10. 可导出完整 JSON；恢复前自动保存当前数据，并可从备份可靠恢复。
11. 类型检查、完整测试、H5 构建和 Docker 里程碑验证通过。

完成以上标准后，第一阶段可以封板为 `v0.1.0`。

## 四、第一阶段不做或延后

- 标签体系和自定义排序：有真实数据管理痛点后再评估。
- Markdown、ZIP、manifest 和可读导出报告：作为后续可读导出能力。
- `deviceId` 和云同步预留：进入多设备设计时统一处理。
- AI、附件、提醒、日历、多人协作和复杂权限。
- 关于我、长期方向、年/月/周计划、计划树和关联图。

## 五、第二阶段主线

第二阶段不继续扩张行动表单，而是建立方向层：

```text
关于我 / 长期方向
→ 阶段目标
→ 年月周计划
→ 具体事项
→ 复盘证据
→ 反向校准方向
```

第二阶段必须在第一阶段封板后单独设计，不能直接沿用 v1 的字段假设开发。
