## 【P1 根因】

`packages/storage-mysql/src/exploration-track-repository.ts` 的关联写入没有把“当前关联主线已软删除”视为不可调整的只读历史事实：

```text
assignItemToExplorationTrack()
- 锁定 Item
- 锁定原关联 Track 与目标 Track
- 仅在原 Track 缺失时拒绝 unavailable
- 原 Track 已 deleted 时仍允许改派到 active Track

removeItemFromExplorationTrack()
- 锁定 Item
- 锁定原关联 Track
- 仅在 Track 缺失时拒绝 unavailable
- 原 Track 已 deleted 时仍允许置 NULL
```

这违反已冻结规则：

```text
lifecycle = deleted 的主线仍可只读查看当前投影、历史和已放弃事实；
不返回可创建、改名、删除或关联调整权限。

主线已删除时，关联写入拒绝且零副作用。
```

软删除不应改写既有 Item 关系；也不允许后续通过“移除”或“改派”消除该删除主线所保留的历史关联。`track-deleted` 与 `unavailable` 都是只读解释状态，不是关联调整入口。

### 实施要求

在同一 transaction、Item 锁与 Track 锁已获得后：

```text
assignItemToExplorationTrack()
- 若 Item 原 exploration_track_id 非 NULL 且原 Track 缺失：拒绝 unavailable，零写入；
- 若原 Track 已 deleted：拒绝 deleted，零写入；
- 目标 Track 不存在或已 deleted：拒绝 not-found / deleted，零写入；
- 只有原关联为空或原 Track active，且目标 Track active 时，允许更新关联。

removeItemFromExplorationTrack()
- 原关联为 NULL：按既有无关联语义处理；
- 原 Track 缺失：拒绝 unavailable，零写入；
- 原 Track 已 deleted：拒绝 deleted，零写入；
- 仅原 Track active 时允许置 NULL。
```

不得借由删除 / 改派更新 `items.updated_at`、状态事件、Review、Method、ItemLink 或任意其他事实。异常继续向上抛出，不得伪装为成功、无关联或空读模型。

### 必增真实 MySQL 临时库测试

在既有 S2 集成测试内新增至少：

```text
删除 Track 后：
- getItemContext() 返回 track-deleted 且保留 Track 与 deletedAt；
- assign 同 Item 到 active Track 被拒绝；
- remove 同 Item 的关联被拒绝；
```

测试继续只使用随机临时 database、独立用户与 finally 清理。禁止对运行库关闭外键、手造脏数据或执行 DDL。
