# 探索主线 V1 S1：UAT 004 跨库只读保护快照路径授权

> 日期：2026-07-24
>
> 结论：**授权一次性新增受控只读快照脚本，并由 QA 在停写窗口使用容器内既有 root Unix socket 对 `knowledge_base` 与 `knowledge_base_uat` 获取部署前后快照。未授权修改用户、权限、Compose、端口、运行组合或任何 migration 执行。**
>
> 依据：`docs/product/当前运行事实.md`、`docker-compose.yml`、`docker/mysql/scripts/reconcile-users.sh`、`docs/architecture/探索主线-V1-S1-Schema004总体稳定审阅与UAT部署授权.md`。

## 【裁决】

部署前停止是正确的。现有四个 app / migrator 用户被设计为按 database 最小权限隔离：日常用户只拥有 `knowledge_base` 权限，UAT 用户只拥有 `knowledge_base_uat` 权限。因此，不存在可由 `.env.uat` 提供、同时只读两个业务库的既有业务凭据。

在“不创建用户、不调整权限、不改 Compose / 端口 / 运行组合、不把管理密码写入 Git 或 `.env.uat`”的约束下，唯一可行且最小的路径是：使用**已经在 MySQL 容器内存在的 root 环境变量和 Unix socket**，运行固定只读快照命令。该 root 访问不经过 TCP，不向浏览器、API、业务环境变量或业务备份暴露任何管理凭据。

这是一条部署验证路径，不是运行时能力；它不改变 API、Application、Repository、Contracts、BackupData 或业务数据边界。

## 【本次唯一授权】

允许修改范围：

```text
scripts/uat-schema004-readonly-snapshot.sh
docs/architecture/**
docs/daily-contributions/YYYY-MM-DD.md（脚本完成并完成工程验证后追加）
```

若现有命令可完全满足以下固定输出格式，允许不创建脚本；但优先创建上述单一脚本，避免人工拼接跨库 SQL、误用 `.env` 或遗漏集合。

禁止修改：

```text
.env、.env.uat、任何示例环境文件
migrations/**
packages/**
apps/**
docker-compose.yml
docker/mysql/**
MySQL 用户、密码、GRANT / REVOKE、端口、容器或运行组合
knowledge_base / knowledge_base_uat 的 schema 或业务数据
```

本授权不允许执行 004。快照路径经 QA 复验并确认可用后，才恢复上一份 UAT 004 部署授权的部署步骤。

## 【执行者、凭据与访问边界】

| 事项 | 冻结要求 |
|---|---|
| 执行者 | QA 负责人执行；后端工程师只实现和定向验证脚本，不执行 UAT 004。 |
| 数据库访问端点 | `docker compose exec -T mysql` 容器内 Unix socket `/var/run/mysqld/mysqld.sock`；不得使用 TCP、`127.0.0.1:3306` 或远程地址。 |
| 凭据来源 | 仅 MySQL 容器已注入的 `MYSQL_ROOT_PASSWORD` 环境变量；脚本在容器内短时设置 `MYSQL_PWD` 给 `mysql` / `mysqldump` 子进程。 |
| 凭据落盘 | 禁止写入 Git、`.env`、`.env.uat`、脚本输出、日志、错误 DTO、业务 JSON 备份或快照文件。 |
| 凭据显示 | 禁止 `set -x`、`docker inspect`、打印环境变量、命令回显密码、将容器环境导出到宿主机。 |
| 撤销 | 不创建临时用户、不授予新权限、不复制凭据，因此无 GRANT / 用户撤销动作。每次命令结束后子进程环境自动结束；脚本不得在宿主机导出 `MYSQL_PWD`。 |
| 快照权限 | 脚本中只能执行 `SELECT`、`SHOW`、`information_schema` 查询与只读 `mysqldump`；不得包含 migration、DDL、DML、`SET GLOBAL`、`LOCK TABLES`、`FLUSH`、恢复或清理命令。 |

注意：root 账户的数据库能力高于只读，但本路径通过**容器 Unix socket、固定脚本、最小 SQL 白名单、停写窗口、QA 执行与前后哈希核验**约束其实际操作为只读。没有新增或扩张 root 权限。

## 【快照脚本冻结输入与输出】

脚本接口固定为：

```text
scripts/uat-schema004-readonly-snapshot.sh <knowledge_base|knowledge_base_uat> <output-directory>
```

- 只接受精确的 `knowledge_base` 或 `knowledge_base_uat`，其他参数立即拒绝。
- `output-directory` 必须由 QA 在项目外的受限临时目录创建；脚本拒绝 project root、Git 工作树、`.env` 所在目录或空路径。
- 输出目录创建后权限必须仅限当前本机用户；不得提交、复制到共享路径或作为测试产物上传。
- 输出文件不得包含密码、连接字符串、host / port、用户名或容器环境。

每个 database 输出三个固定工件：

```text
schema.tsv
records.sql
manifest.sha256
```

### `schema.tsv`

必须通过 `information_schema` 以稳定排序导出：

```text
schema_migrations 的 version / name / checksum / applied_at
exploration_tracks、items 的相关列定义
exploration_tracks 与 items 的全部索引定义
items_exploration_track_fk 外键定义
```

对于 004 部署前后，需要能明确辨识：表、列、三个索引、外键与 migration record 的变化；不得只记录 schemaVersion 数字。

### `records.sql`

必须包含以下表的完整稳定排序记录，使用只读 `mysqldump` 或等价固定 SELECT 导出：

```text
schema_migrations
exploration_tracks
items
reviews
methods
method_versions
method_evidence
method_applications
method_tombstones
item_links
item_status_events
system_metadata
```

冻结排序原则：按每表主键；复合 / 无主键表按完整稳定业务键或全部列固定顺序。推荐使用只读 `mysqldump`：

```text
--no-create-info
--skip-comments
--skip-dump-date
--compact
--skip-extended-insert
--order-by-primary
--single-transaction
```

若 `system_metadata` 或任一表不存在 / 无主键，脚本必须使用确定的显式 `SELECT ... ORDER BY ...` 输出，不能依赖自然行序。`records.sql` 是本机临时受限证据，不得进入 Git。

### `manifest.sha256`

必须至少记录：

```text
目标 database 名称（不含 host / port / user）
schema.tsv 的 SHA-256
records.sql 的 SHA-256
每个冻结表独立的记录行数与 SHA-256
```

禁止把 `MYSQL_PWD`、root 密码、连接参数、SQL 错误原文或业务备份正文写入 manifest。

## 【快照与比较操作】

QA 在停写窗口按以下顺序执行；脚本运行本身不授予 004 migration：

```text
1. 停止 H5 / API，确认 10086 / 32146 无监听。
2. 确认无 UAT、migration、restore、清库、自动化 suite 或人工业务写入并行。
3. 在项目外创建仅当前用户可读写的临时目录，例如系统临时目录下的随机目录；不使用 Git 工作树。
4. 对 knowledge_base 执行前快照。
5. 对 knowledge_base_uat 执行前快照。
6. 比较并记录两个 manifest；此时不执行 004。
7. 仅在本路径已通过 QA 定向验证、且上一份 UAT 部署授权所有前置仍满足时，执行受控 004。
8. 对两个 database 分别执行后快照。
9. 比较：
   - knowledge_base：schema.tsv、records.sql、各表行数与哈希必须完全相同；
   - knowledge_base_uat：十个既有业务集合与 system_metadata 的记录哈希必须完全相同；
     仅允许 schema_migrations 新增 004，以及 004 所定义的 exploration_tracks 空表、items 新列 / 索引 / 外键的 schema.tsv 差异。
10. QA 将 manifest、比较结论和不含数据正文的命令结果纳入验收报告；完整 records.sql 保留到 QA 与架构签字后立即从受限临时目录安全删除。
```

在完整快照删除前，必须保留两个 manifest SHA-256 和比较结论；它们只证明内容一致性，不承载业务恢复能力，也不得替代 JSON BackupData。

## 【脚本最小自动化验证】

后端工程师只需在随机临时 database 中验证脚本：

```text
- 可对两个允许 database 名称分别执行固定只读查询；
- 非法 database 参数拒绝；
- 工作树 / 空输出目录拒绝；
- 输出不含 MYSQL_ROOT_PASSWORD、MYSQL_PWD、root 用户名、host、port 或连接字符串；
- 对同一静止临时库连续执行两次，manifest 与记录哈希一致；
- 尝试在脚本路径注入 DDL / DML 不存在；通过审阅确认仅包含 SELECT / SHOW / information_schema / mysqldump；
- 脚本执行前后临时库业务表快照一致。
```

脚本不是 API，不得新增 HTTP endpoint、DTO、前端入口或业务 Contract。
