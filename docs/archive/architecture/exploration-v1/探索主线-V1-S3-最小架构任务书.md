# 探索主线 V1 S3：最小架构任务书

> 日期：2026-07-25
> 责任岗：架构师
> 状态：**架构冻结待产品书面授权；本文不构成编码授权。**

## 1. 技术结论与状态锚点

**技术结论：有条件可行。**S3 只把 S1/S2 已封板的探索主线能力接入 MySQL 运行闭环，不新增任何业务语义、Schema 或 migration。

唯一运行事实以 `docs/product/当前运行事实.md` 为准：H5 `127.0.0.1:10086` → loopback API `127.0.0.1:32146` → Application → MySQL。当前 API 会话实际连接 `knowledge_base_uat`、`schemaVersion: 4`；日常运行须停止旧 API、显式加载 `.env` 并以 `/health` 确认 `knowledge_base`。任何运行时操作不得按端口或历史记录猜测目标库。

## 2. 可复用能力与不可改变的不变量

复用已封板的 Schema 004、Contracts、`ExplorationTrackRepository`、MySQL Backup Repository、Application 原子工作流和既有 API/H5 基础设施。API 路由矩阵、DTO、稳定排序和错误语义以 `探索主线-V1-API路由矩阵与DTO补充冻结.md` 为唯一契约来源。

以下不变量不得修改或重新解释：

- 一个 Item 仅可关联 0 或 1 条 Track；只接受用户明确操作，禁止任何推断或自动关联。
- Track 仅创建、改名、软删除、恢复；删除不改写 Item、Review、Method、ItemLink、Event 或既有事实。
- `track-deleted` 与 `unavailable` 必须诚实展示；后者保留原 `trackId`，调整/移除稳定拒绝且零副作用。
- `createItemWithExplorationTrack()` 的 existing/new 路径保持单一 MySQL transaction；无幂等键、无自动写入重试。
- 不允许 IndexedDB/MySQL 双写、同步、回填、fallback 或合并展示；浏览器不得直连 MySQL。

## 3. 实施切片及顺序

所有切片须按顺序验收；切片 1 未通过，不得开始后续切片。数据 / Application / Repository 与 API 的实现由同一后端责任范围承接；H5 仅在 API 契约测试通过后开始。

### 切片 0：授权前只读基线

- 读取当前 `/health` 并记录实际 `database`、`schemaVersion`；不写入。
- 确认 004 已在两个运行库存在且为 Schema 4；禁止执行 DDL 回退、删除 migration record 或手工修表。
- 固化当前 API 契约、H5 fixture 接入点与 QA 测试矩阵；发现与唯一运行事实冲突立即停止并转产品裁决。

验收：产品确认目标切片、禁止项、验收门和写入职责；本切片不产生业务代码。

### 切片 1：Backup V3（后端）

- 新增 `BackupDocumentV3` / `BackupDataV3` 的 Contracts 与 MySQL Backup 映射，仅增加 `explorationTracks` 这一第十业务集合。
- V1/V2 导入将 Track 集合与 Item 的 `explorationTrackId` 归一为空：不失败、不猜测、不生成关联。
- V3 导出保留 Track、`deletedAt` 与 Item 关联；导入在任何业务集合写入前完整校验 ID、名称、规范名、时间、全生命周期唯一名、既有九集合及 Item 引用。
- 任一不可信输入（含断裂引用）整体拒绝，十个业务集合零写入；`replaceData()` 在单一 MySQL DML transaction 中完成清理、导入及末端失败整体回滚。
- `system_metadata` 永不导出、清理、恢复或覆盖。

验收：V1/V2 降级、V3 导出/恢复等价、非法 V3 预写入拒绝、末端故障回滚及 metadata 隔离均由随机临时数据库集成测试证明。

### 切片 2：冻结 API 与 HTTP 契约（后端）

- 仅实现产品范围冻结所列的 Track、Item 关联及受限 `GET /api/v1/items?status=&explorationTrackId=` 路由；不新增路由、筛选、计数、分页总数或管理能力。
- API handler 只负责 decode、请求限制、DTO 映射、Application 调用、统一错误与 `requestId`；不得访问 pool、SQL 或 Repository，不得自行加锁或拼事务。
- 普通 JSON body 最大 64 KiB；既有 Backup restore 16 MiB 限制延续至 V3。响应保持 JSON UTF-8、`Cache-Control: no-store`、`X-Request-Id`。
- 映射固定为 400 `VALIDATION_FAILED`、404 `NOT_FOUND`、409 `CONFLICT`、503 `MYSQL_SCHEMA_NOT_READY`/`MYSQL_UNAVAILABLE`、500 `INTERNAL_ERROR`，并保留 413/415/405/`NOT_FOUND_ROUTE`。所有失败脱敏且包含 `requestId`。
- API 只调用已封板 Application 能力；读模型、稳定排序、deleted/unavailable 语义和 `POST /items` 的可选 `explorationTrack` selection 必须逐项符合冻结矩阵。

验收：真实 MySQL 临时库上的路由、DTO、排序、body/query 边界、所有错误码、脱敏与无额外路由回归通过。

### 切片 3：H5 API Client / Adapter 真实接入（前端）

- 在 `apps/client` 内以 API Client / Adapter 替换探索主线 fixture；页面和组件不得操作 MySQL、Repository、IndexedDB、SQLite、localStorage 或其他浏览器持久化。
- 逐项按冻结设计解除控件禁用：真实 loading、空态、读取/业务错误、已删除只读、unavailable 只读和稳定拒绝；所有关联事实只显示 API 结构化读模型。
- 快速捕获的新 Track 名称只留在草稿，且只随 `POST /items` 提交；取消选择或取消提交零写入，禁止拆为创建 Track 后再关联。
- 通过 AbortController / 请求序号或等价机制取消过期读取；旧请求、默认值、列表刷新不得覆盖当前草稿或用户明确 selection。
- 补充说明维持已冻结的初始单行、最多两行、超出省略号规则；不改变字段语义。

验收：fixture 不再参与探索主线真实读写；浏览器 Network 仅见 loopback API、无 IndexedDB fallback；设计状态与小屏回归通过。

### 切片 4：unknown-outcome 端到端保护（前后端联合）

- 所有 Track 写入、关联写入及扩展 `POST /items` 在超时、断线、页面关闭或响应丢失后均进入 unknown-outcome。
- 前端保留输入和 selection，不伪造成功/失败、不自动重发；只允许重新读取冻结 API 以确认真实状态。
- API 不新增幂等键、结果查询、后台补偿写入或客户端重试语义；MySQL 不可用须诚实返回 503，绝不降级为空列表或无关联。

验收：通过可控超时/断线和 MySQL 不可用测试，证明草稿保留、无重复写入、无本地成功推断，并可在服务恢复后以真实读取确认。

### 切片 5：QA 浏览器 UAT、架构复审与产品验收

- QA 在显式 `.env.uat` 环境、`/health` 确认 `database=knowledge_base_uat` 后执行浏览器 UAT；日常 `knowledge_base` 只做前后快照/等价稳定证据，不得被触及。
- 覆盖生命周期、existing/new 原子捕获和取消零写入、关联调整/移除、deleted/unavailable、详情历史/定位、V1/V2/V3 备份、unknown-outcome、MySQL 不可用、无 IndexedDB fallback、桌面/小屏及两行截断。
- QA 输出隔离证据、缺陷分级和回归结论；架构师复核契约、数据边界和禁止项；产品经理据此验收、归档与封板。

## 7. 运行库隔离与风险保护

- 日常：仅显式 `.env`，目标 `knowledge_base`；UAT：仅显式 `.env.uat`，目标 `knowledge_base_uat`。每个 API 进程只连接一个库。
- 实施、迁移、恢复、UAT 或破坏性操作前后均请求 `/health` 并记录 database/schemaVersion；当前会话处于 UAT 时，不得将结果称为日常运行验证。
- 禁止删除 `mysql-data`、执行 DDL 回退、`git clean -fdx` 或 `git reset --hard`。
- API 仅监听 loopback；H5 仅通过 `/api` 调 API，浏览器不获得数据库凭据。
