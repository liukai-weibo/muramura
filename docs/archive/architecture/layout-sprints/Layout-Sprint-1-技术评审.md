## 一、评审结论

Layout Sprint 1 技术方案可行，不需要新增后端能力，也不需要调整现有业务架构。

本轮应被限定为一次客户端表现层重组：

```text
现有单页 React 状态与业务处理函数
→ 增加应用外壳
→ 增加四个一级模块容器
→ 将现有功能区块归位
→ 统一搜索和仪表盘的跨模块定位
```

推荐继续采用：

- 单个 Taro 页面；
- React `useState`；
- 当前页面作为状态协调容器；
- 现有 Application Service；
- 现有 IndexedDB Repository；
- 不引入 React Router；
- 不引入 Redux、Zustand 等全局状态库；
- 不拆分为多个 Taro 页面；
- 不新增导航状态持久化；
- 不修改任何持久化业务数据。

本轮唯一需要新增的核心页面概念是：

```ts

```

以及一组页面内部的统一跨模块定位操作。

## 二、技术原则

Layout Sprint 1 的技术原则是：

> 拆分 JSX，不重写业务流程；提取模块容器，不重新设计 Application 层。

本轮只处理：

- 应用外壳；
- 一级导航；
- 顶部全局栏；
- 四个模块容器；
- 现有功能归位；
- 跨模块定位；
- 页面上下文和未提交草稿保留。

本轮不处理：

- 业务状态机调整；
- 复盘和方法规则调整；
- 方法列表—详情重构；
- 完整搜索浮层；
- 完整快速捕获折叠面板；
- 最终响应式布局；
- 路由体系；
- 全局状态管理体系；
- 新业务实体和持久化结构。

## 三、页面和组件拆分方案

### 3.1 总体结构

推荐维持一个页面入口：

```text
IndexPage
├── Application Services 装配
├── 页面级业务数据
├── 页面级交互状态
├── 跨模块定位协调
└── AppShell
    ├── PrimaryNavigation
    ├── GlobalHeader
    └── ModuleContent
        ├── ActionsModule
        ├── MethodsModule
        ├── InsightsModule
        └── SettingsModule
```

### 3.2 `IndexPage`

继续作为页面级协调器，负责：

- 创建并持有 Application Service；
- 初始化和关闭 IndexedDB；
- 加载事项、回收站和方法数据；
- 持有四个模块共享的状态；
- 执行业务操作；
- 执行跨模块定位；
- 统一处理刷新、操作中状态和消息反馈。

本轮不建议将所有状态立即改写为多个 Hook、Reducer 或全局 Store，否则会把“布局重组”扩大为“状态架构重构”。

### 3.3 `AppShell`

负责：

- 左侧一级导航；
- 顶部全局栏；
- 主内容区域；
- 桌面端应用骨架；
- 当前模块内容插槽。

不负责：

- 查询业务数据；
- 修改状态机；
- 调用 Repository；
- 处理复盘或备份业务。

### 3.4 `PrimaryNavigation`

负责：

- 展示行动、方法、观察、数据与设置；
- 展示当前模块选中状态；
- 将数据与设置和三个业务模块视觉分组；
- 展示简洁的本地数据状态；
- 触发一级模块切换。

一级导航不自行修改事项筛选、当前选择或任何业务数据。

### 3.5 `GlobalHeader`

负责：

- 当前模块标题；
- 全局搜索入口；
- 快速捕获入口。

Layout Sprint 1 允许继续复用现有搜索结果和捕获表单，不要求提前完成 Layout Sprint 3 的搜索浮层和折叠捕获。

搜索词和捕获草稿继续由 `IndexPage` 持有，防止模块切换造成输入丢失。

### 3.6 `ActionsModule`

承载现有：

- 状态筛选；
- 有效事项和回收站切换；
- 事项列表与分页；
- 事项详情；
- 状态操作；
- 方法应用上下文；
- 状态时间线；
- 复盘工作区；
- 删除与恢复。

本轮不修改状态操作、复盘字段、方法沉淀、删除和回收站规则。

### 3.7 `MethodsModule`

承载现有：

- 方法卡片；
- 方法版本历史；
- 来源复盘证据；
- 用方法发起行动；
- 方法行动草稿。

本轮继续沿用当前方法卡片，不提前实现 Layout Sprint 2 的方法列表—详情工作台。

### 3.8 `InsightsModule`

承载现有：

- 7 天、30 天和全部时间窗口；
- 七类运行指标；
- 堵塞状态；
- 方法复利；
- 事实提示；
- 指标下钻。

原来的折叠仪表盘进入观察模块后默认展示。统计算法和 `DashboardApplicationService` 保持不变。

### 3.9 `SettingsModule`

承载现有：

- 当前事项、方法和回收站数量；
- 完整 JSON 导出；
- 备份文件选择和校验；
- 恢复前安全备份；
- 恢复确认；
- 恢复结果和错误信息。

`pendingBackup`、恢复消息和操作中状态必须由页面上层持有，不能因模块条件卸载而丢失。

### 3.10 推荐拆分粒度

本轮建议拆出：

```text
AppShell
PrimaryNavigation
GlobalHeader
ActionsModule
MethodsModule
InsightsModule
SettingsModule
```

如果四个模块提取后需要传递大量 Props，可以暂时保留为 `IndexPage` 内部渲染函数：

```ts
renderActionsModule()
renderMethodsModule()
renderInsightsModule()
renderSettingsModule()
```

不应为了形式上的组件拆分引入 Context 或全局 Store。

本轮不建议进一步建设：

- 通用跨项目 UI 组件库；
- Repository Hook；
- 路由控制器；
- 页面级领域状态容器；
- 每个小字段一个组件的过度拆分。

## 四、一级导航状态管理方案

### 4.1 页面状态

在当前页面内部增加：

```ts
type PrimaryModule = 'actions' | 'methods' | 'insights' | 'settings'
```

默认状态：

```text
activeModule = actions
filter = idea_to_try
```

这符合首次进入行动模块、默认查看“想试试”的现有产品规则。

### 4.2 不持久化导航状态

本轮不将一级导航写入：

- `localStorage`；
- IndexedDB；
- URL 查询参数；
- 路由参数。

页面刷新后继续默认进入行动模块和“想试试”。导航状态不属于正式业务数据。

### 4.3 手动切换原则

手动切换一级模块时，只修改 `activeModule`，不得顺带重置：

- 行动筛选；
- 回收站状态；
- 当前页码；
- 当前选中事项；
- 方法历史展开状态；
- 仪表盘窗口；
- 仪表盘下钻状态；
- 搜索词；
- 快速捕获草稿；
- 复盘草稿；
- 方法行动草稿；
- 待恢复备份。

统一规则：

```text
手动切换模块
→ 只改变当前可见模块
→ 不改变模块内部上下文
```

### 4.4 不引入复杂状态管理

本轮继续使用现有 `useState`。

不建议引入：

- React Router；
- Redux；
- Zustand；
- Context 全局状态；
- 页面级状态机；
- IndexedDB 导航草稿。

如果 Layout Sprint 2 完成后状态协调确实出现持续性问题，再单独评估 Reducer 或页面控制器 Hook，不在本轮预埋。

## 五、搜索和仪表盘的跨模块定位方案

### 5.1 总体原则

当前定位部分依赖 `scrollIntoView`。四模块结构下，目标模块可能尚未渲染，因此不能只执行页面滚动。

统一定位顺序应为：

```text
切换目标模块
→ 修正目标模块上下文
→ 设置目标 ID
→ 等待目标模块渲染
→ 必要时执行模块内部滚动或聚焦
```

可以使用统一目标类型：

```ts
type NavigationTarget =
  | { type: 'item'; itemId: string }
  | { type: 'review'; itemId: string }
  | { type: 'method'; methodId: string; methodVersion?: number }
  | { type: 'backlog'; status: ItemStatus }
```

也可以保留四个清晰函数：

```ts
locateItem(itemId)
locateReview(itemId)
locateMethod(methodId, version?)
locateBacklog(status)
```

搜索和仪表盘必须复用同一组定位逻辑，避免行为漂移。

### 5.2 定位事项

流程：

```text
验证目标事项仍存在
→ activeModule = actions
→ showTrash = false
→ 清除不兼容筛选
→ 将分页调整到目标所在页
→ selectedId = itemId
→ 展示事项详情
```

不能固定将分页设为第一页，否则目标事项可能已被选中，但不在当前列表页中。

目标不存在时：

- 清空无效选择；
- 进入行动模块；
- 显示“目标记录不存在或已删除”；
- 不继续展示上一次选中的详情。

### 5.3 定位复盘

搜索结果已包含来源事项 ID，无需新增后端或 Application 接口。

流程：

```text
activeModule = actions
→ 退出回收站
→ 清除不兼容筛选
→ 选中所属事项
→ 调整到事项所在页
→ 等待复盘数据加载
→ 显示或定位复盘区域
```

定位复盘只负责展示，不修改复盘内容，也不重新打开已完成复盘的编辑状态。

### 5.4 定位方法

流程：

```text
确认方法仍存在
→ activeModule = methods
→ 设置目标方法 ID
→ 方法模块渲染
→ 定位目标方法卡片
→ 如命中历史版本，加载并展开版本历史
```

现有方法历史、来源复盘加载和方法 DOM 标识可以直接复用。

建议使用一次性的待定位目标和模块渲染后的 `useEffect` 完成滚动，避免在多个入口散落不同的 `setTimeout`。

### 5.5 定位堵塞状态

流程：

```text
activeModule = actions
→ showTrash = false
→ filter = targetStatus
→ currentPage = 1
→ selectedId = undefined
→ 展示对应状态事项
```

目标是状态集合，因此清空具体事项选择是合理行为。

### 5.6 用方法发起行动后的定位

创建成功后应：

```text
activeModule = actions
→ showTrash = false
→ filter = undefined
→ 刷新数据
→ 选中新事项
→ 定位到新事项所在页
```

否则可能出现数据已经创建，但用户仍停留在方法模块而无法看到结果。

### 5.7 快速捕获后的定位

建议维持当前“创建后进入新事项上下文”的反馈：

```text
创建成功
→ 清空捕获草稿
→ activeModule = actions
→ showTrash = false
→ filter = undefined
→ 选中新事项
```

如果产品希望在方法或观察模块捕获后停留原模块，需要另行明确；本技术方案默认沿用当前创建后定位新事项的行为。

## 六、未提交表单和模块上下文保留方案

### 6.1 核心方案

所有未提交表单继续由 `IndexPage` 持有，模块组件只接收值和事件处理函数。

```text
状态上提到 IndexPage
→ 模块切换时不清空
→ 仅在提交成功或明确取消时清空
→ 页面刷新后允许恢复默认状态
```

本轮不增加：

- IndexedDB 草稿表；
- `localStorage` 草稿；
- Session Storage；
- 自动保存；
- 草稿版本管理；
- 页面刷新后的草稿恢复。

### 6.2 快速捕获草稿

保留：

- 标题；
- 补充说明。

只在创建成功或用户明确取消时清空，不能因一级模块切换清空。

### 6.3 复盘草稿

保留：

- 复盘表单内容；
- 是否产生新想法；
- 方法处理模式；
- 选中的已有方法；
- 是否修订；
- 方法表单；
- 当前校验错误。

现有代码在事项选择变化时重置部分复盘状态可以继续保留，但一级模块切换不得修改当前事项 ID。

### 6.4 方法行动草稿

保留：

- 当前展开行动表单的方法 ID；
- 行动标题；
- 行动补充说明。

只在创建成功、用户关闭表单或明确取消时清空。

### 6.5 观察上下文

保留：

- 仪表盘时间窗口；
- 当前下钻指标；
- 当前报告。

重新进入观察模块时可以刷新数据，但不自动重置窗口和下钻选择。

### 6.6 备份恢复上下文

保留：

- 已校验的待恢复备份；
- 恢复提示和错误信息。

只选择并校验备份时，可以允许切换模块，但不得清空待恢复文件。

恢复操作已经开始后：

- 禁止重复提交；
- 建议临时禁用一级导航；
- 保持恢复进度可见；
- 成功后刷新所有模块数据；
- 失败后保留明确错误。

## 九、重点回归风险

### P0：跨模块定位只切模块、不显示目标

必须同时处理：

- 目标模块；
- 回收站状态；
- 当前筛选；
- 当前页码；
- 目标 ID；
- 目标是否存在。

不能出现目标已经选中，但被筛选或分页隐藏。

### P0：模块切换导致复盘或捕获草稿丢失

常见原因：

- 草稿状态下放到条件渲染模块；
- 模块卸载时重新初始化；
- 导航切换误调用表单重置。

保护原则：

```text
普通模块切换只修改 activeModule
```

### P0：恢复确认或恢复操作被模块切换绕过

必须保证：

- 待恢复备份不因切换丢失；
- 恢复开始后不能重复提交；
- 安全备份失败仍禁止覆盖；
- 恢复完成后四个模块读取一致数据。

### P0：拆组件时复制业务逻辑

以下逻辑必须保持单一实现：

- 数据刷新；
- 操作中控制；
- 搜索；
- 状态迁移；
- 复盘提交；
- 方法历史加载；
- 备份恢复。

### P0：搜索和仪表盘使用不同定位规则

搜索与仪表盘必须复用统一定位函数，不能各自维护筛选、分页和选中规则。

### P1：仪表盘移动后不再自动刷新

必须验证：

- 首次进入观察可读取报告；
- 切换时间窗口可刷新；
- 业务数据变化后重新进入观察可看到最新数据；
- 不因普通渲染产生重复请求。

### P1：方法定位时目标尚未渲染

模块切换后需要等待 React 完成渲染，再执行滚动或聚焦。建议使用一次性待定位目标和 `useEffect`，不要散落不同延时值。

### P1：创建成功后用户看不到新事项

快速捕获或用方法发起行动成功后，应进入行动模块并选中新事项。

### P1：数据库或 Application Service 被重复装配

服务装配和数据库生命周期继续留在 `IndexPage`，不能在四个模块中分别创建数据库和服务实例。

### P2：四个模块同时挂载并仅用 CSS 隐藏

不建议所有模块长期同时挂载，因为可能造成：

- 隐藏内容参与焦点顺序；
- Effect 重复执行；
- DOM 体积扩大；
- 目标滚动混乱。

推荐只渲染当前模块，并将需要保留的状态上提到 `IndexPage`。

### P2：范围滑入 Layout Sprint 2 或 3

本轮不得顺手加入：

- 方法完整列表—详情；
- 复杂搜索浮层；
- 最终捕获折叠体验；
- 完整移动端导航；
- 复杂路由；
- 全局状态库；
- 新视觉系统。

## 十一、底层架构影响评估

### 结论：均不触碰

| 层级 | 是否修改 | 说明 |
|---|---:|---|
| Domain | 否 | 状态机和业务规则不变 |
| Contracts | 否 | 现有实体和接口足够 |
| Application | 否 | 现有用例全部复用 |
| Repository | 否 | 不需要新增查询或写入能力 |
| IndexedDB Schema | 否 | 没有新实体和字段 |
| IndexedDB Migration | 否 | Schema 不变 |
| JSON 备份格式 | 否 | 数据语义和数据集合不变 |
| Docker | 否 | 构建与部署形态不变 |
| 后端服务 | 否 | 当前仍为本地优先 H5 |
| AI 能力层 | 否 | 不属于本轮 |

本轮新增的模块类型、定位目标和 UI 组件 Props 都属于客户端临时交互状态，不进入 `packages/contracts`。

## 十二、技术裁决

Layout Sprint 1 采用：

```text
单个 Taro 页面
+ 现有 React useState
+ 页面级 Application Service 装配
+ 四个模块展示组件
+ 统一跨模块定位函数
+ 草稿状态上提
+ 条件渲染当前模块
```

明确不采用：

```text
React Router
Redux / Zustand
Taro 多页面改造
Context 全局状态
IndexedDB 草稿表
URL 导航状态持久化
Domain 或 Application 改造
新的后端接口
```

## 十三、产品评审待确认项

技术侧没有阻塞项。产品经理只需重点确认以下交互结论：

1. 在方法、观察或设置模块使用快速捕获后，是否接受自动进入行动模块并选中新事项；技术侧建议接受，以维持明确的创建反馈。
2. 已选择并校验备份、但尚未开始恢复时，是否允许切换其他模块；技术侧建议允许，但保留待恢复状态。
3. 搜索命中复盘时，是否只需定位到所属事项的复盘区域；技术侧建议本轮不增加独立复盘路由。
4. 仪表盘下钻记录同时包含事项和方法目标时，应由产品明确该指标的主定位对象，避免点击行为不确定。

以上确认后，Layout Sprint 1 可以直接交 UI 会话按本评审边界实施。

## 十四、实施中需要返回架构评审的条件

出现以下任一情况，应暂停并返回总体架构会话：

1. 现有 Application Service 无法提供 PRD 必需数据；
2. 必须修改 `packages/contracts` 才能完成定位；
3. 需要新增持久化草稿；
4. 需要修改备份恢复流程；
5. 需要引入路由或全局状态库；
6. 跨模块定位存在新的产品歧义；
7. 实施范围开始进入 Layout Sprint 2 或 Layout Sprint 3；
8. 需要修改 Domain、Repository 或 IndexedDB Schema。
