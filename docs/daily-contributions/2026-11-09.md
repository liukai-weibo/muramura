# 每日贡献 2026-11-09

## 增加项

1. 新增睡眠记录：每天一条「当天起床 + 当晚入睡」，两个时间可以只记其中一个；可切换日期补录任意一天。入睡按「与当天起床的先后」自动落日期：晚于起床记当天，早于起床自动记为次日凌晨；没有起床记录时一律记当天。跨天顺序链 `bed(D) < wake(D+1)` 在应用层与备份校验中强制，次日起床早于前晚入睡会提示「今天 06:00 才睡，起床要晚于 06:00」。
2. 新增睡眠折线图（手记文本视图右栏）：横轴按「夜」，纵轴 18:00 → 次日 12:00 自上而下；入睡点在上、起床点在下，00:00 用低对比虚线分界；缺起床画空心圆、缺前一晚入睡画空心方点，支持 7/14/30 夜切换。
3. 新增打开应用时的补记提醒：只在设置的时间段内、且当天还没有起床记录时弹一次；填过或关闭后写 `last_prompted_date`，当天与其它设备都不再弹。
4. 新增睡眠设置：提醒开关、提醒时间段、整点 / 精确到分钟两档输入精度，按用户存服务端。

## 决策

1. **一条记录只描述一天**：`sleep_date=D` 表示 D 早起床 + D 晚入睡，单条记录不再跨天；「一夜」= `bed(D) + wake(D+1)`，只在图表和摘要里拼接，标为 D 日的睡眠。
2. **跨天顺序链**：`wake(D) < bed(D) < wake(D+1)` 必须成立。入睡日期由它与当天起床的先后推导，不再用 12 点分界；次日起床早于前晚入睡直接拒绝，不做自动顺延。
3. 睡眠数据单独建表，不从手记正文推导；手记时间只作为弹窗里的「用手记时间填入」建议，用户确认后才落库。
4. 提醒只在打开应用/网页时判定，不做服务端定时推送；只催起床，晚上不催入睡。
5. 整点模式载入含分钟的记录时保留原分钟，只有用户主动改小时才归零，避免静默改写历史精确记录。

## 验证

1. 单元测试 58 例通过：日期顺序规则、按夜取数、纵轴翻转与 00:00 分界、提醒判定、合并写入、备份 V12→V13 转换与跨天校验。
2. MySQL 集成测试 4 例通过：只记起床再补入睡、越权隔离、设置与 ack、备份往返。
3. 顺序链实测：入睡 06:00 + 起床 07:00 显示「次日 06:00」，起床改成 05:00 后变回「当天 06:00」；前晚 06:00 入睡时起床 00–06 置灰、提示「昨天 06:00 才睡」，强行保存返回 400 且消息带时间；次日 05:30 起床可保存，04:59 被拒。
4. 真实 HTTP 冒烟：`PUT` 合并语义（缺省保留 / null 清除 / 双空删除）与非法时间 400；备份导出为 V13。
5. 无头浏览器实测：卡片摘要 `23:40 → 07:30 · 7h50m`、入睡点位于起床点上方、00:00 分界线存在、弹窗日期切换与双区块录入、整点模式保存不改分钟。
