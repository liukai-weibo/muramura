## 修复项
1. Caddy 首次启动因 `/var/log/caddy` 属主为 root 而无法写访问日志，改为 `caddy:caddy` 后启动正常。
2. 会话 Cookie 在 HTTPS 下缺少 `Secure` 标志：`apps/api/src/hono/session.ts` 新增 `isSecureRequest`，按 `X-Forwarded-Proto`（无该头时回落请求 URL 协议）决定是否添加 `Secure`，`auth.ts` 与 `account.ts` 三处 Cookie 构造点同步；新增 `tests/session-cookie.test.ts` 17 个用例。
3. Caddy 配置 `header_up X-Real-IP` 会替换默认转发头集合，导致 `X-Forwarded-Proto` 不再下发，改为显式设置 `X-Forwarded-Proto`/`X-Forwarded-For`/`X-Forwarded-Host`。
4. 容器内 nginx 以 `X-Forwarded-Proto $scheme` 覆盖了 Caddy 传来的 `https`（Caddy 到 nginx 之间为明文 HTTP），改为优先透传上游值、无上游时回落 `$scheme`。
5. 桌面端检查更新报「无法获取最新版本」：`updater.json` 以 PowerShell `Set-Content -Encoding UTF8` 写入时带上了 UTF-8 BOM（`EF BB BF`），Tauri 更新器解析该清单时直接失败；改为以 `.NET UTF8Encoding($false)` 写入无 BOM 文件。同时实测 gh-proxy 对 `raw.githubusercontent.com/.../main/updater.json` 这一缓存条目曾返回额外 3 字节 BOM（1170 字节 vs 源文件 1167 字节），改用 `refs/heads/main` 路径形式可绕过该缓存条目。
