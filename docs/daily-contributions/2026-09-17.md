## 修复项
1. `deploy/backup-db.sh` 的行数统计 SQL 未加库名前缀，MySQL 以 `No database selected` 失败并返回空值，被当成 0 后与同样为 0 的恢复结果“比对通过”。已改为带库名前缀，且返回值非数字时直接报错退出，不再静默降级为 0。
2. `deploy/backup-db.sh` 生成 `.sha256` 时写入绝对路径，导致备份文件下载到其他机器后 `sha256sum -c` 全部失败。已改为只写文件名。
3. `.github/workflows/fetch-backup.yml` 用 `knowledge_base_*.sql.gz` 取最新备份，该通配符会匹配到 `knowledge_base_uat_*.sql.gz`，导致打包到 UAT 空白库。已改为用文件名正则精确匹配主库。
4. `deploy/backup-db.sh` 中 `docker compose ps -q` 在缺少对应服务时以非零码退出，配合 `set -e` 中断整个备份。已用 `|| true` 兜底。
5. 云端入口地址以硬编码形式散落在四处，迁机后旧地址全部失效：`apps/api/src/hono/http.ts` 的 API CORS 白名单、`apps/client/.env.production` 的 `TARO_APP_API_BASE_URL`、`tests/api-m5b.integration.test.ts` 的 CORS 断言、`docs/product/当前运行事实.md` 的运行事实记录。已统一改为 `http://47.116.6.111:10086`。
6. 新服务器首次启动时运行的仍是迁移前构建的镜像，其 CORS 白名单只含旧地址，导致新服务器自身 H5 来源 `http://47.116.6.111:10086` 被返回 403（H5 同源写请求会携带 Origin）。重新构建并部署镜像后实测：新来源返回 200，旧来源返回 403，`tauri://localhost` 与 `http://tauri.localhost` 仍返回 200。
