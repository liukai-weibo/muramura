# 2026-09-17 每日贡献记录

## 增加项
1. 新增 `deploy/start.sh`：将原先仅存在于云服务器 `/root/start.sh` 的部署脚本纳入仓库版本管理，脚本内容未作改动，并在 Git 中标记为可执行（100755）。脚本以 `BASH_SOURCE` 推断自身目录，不依赖固定绝对路径。
2. 新增 `deploy/.env.example`：云服务器私有环境配置模板，覆盖 `docker-compose.yml` 中全部强制与可选变量，占位符统一为 `replace-with-*`，不含真实凭据。
3. 新增 `deploy/README.md`：记录服务器目录布局、新服务器首次部署步骤、旧服务器数据迁移与备份清单、脚本行为说明与注意事项。
4. 新增 `deploy/backup-db.sh`：云服务器数据库备份脚本。导出 `knowledge_base`（`knowledge_base_uat` 存在时一并导出），备份 `knowledge_base_ai_secrets` 卷，生成 sha256 校验和与含 Schema 版本、表数、镜像标签的元数据文件；`--verify` 可将导出恢复到临时库比对表数与 Schema 版本后自动清理；`--keep N` 控制保留份数。导出不加 `--databases`，恢复时须显式指定目标库，避免误写入生产库。

5. 新增 `.github/workflows/backup-database.yml`：手动触发的备份工作流，复用既有 `DEPLOY_*` Secrets 登录云服务器执行 `backup-db.sh`，避免在本地保存服务器凭据。
6. 新增 `.github/workflows/fetch-backup.yml`：把服务器上的最新备份打包后，用调用方提供的公钥加密再上传为 artifact，供本地解密下载。仓库为公开仓库，明文备份不得直接上传。
7. `deploy/backup-db.sh` 增加行数校验：统计源库全部基础表真实行数，与导出文件中的 INSERT 语句数交叉核对，并在 `--verify` 时逐表比对列数。

## 修复项
1. `deploy/backup-db.sh` 的行数统计 SQL 未加库名前缀，MySQL 以 `No database selected` 失败并返回空值，被当成 0 后与同样为 0 的恢复结果“比对通过”。已改为带库名前缀，且返回值非数字时直接报错退出，不再静默降级为 0。
2. `deploy/backup-db.sh` 生成 `.sha256` 时写入绝对路径，导致备份文件下载到其他机器后 `sha256sum -c` 全部失败。已改为只写文件名。
3. `.github/workflows/fetch-backup.yml` 用 `knowledge_base_*.sql.gz` 取最新备份，该通配符会匹配到 `knowledge_base_uat_*.sql.gz`，导致打包到 UAT 空白库。已改为用文件名正则精确匹配主库。
4. `deploy/backup-db.sh` 中 `docker compose ps -q` 在缺少对应服务时以非零码退出，配合 `set -e` 中断整个备份。已用 `|| true` 兜底。
