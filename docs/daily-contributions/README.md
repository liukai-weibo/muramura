# 每日贡献记录

> 本目录用于按日期沉淀当天对 Knowledge_Base 的真实项目贡献。
>
> 命名规则：`YYYY-MM-DD.md`，例如 `2026-07-21.md`。

## 记录规则

- 每次完成一轮 `typecheck`、`test`、`build:h5`、`git diff --check` 或 H5 人工验收后，同步当天文件。
- 同一天持续追加到同一个文件，不重复创建多个日期文件。
- 只写三部分：增加项、修复项，以及近几天尚未开始或当天未完成的事项。
- 每个部分使用 `1. 2. 3.` 从上到下编号；开放能力、增加入口、隐藏无效信息和页面调整均归入增加项。
- 修复项只记录解决既有错误或异常行为的修改。
- 不记录验证命令、关键决策、关联文档、风险分级或过程说明；这些仍各自留在 QA、产品、架构和 Git 记录中。
- 若当天没有实质项目修改或验证，不强制创建空文件。

## 单日模板

```markdown
# YYYY-MM-DD 每日贡献

## 增加项

1. 增加方法回收站、恢复与永久清理后的历史说明。
2. 增加快速捕获打开后输入框自动聚焦。
3. 增加“更多状态 → 已放弃”入口。
4. 增加需求池、UX 观察清单和 Sprint 验收文档。
5. 增加每日贡献记录目录和模板。
6. 开放所有未删除事项的补充说明添加、编辑与主动清空；回收站保持只读。
7. 将事项详情“流转历史”“添加说明 / 编辑”调整为次级按钮，并优化窄屏换行。
8. 隐藏正常未关联方法的空提示；保留历史关联断裂、回收站和永久清理的说明。

## 修复项

1. 修复关联方法缺失和备份恢复问题。
2. 修复新建事项自动跳到“全部事项”的问题。
3. 修复“更多状态 → 已放弃”与回收站混用的问题。
4. 修复事项说明保存与状态切换同时发生时可能互相覆盖的问题。
5. 修复补充说明保存旧回包覆盖较新状态迁移的问题。

## 未完成

1. ……
2. ……
```
