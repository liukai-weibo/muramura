# 每日贡献记录

> 本目录用于按日期沉淀当天对 Knowledge_Base 的真实项目贡献。
>
> 命名规则：`YYYY-MM-DD.md`，例如 `2026-07-21.md`。

## 记录规则

- 每次完成一轮 `typecheck`、`test`、`build:h5`、`git diff --check` 或 H5 人工验收后，同步当天文件。
- 同一天持续追加到同一个文件，不重复创建多个日期文件。
- 只写两部分：当天已完成项，以及近几天尚未开始或当天未完成的事项。
- 已完成项使用 `1. 2. 3.` 从上到下编号，描述功能增加、缺陷修复、页面调整或文档归档即可。
- 不记录验证命令、关键决策、关联文档、风险分级或过程说明；这些仍各自留在 QA、产品、架构和 Git 记录中。
- 若当天没有实质项目修改或验证，不强制创建空文件。

## 单日模板

```markdown
# YYYY-MM-DD 每日贡献

## 今日完成

1. 完成……
2. 修复……
3. 调整……

## 未完成

1. ……
2. ……
```
