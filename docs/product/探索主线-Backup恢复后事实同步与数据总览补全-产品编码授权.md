# 探索主线：Backup 恢复后事实同步与数据总览补全产品编码授权

日期：2026-07-29

## 结论

授权实施。这是 Backup 恢复成功后前端仍展示陈旧探索主线事实的 P1 修复，并补全既有“数据与设置”总览中的探索主线活跃数量；不改变任何恢复、删除或数据模型语义。

## 冻结规则

- 仅在恢复 API 已明确成功，且事项、方法、回收站与既有 exploration-tracks 真实读取全部成功后，才显示恢复完成并更新探索主线事实版本。
- 恢复后的活跃探索主线为空时，长期探索必须清空列表、`selectedId`、历史及任何旧主线上下文，展示正常空态；不得显示“探索主线不存在”错误，亦不得继续使用旧主线创建或关联事项。
- “数据与设置”新增“探索主线”活跃真实数量。已删除探索主线不计入该数，继续仅属于回收站。
- 读取中的 loading、503、Abort、响应丢失、unknown-outcome 或后续任一真实读取失败时，保留旧事实和明确错误/锁定状态；不得清空伪造成功、降级为空或自动重试。

## 授权范围

- `apps/client/src/pages/index/index.tsx`
- `apps/client/src/pages/index/exploration-prototype.tsx`
- 直接前端测试、必要 QA / 产品记录与当天贡献记录

## 明确禁止

- `api-client`、API、DTO、Application、Repository、Contracts、Migration、Backup 格式、数据库、配置、运行库、状态机、删除恢复语义及任何业务写入语义修改。
- 新增接口、字段、业务对象、缓存、自动重试或恢复后的自动写入。

## 验收标准

- 在已有探索主线并进入长期探索后，恢复一份 `explorationTracks: []` 的合法 Backup；恢复完成后列表、选中和历史均为空，且不出现“不存在”错误或旧主线操作入口。
- 数据与设置展示“探索主线：0”；存在活跃主线时展示真实活跃数量，已删除主线不计入。
- 恢复失败、503、Abort、响应丢失与 unknown-outcome 不会将界面伪装为空态，且不自动重试。
- 通过直接前端测试、`typecheck`、`build:h5` 与 `git diff --check`；完成后再交 QA 验证。
