## 一、评审结论

技术方案符合 Layout Sprint 1 PRD，可以进入前端实施。

批准采用：

```text
单个 Taro 页面
+ 现有 React useState
+ 页面级 Application Service 装配
+ 四个一级模块
+ 统一跨模块定位
+ 页面级草稿保留
+ 只渲染当前模块
```

技术方案满足以下产品边界：

- 只重组客户端页面表现层。
- 不修改业务状态机。
- 不修改复盘和方法规则。
- 不修改 Domain、Contracts、Application 和 Repository。
- 不修改 IndexedDB Schema 和迁移。
- 不修改 JSON 备份格式和安全恢复规则。
- 不引入路由、全局状态库和新后端接口。
- 不提前实施 Layout Sprint 2、Layout Sprint 3 或其他新功能。

## 二、四项产品裁决

### 决策 1：跨模块快速捕获后进入行动

**裁决：采纳技术建议。**

用户在行动、方法、观察或数据与设置模块完成快速捕获后，统一执行：

```text
创建成功
→ 清空本次捕获草稿
→ 进入行动模块
→ 退出回收站
→ 清除不兼容筛选
→ 定位新事项所在页
→ 选中新事项
→ 显示新事项详情
```

产品理由：快速捕获是创建行动对象的全局入口。创建成功后让用户明确看到结果，比停留原模块并仅显示一条成功消息更可靠，也能减少“是否真的创建成功”的不确定性。

该规则只在**创建成功后**触发。创建失败或取消时不得切换模块、清空草稿或改变原上下文。

### 决策 2：待恢复备份允许模块切换

**裁决：采纳技术建议。**

备份文件已选择并校验、但用户尚未确认恢复时：

- 允许切换其他模块。
- 保留待恢复备份、校验结果和提示信息。
- 返回数据与设置后必须恢复原确认上下文。
- 不因普通模块切换执行恢复或覆盖数据。

真正开始恢复后：

- 暂时禁止一级模块切换。
- 禁止重复提交。
- 恢复进度或操作中状态必须可见。
- 成功后刷新全部模块数据。
- 失败后保留原数据并给出明确错误。

产品理由：选择文件不等于授权覆盖。恢复前允许用户离开可以降低流程强制性；开始恢复后锁定导航则用于保护高风险操作的完整性。

### 决策 3：复盘搜索定位所属事项

**裁决：采纳技术建议。**

搜索命中复盘后采用：

```text
进入行动模块
→ 退出回收站
→ 清除不兼容筛选
→ 定位所属事项所在页
→ 选中所属事项
→ 等待复盘内容加载
→ 定位或突出显示复盘区域
```

本轮不增加独立复盘页面、路由或新的业务对象导航。

产品理由：复盘是事项闭环的一部分，不是独立的一级工作上下文。该方案符合“一事一条主记录”和“复盘位于事项详情”的现有产品原则。

定位只负责查看，不得重新打开已完成复盘的编辑状态，也不得修改复盘内容。

### 决策 4：仪表盘下钻主目标按指标语义确定

**裁决：采纳语义分流方案，并冻结如下映射。**

| 仪表盘指标 / 入口 | 主定位对象 | 目标模块 |
|---|---|---|
| 新增事项 | 事项 | 行动 |
| 进入执行 | 事项 | 行动 |
| 完成复盘 | 事项及其复盘区域 | 行动 |
| 方法形成 | 方法 | 方法 |
| 方法验证 | 方法 | 方法 |
| 方法修订 | 方法及对应版本 | 方法 |
| 方法发起行动 | 具体事项 | 行动 |
| 当前堵塞 | 对应状态事项集合 | 行动 |
| 方法复利 | 方法 | 方法 |

补充规则：

- 一条记录同时存在 `itemId` 和 `methodId` 时，不按字段是否存在决定跳转，必须按上表的指标语义决定。
- 方法验证优先定位方法资产，因为该指标表达的是方法证据增长；来源事项属于次级证据，可在方法证据区域查看。
- 方法发起行动优先定位事项，因为该指标表达的是一次具体行动已经被创建；方法上下文应在事项详情中可见。
- 完成复盘优先定位事项的复盘区域，不停留在普通事项详情顶部。
- 目标不存在或已删除时，显示明确提示并清除错误选中，不回退展示上一次对象。

## 三、对技术方案的产品审查

### 已通过项

- 页面和组件拆分符合最小改造原则。
- 一级导航不持久化，刷新后返回行动 / 想试试，符合本轮范围。
- 搜索与仪表盘复用统一定位逻辑，符合 PRD。
- 定位事项时考虑筛选、回收站和分页，不会只选中但不可见。
- 未提交捕获、复盘和方法行动草稿上提，模块切换不会丢失。
- 待恢复状态与恢复中状态被正确区分。
- 只渲染当前模块，避免隐藏模块副作用。
- 修改范围被限制在客户端页面、样式、可选展示组件和测试。
- 完整闭环、搜索、下钻和备份恢复均纳入回归。

### 实施提醒

1. “保留上下文”不能只保留 ID；筛选、分页、展开状态和草稿也必须按技术方案保留。
2. 搜索与仪表盘不得分别实现两套相似但不同的定位规则。
3. 快速捕获和方法发起行动成功后，都必须定位到新事项。
4. 方法验证下钻必须进入方法模块；方法发起行动下钻必须进入行动模块。
5. 不得借机完成方法列表—详情、复杂搜索浮层、折叠捕获或最终响应式。
6. 如果组件拆分导致大量业务函数复制，应退回由 `IndexPage` 协调，不以形式化拆分为目标。

## 五、实施中必须暂停并回流的条件

出现以下任一情况，前端必须停止扩大修改并返回产品与架构评审：

1. 必须修改 Domain、Contracts、Application 或 Repository。
2. 必须修改 IndexedDB Schema、迁移或 JSON 备份格式。
3. 现有数据无法支持 PRD 中的定位行为。
4. 必须引入路由、全局状态库或持久化草稿。
5. 发现新的业务状态或产品规则歧义。
6. 实施范围进入 Layout Sprint 2 或 Layout Sprint 3。
7. 为完成布局需要重写复盘、方法、搜索、仪表盘或恢复业务逻辑。

## 六、产品验收门槛

前端自测和自动化验证完成后，必须回到产品经理按以下维度验收：

1. 四模块是否真正替代单页长页面。
2. 高频行动上下文是否成为默认入口。
3. 搜索跨模块定位是否完整。
4. 仪表盘语义分流是否符合本文件映射。
5. 模块切换是否保留上下文和未提交草稿。
6. 快速捕获和方法发起行动后是否能看到新事项。
7. 备份待确认和恢复中状态是否符合安全规则。
8. `v0.1.0` 完整业务闭环是否无回归。
9. 是否严格停留在 Layout Sprint 1 范围。
