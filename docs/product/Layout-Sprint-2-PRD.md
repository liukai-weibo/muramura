# Layout Sprint 2 PRD：方法工作台与复盘交互优化

> 状态：待架构轻量技术评审
>
> 产品依据：`功能清单-v2.md`、`整体布局设计-v1.md`、`产品经理工作基线-v1.md`、`Layout-Sprint-1-产品验收记录.md`
>
> 前置条件：Layout Sprint 1 已正式验收通过并封板。
>
> 本轮解决真实使用中已经出现的方法浏览、方法复用后复盘、方法处理选择和事项流转历史展示问题。除本文件明确规定的交互调整外，不修改核心业务对象、状态机、备份格式和数据安全规则。

## 一、产品背景

Layout Sprint 1 已将单页功能堆积重组为行动、方法、观察、数据与设置四个工作上下文。真实使用后，当前主要摩擦集中在方法模块和事项详情的辅助信息展示。

### 问题 1：方法大卡片占用空间

当前方法采用双列大卡片：

- 内容较短时出现大量无意义空白。
- 一屏只能浏览少量方法。
- 方法数量增加后难以快速定位和比较。
- 完整步骤、说明、操作与历史同时堆在卡片中，信息层级不清。
- 方法资产没有形成“目录负责定位、详情负责理解”的工作台结构。

### 问题 2：方法发起事项后的复盘存在重复操作

系统已保存事项来源方法和实际使用版本，但复盘时仍需要用户：

1. 主动选择“验证已有方法”。
2. 再次从所有方法中寻找来源方法。
3. 决定是否修订。

这是系统已经知道但仍要求用户重复输入的信息。

### 问题 3：方法处理选择存在冗余

当前复盘显示：

```text
不沉淀方法
形成新方法
验证已有方法
```

“不沉淀方法”实际上应是未选择任何方法动作时的默认状态，不需要占据与两个真实业务动作相同的视觉权重。

### 问题 4：方法表单文案偏技术化

“具体步骤”能表达业务含义，但在形成或修订方法的操作场景中不够行动导向。“新动作”又容易与系统中的事项 / 行动对象混淆。

### 问题 5：流转历史推动主内容

当前在事项详情顶部展开流转历史后，历史区域进入正常文档流，导致标题、正文和复盘表单整体下移。辅助审计信息不应造成主要工作区大幅重排。

## 二、本轮目标

```text
方法卡片堆叠
→ 方法列表—详情工作台

重复选择来源方法
→ 系统识别并默认关联

三项方法决策
→ 两个可切换业务动作

历史展开推动正文
→ 右侧浮动抽屉叠加查看
```

完成后必须达到：

1. 用户能在一屏内紧凑浏览和比较更多方法。
2. 用户选择方法后，在固定详情区域查看完整步骤、说明、证据、版本和复用入口。
3. 搜索和仪表盘定位方法后，直接选中目标方法并显示详情。
4. 方法发起事项进入复盘时，默认进入来源方法验证上下文。
5. 用户不需要通过一个显式“不沉淀方法”选项表达无方法处理。
6. 仅验证与修订保持明确区别，不为无变化的方法强制生成版本。
7. 查看流转历史不改变事项正文和复盘区域的位置。

## 三、范围

### 本轮必须完成

- 方法模块改为桌面端列表—详情结构。
- 方法列表支持名称 / 步骤搜索。
- 方法列表支持“最近更新”和“验证最多”两种排序。
- 方法详情展示当前版本、步骤、补充说明、复用入口、证据和版本历史。
- 证据与版本历史默认折叠。
- 搜索和仪表盘定位方法时直接选中方法。
- 命中历史版本时选中方法并展开对应版本。
- 复盘方法决策改为两个可切换动作。
- 方法来源事项复盘时默认关联实际使用的方法。
- 明确仅验证和修订的交互规则。
- 优化形成 / 修订方法时的字段文案。
- 流转历史改为右侧浮动抽屉。
- 完成相关回归测试和人工验收。

### 本轮明确不做

- 不修改事项状态机。
- 不新增“方法有效 / 无效 / 不适用”等方法状态。
- 不新增否证评分、置信度或自动淘汰机制。
- 不强制每次方法复用都生成新版本。
- 不新增方法标签、分类树、文件夹和复杂筛选。
- 不新增方法删除、合并和归档能力。
- 不实施关系型搜索增强。
- 不修改全局搜索的数据范围和结果类型。
- 不实施 Layout Sprint 3 的最终搜索浮层、捕获交互和完整响应式。
- 不引入 AI、计划、方向层、附件、提醒或云同步。
- 不修改 JSON 备份格式和恢复规则。

## 五、方法列表需求

### 1. 每行信息

每条方法只展示用于定位和比较的信息：

```text
方法名称
当前版本 · 验证次数 · 最近更新时间
当前步骤首行摘要
```

不得在列表中展示：

- 完整步骤。
- 完整补充说明。
- 来源复盘全文。
- 版本历史。
- “用此方法发起行动”主按钮。

### 2. 选中状态

- 当前选中方法必须有明确背景、边线或其他稳定视觉状态。
- 点击列表项只改变当前选中方法，不执行其他业务动作。
- 选择方法后右侧显示详情。
- 重新进入方法模块时，保留上次选择的方法；若没有选择，默认选择当前排序下第一条方法。
- 当前方法不存在时，清除无效选择并显示空详情状态。

### 3. 方法搜索

搜索范围：

- 方法名称。
- 当前步骤。

规则：

- 只搜索当前有效方法，不搜索历史版本和来源复盘。
- 搜索仅作用于方法模块左侧列表，不改变全局搜索行为。
- 搜索词为空时展示全部方法。
- 搜索无结果时显示明确空状态。
- 清空搜索后恢复原排序和可见列表。
- 如果当前选中方法被搜索结果排除，右侧详情可以继续保留，但必须提示“当前方法不在筛选结果中”；或者清除选择。具体采用哪种方案由技术评审提出，产品优先建议清除选择，降低隐藏上下文。

### 4. 排序

只提供：

- 最近更新。
- 验证最多。

默认：最近更新。

规则：

- 最近更新按更新时间倒序。
- 验证最多按验证次数倒序；相同时按更新时间倒序。
- 不增加拖拽、自定义排序和其他复杂排序。

## 六、方法详情需求

### 1. 当前方法信息

按以下顺序展示：

1. 方法名称。
2. 当前版本和验证次数。
3. 当前有效步骤。
4. 补充说明。
5. 用此方法发起行动。
6. 来源与验证证据。
7. 版本历史。

字段为空时：

- 补充说明为空可以不展示正文，只显示“暂无补充说明”或隐藏该区块标题。
- 当前步骤不可为空。

### 2. 用方法发起行动

- 作为方法详情中的主要操作。
- 点击后在详情内展开紧凑表单，或复用现有方法行动表单。
- 创建成功后继续进入行动模块、定位并选中新事项。
- 必须冻结实际使用的方法版本。
- 创建失败时保留草稿和当前方法详情。
- 普通模块切换继续保留未提交的方法行动草稿。

### 3. 来源与验证证据

默认折叠。

展开后按时间倒序显示：

- 证据对应事项标题。
- 复盘时间。
- 关系类型：形成 / 验证 / 修订。
- 必要的复盘摘要。
- 定位原事项 / 复盘的入口。

本轮不修改证据数据模型。若现有数据无法可靠区分形成、验证和修订，应由架构评审说明可表达范围，产品不得要求前端伪造关系类型。

### 4. 版本历史

默认折叠。

展开后按版本倒序显示：

- 版本号。
- 创建时间。
- 该版本步骤。
- 补充说明。
- 来源复盘入口（若存在）。

从全局搜索命中历史版本时：

```text
进入方法模块
→ 选中所属方法
→ 展开版本历史
→ 定位并突出显示目标版本
```

版本历史不得以展开全部大卡片的形式再次制造长页面。

## 七、复盘方法决策改造

### 1. 普通事项

方法处理区只展示两个动作：

```text
形成新方法
验证已有方法
```

默认状态：两个动作均未选择，表示本次不处理方法。

不再显示独立的：

```text
不沉淀方法
```

### 2. 切换规则

点击“形成新方法”：

```text
未选中
→ 选中形成新方法
→ 展开新方法表单
```

再次点击：

```text
已选中
→ 取消选择
→ 收起表单
→ 回到不处理方法
```

“验证已有方法”同理。

两个动作互斥：

- 选择形成新方法时取消验证已有方法。
- 选择验证已有方法时取消形成新方法。
- 切换动作时，不保留另一个动作的错误提示。
- 是否保留另一个动作尚未提交的草稿，由技术评审评估；产品优先建议在同一次复盘中暂时保留，避免误触导致内容丢失，但提交时只使用当前选中动作的数据。

### 3. 不处理方法

用户未选择任何方法动作时，可以正常提交复盘。

产品语义：

```text
复盘完成
+ 本次不形成、不验证、不修订方法
```

该默认状态不需要额外按钮、勾选或确认。

## 八、方法来源事项的默认复盘上下文

### 1. 系统已知条件

如果事项由方法发起，系统已经保存：

- 来源方法。
- 实际使用的方法版本。

进入待复盘事项时，应展示：

```text
本次行动使用了：
「方法名称」vN
```

### 2. 默认行为

进入该事项的复盘工作区时：

```text
默认选中“验证已有方法”
→ 默认选择来源方法
→ 显示实际使用版本
→ 默认采用“仅验证”
```

用户不需要从完整方法列表重新寻找来源方法。

### 3. 是否允许取消

允许用户再次点击“验证已有方法”取消方法处理。

取消后：

- 仍展示只读的来源方法上下文。
- 本次复盘不增加方法验证次数。
- 不生成新版本。
- 不删除原有方法应用关系。

产品理由：通过方法发起不等于本次行动必然足以评价方法。强制验证会污染证据真实性。

### 4. 是否允许切换其他方法

本轮建议：允许切换，但默认选择来源方法。

适用场景：用户实际执行时发现本次复盘更能验证另一个已有方法。

如果技术或业务一致性风险较大，架构评审可以提出“来源方法锁定”的替代方案，交产品经理再次裁决。前端不得自行决定。

## 九、仅验证与修订

### 1. 仅验证

默认行为：

```text
选择已有方法
→ 默认仅验证
→ 提交复盘
→ 增加证据和验证次数
→ 方法版本不变
```

### 2. 修订方法

用户主动选择：

```text
本次需要修订方法
```

之后展开修订表单。

提交后：

```text
增加本次复盘证据
+ 增加验证次数
+ 生成方法新版本
```

### 3. 禁止强制修订

不得要求用户为了完成复盘而必须修改方法。

不得在步骤无变化时自动生成新版本。

验证和修订的产品语义必须保持：

| 行为 | 新增证据 | 验证次数增加 | 生成版本 |
|---|---:|---:|---:|
| 不处理方法 | 否 | 否 | 否 |
| 仅验证 | 是 | 是 | 否 |
| 修订并验证 | 是 | 是 | 是 |

## 十、方法表单文案

避免统一使用容易与事项混淆的“新动作”。

冻结文案：

| 场景 | 字段标题 |
|---|---|
| 形成新方法 | 下一次怎么做 |
| 修订已有方法 | 更新后的做法 |
| 方法详情展示 | 具体步骤 |

补充说明继续使用：

```text
补充说明（可选）
```

方法名称继续取步骤首行；修订时沿用原方法身份和名称规则，不新增独立名称输入。

## 十一、事项流转历史抽屉

### 1. 问题目标

流转历史属于辅助审计信息。打开历史不得推动事项标题、正文、操作区和复盘表单整体下移。

### 2. 桌面端方案

点击事项详情右上角“流转历史”后，在详情右侧叠加浮动抽屉：

```text
事项详情保持原位置
+
右侧流转历史抽屉覆盖出现
```

### 3. 抽屉规则

- 不进入事项正文文档流。
- 不改变正文起始位置和当前滚动位置。
- 建议宽度 `360px–420px`。
- 最大不超过事项详情区域宽度的 `40%`。
- 抽屉内部独立滚动。
- 展示事项创建时间、更新时间和完整状态事件。
- 状态事件按时间正序，保持事项生命周期阅读顺序。
- 点击关闭按钮可关闭。
- 再次点击“流转历史”可关闭。
- 桌面 Web 支持 `Esc` 关闭；若 Taro 跨端实现代价较大，可由架构评审决定是否列为必须项。
- 关闭后事项详情保持原滚动位置。
- 不需要大面积遮罩；使用边界和轻阴影表达叠加层。
- 删除确认、恢复确认等更高风险浮层出现时，历史抽屉不得覆盖其上。
- 切换事项时默认关闭历史抽屉，避免把上一事项的历史视觉状态带到新事项。
- 切换一级模块再返回行动时，是否恢复历史抽屉展开状态沿用 Layout Sprint 1 上下文保留原则；如果实现会导致错误事项历史闪现，则允许安全地关闭。

### 4. 小屏边界

本轮以桌面端为主。小屏下允许抽屉占据更大宽度或全宽覆盖，但不要求完成 Layout Sprint 3 的最终移动端导航与响应式体系。

## 十二、跨模块定位规则

### 1. 定位当前方法

```text
全局搜索 / 仪表盘方法复利 / 方法指标
→ 进入方法模块
→ 清除不兼容的方法模块搜索条件或提示当前目标不在筛选结果
→ 选中目标方法
→ 右侧显示详情
```

产品优先建议：外部定位优先于方法模块内部搜索，自动清空阻挡目标的方法搜索词。

### 2. 定位历史版本

```text
全局搜索历史版本
→ 进入方法模块
→ 选中所属方法
→ 展开版本历史
→ 定位目标版本
```

### 3. 从方法证据定位复盘

```text
点击证据来源
→ 进入行动模块
→ 定位所属事项
→ 定位复盘区域
```

必须复用 Layout Sprint 1 已建立的统一跨模块定位逻辑，不增加第二套导航行为。

## 十三、状态与空状态

### 方法为空

```text
还没有形成方法。
先完成真实行动和复盘，不必为了填满方法库而创建。
```

### 方法搜索无结果

```text
没有找到符合当前关键词的方法。
```

提供清空搜索入口。

### 未选择方法

右侧详情展示：

```text
从左侧选择一条方法，查看步骤、证据和版本。
```

### 方法目标不存在

```text
目标方法不存在或已删除。
```

清除错误选中，不显示上一方法详情。

### 版本不存在

方法仍存在但目标历史版本不存在时：

- 继续显示当前方法详情。
- 展示“目标版本不存在”的提示。
- 不伪造版本或定位到其他版本。

## 十四、研发交付拆分建议

### L2-01 方法列表—详情骨架

- 左侧方法列表。
- 右侧方法详情。
- 当前选中方法。
- 空状态。
- 最近更新 / 验证最多排序。
- 方法模块局部搜索。

### L2-02 方法详情与复用

- 当前步骤与补充说明。
- 用方法发起行动。
- 来源证据折叠。
- 版本历史折叠。
- 方法行动草稿保护。

### L2-03 方法定位

- 全局搜索定位方法。
- 历史版本定位。
- 仪表盘方法指标定位。
- 方法证据反向定位事项复盘。

### L2-04 复盘方法决策

- 移除显式“不沉淀方法”。
- 两个可切换动作。
- 来源方法默认验证。
- 仅验证 / 修订交互。
- 表单文案调整。

### L2-05 流转历史抽屉

- 右侧叠加抽屉。

## 十五、产品验收清单

### 方法列表—详情

- [ ] 方法不再以双列大卡片铺满页面。
- [ ] 一屏可以紧凑浏览多条方法。
- [ ] 每行只展示定位和比较信息。
- [ ] 点击方法后右侧显示完整详情。
- [ ] 当前选中方法状态明确。
- [ ] 最近更新和验证最多排序正确。
- [ ] 方法局部搜索只作用于当前方法。
- [ ] 来源证据和版本历史默认折叠。
- [ ] 展开历史不会重新制造大面积卡片堆叠。

### 方法定位

- [ ] 全局搜索方法后进入方法模块并选中目标。
- [ ] 搜索历史版本后展开并定位版本。
- [ ] 仪表盘方法形成、验证、修订和复利正确定位方法。
- [ ] 方法发起行动指标仍定位具体事项。
- [ ] 方法证据可反向定位所属事项复盘。

### 复盘方法决策

- [ ] 普通事项默认不选择任何方法动作。
- [ ] 不再显示“不沉淀方法”按钮。
- [ ] 点击形成新方法可展开，再次点击可取消。
- [ ] 点击验证已有方法可展开，再次点击可取消。
- [ ] 两个动作互斥。
- [ ] 未选择动作时仍可正常提交复盘。
- [ ] 方法来源事项默认打开验证已有方法。
- [ ] 默认选择实际来源方法并显示使用版本。
- [ ] 用户可以取消方法处理。
- [ ] 默认仅验证，不强制修订。
- [ ] 只有主动修订时才生成新版本。

### 字段文案

- [ ] 形成新方法显示“下一次怎么做”。
- [ ] 修订方法显示“更新后的做法”。
- [ ] 方法详情继续显示“具体步骤”。
- [ ] 不使用容易与事项混淆的统一“新动作”。

### 流转历史

- [ ] 点击流转历史后事项正文不下移。
- [ ] 历史以右侧浮动抽屉显示。
- [ ] 抽屉内部独立滚动。
- [ ] 关闭后正文位置不变化。
- [ ] 切换事项不会显示上一事项历史。
- [ ] 高风险确认层级高于历史抽屉。

### 核心回归

- [ ] 形成方法业务结果正确。
- [ ] 仅验证增加证据与验证次数，但不生成版本。
- [ ] 修订并验证增加证据、验证次数和新版本。
- [ ] 方法发起事项仍冻结使用版本。
- [ ] 搜索和仪表盘原有事项定位无回归。
- [ ] JSON 导出和安全恢复无回归。

## 十六、架构评审重点

架构师必须回答：

1. 方法列表—详情是否只需要前端状态和现有数据能力。
2. 是否需要修改 Contracts、Application、Repository 或 IndexedDB Schema。
3. 现有方法证据和版本数据能否可靠表达形成、验证、修订关系。
4. 方法来源事项进入复盘时，如何读取并默认选择来源方法。
5. 当前复盘初始化逻辑如何避免覆盖用户已输入草稿。
6. 两个可切换方法动作的草稿保留如何实现且不污染提交数据。
7. 方法局部搜索和排序是否可以在客户端完成。
8. 外部方法定位如何处理局部搜索条件和目标版本。
9. 流转历史抽屉如何避免推动正文并处理层级、滚动和事项切换。
10. 哪些需求会触碰底层业务语义，哪些只是表现层调整。
11. 测试应如何覆盖来源方法默认验证、取消验证、仅验证和修订。
12. 若本轮必须修改业务层，应给出最小变更范围和不可替代理由。

## 十七、实施中必须暂停的条件

出现以下任一情况，应停止开发并返回产品 / 架构评审：

1. 需要新增或改变事项状态。
2. 需要改变验证次数或版本生成的既有业务含义。
3. 现有方法应用关系无法确定来源方法或使用版本。
4. 需要修改 JSON 备份格式但未完成兼容设计。
5. 需要引入路由、全局状态库或新的后端接口。
6. 需要新增方法标签、分类、删除、合并等超范围能力。
7. 流转历史抽屉开始演变为完整事项侧边栏重构。
8. 实施范围进入关系型搜索或 Layout Sprint 3。

## 十八、封板条件

以下条件同时成立，Layout Sprint 2 才可封板：

1. 方法列表—详情在真实方法数据下通过人工验收。
2. 方法来源事项默认验证来源方法，但不强制修订。
3. 普通复盘方法动作两项化且可取消。
4. 仅验证与修订的数据结果符合既有业务规则。
5. 流转历史不再推动事项正文。
6. 搜索和仪表盘方法定位无回归。
7. 完整业务测试、类型检查和 H5 构建通过。
8. JSON 备份和安全恢复无回归。
9. 未混入 Layout Sprint 3、关系型搜索、AI 或方向层需求。
