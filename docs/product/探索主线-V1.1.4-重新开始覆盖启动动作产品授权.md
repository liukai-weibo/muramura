# 探索主线 V1.1.4：重新开始覆盖启动动作产品授权

日期：2026-07-27

## 产品裁决

批准对既有 StartItemExecutionInput 的最小例外：增加 `overwriteExistingStartAction` 确认参数。它只表达本次请求已获用户明确确认，不新增持久字段、对象、状态或路由。

## 规则

- 适用场景仅为事项已从 `abandoned` 真实刷新为 `idea_to_try` 后重新开始。
- 旧启动动作存在、用户提交的新动作非空且与旧值不同：前端必须先显示“是否覆盖已有启动动作”。
- 用户确认后才发出 `overwriteExistingStartAction: true`；Repository 在单一事务锁内验证条件，并原子覆盖动作、迁移为 `doing`、写入唯一状态事件。
- 缺少确认参数时稳定拒绝并保留旧动作与 `idea_to_try`；用户取消确认零写入并保留输入草稿。
- 新动作为空或与旧值相同：不显示覆盖确认，沿既有开始执行语义处理。
- unknown-outcome 不自动重试或本地推断；仅允许用户显式重读确认。

## 授权范围

- `packages/contracts/src/**`
- `packages/application/src/**`
- `packages/storage-mysql/src/**`
- `apps/api/src/**`
- `apps/client/src/pages/index/**`
- 与本参数、事务规则、API 映射、前端确认层直接对应的 `tests/**`
- 必要架构、QA、产品记录与当天贡献记录

## 明确禁止

- 新增业务对象、持久字段、状态、关系、路由、migration、备份格式、DDL、Docker/MySQL 或 `.env` 配置。
- 任何自动重试、后台补偿、fallback、本地成功推断，或 V1.1.4 以外的启动流程重构。

## 验收

- 无旧动作、空动作、同值动作保持既有路径。
- 旧动作 + 不同新动作 + 未确认稳定拒绝并零写入。
- 明确确认后，动作、`doing` 与唯一状态事件在同一事务内生效。
- 取消确认零写入且草稿保留；unknown-outcome 不自动重试。
- 定向测试、typecheck、相关 API / MySQL 集成测试、build:h5 与 `git diff --check` 通过。
