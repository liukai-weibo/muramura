## 关键业务规则

- `member` 是每个用户固定基础角色，不提供撤销能力；`platform_admin` 是唯一可选附加角色。
- 管理员不得调整自己的角色，不得通过管理能力撤销自己的会话；最后一个管理员不得撤销。
- 用户列表固定每页 20 条，按 `createdAt` 倒序、userId 升序，支持用户名 literal substring 搜索。
- 用户列表只含 username、roles、createdAt；userId 只用于定位操作。不得展示密码、密码哈希、Cookie、会话秘密/摘要、业务内容或业务统计。
- 普通用户未来调用管理 API 必须为 403；跨用户业务读取、写入、删除、恢复继续统一 404。管理员身份不得绕过十个业务集合的 owner scope。
- 角色修改、会话撤销与对应审计必须同事务提交。重复角色操作不新增审计；最后管理员、自操作、非管理员 actor、目标不存在或 operation 冲突必须零写入。
- commit 后响应丢失或测试钩子失败属于 unknown-outcome：不得自动重试，必须按 operationId 显式读取审计并真实重读事实。
- Backup V1/V2/V3 不加入 users、roles、sessions 或 security audit 数据。
