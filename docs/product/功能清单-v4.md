# 个人系统功能清单 v4

> 状态：当前有效产品基线，已同步至方法生命周期治理 Sprint 封板行为。
>
> `功能清单-v1.md`、`功能清单-v2.md` 与 `功能清单-v3.md` 保留为历史记录；当其与本文件或已验收行为冲突时，以本文件为准。

## 一、第一阶段目标

建立稳定、可追溯、可恢复的个人行动闭环：

```text
想法
→ 执行
→ 复盘
→ 形成 / 验证 / 修订方法
→ 用方法发起新行动
→ 搜索定位
→ 周期观察
→ 从仪表盘下钻到具体记录
```

产品原则：

1. 本地优先，不依赖外部服务才能使用。
2. 一件事一条主记录，通过状态迁移而非复制推进。
3. 复盘优先于方法沉淀；默认不沉淀方法，多次真实证据积累后再主动形成或修订方法。
4. 捕获和复盘保持低阻力，字段只保留能推动判断与行动的内容。
5. 核心数据必须完整备份、可靠恢复，不能锁死在系统内。
6. 可视化只服务判断、定位和下一步行动。
7. 历史事实必须诚实保留；删除方法正文不得伪装为“从未发生过关联”。

## 二、第一阶段有效功能

### 1. 总览与定位

- 系统仪表盘支持 7 天、30 天和全部时间窗口。
- 展示新增事项、进入执行、完成复盘、方法形成、验证、修订和方法发起行动。
- 指标支持下钻到对应事项或方法。
- 展示当前堵塞状态和方法复利信息。

### 2. 想法与执行

- 顶部“＋快速捕获”与行动模块“＋捕获”共用捕获浮层；浮层打开后主输入框自动聚焦。
- 使用“一句话标题 + 补充说明（可选）”快速捕获。
- 只填写补充说明时，第一行自动成为标题。
- 可进入“想试试”或“以后再说”。
- 想法可以开始执行，支持暂停、恢复和放弃；执行完成后进入待复盘。
- 事项池按真实运行状态筛选；系统自动定位事项时进入其真实状态对应的池，“全部事项”仅由用户主动选择。
- 已放弃作为低频历史决策状态保留：活跃事项存在已放弃记录时，可通过“更多状态 → 已放弃”主动查看；不与暂停、以后再说或回收站混同。
- 状态迁移写入独立事件日志。

### 3. 复盘

复盘表单包含：

- 结果怎样（唯一默认必填文本）；
- 有效 / 舒服、阻力 / 不舒服、产生新想法三类可选过程信号及可选补充说明；
- 信号支持多选，不替代事实记录；过程信号说明按需展开，并在清除已有内容前要求确认。

复盘页遵循“先完成事实复盘，再决定是否处理方法”：

- 方法处理默认渐进披露；两项均未选择即不处理方法。
- 方法来源事项进入待复盘时，完整关联默认建议验证来源方法；用户可取消建议、切换验证其他方法或选择形成新方法。
- 关联方法处于回收站、已永久清理或历史关联不可用时，只允许完成事实复盘，不自动验证、修订、重连或推断其他方法。
- 提交失败保留事实、信号及页面局部草稿；离开含未保存输入的复盘需确认放弃。

### 4. 方法

- 复盘时提供“形成新方法”与“验证已有方法”两个互斥选择；两项均未选择即不处理方法。
- 形成新方法的最小结构为：方法名（必填）、具体步骤（必填）、补充说明（可选）。方法名由用户显式填写，不再由步骤首行派生。
- 修订已有方法默认沿用稳定方法名称，仅更新步骤与补充说明并产生新版本；验证不改名称、步骤或版本。
- 方法模块采用左侧列表、局部搜索与右侧详情工作台；局部搜索排除当前选择时清空详情选择。
- 方法详情展示来源与验证证据、版本历史；证据关系由结构化读模型提供，包含形成、验证、修订和历史证据。历史关系未知时必须明确显示“关系类型无法从旧数据中确定”，不得推断。
- 可从正常可用的方法发起新行动，并冻结实际使用的方法版本。

### 5. 方法生命周期治理

- 方法详情通过 `··· 更多操作 → 移入回收站 → 二次确认` 进入统一回收站，保留 30 天。
- 30 天内可从“数据与设置 → 回收站”恢复方法；回收站支持全部、事项、方法筛选。
- 回收站期内的方法保留完整本体、版本、证据及关系以支持恢复，但从默认方法列表、全局搜索、行动发起、验证 / 修订候选和编辑入口排除。
- 方法到期永久清理时删除方法与版本正文，仅为仍存在的历史关系保留最小历史墓碑。
- 历史关联稳定显示“已移入回收站”或“已永久清理”；墓碑不可搜索、不可复用、不可编辑、不可验证或修订，也不能恢复完整正文。
- 当无任何 MethodEvidence 或 MethodApplication 再引用墓碑时，墓碑一并清理。

### 6. 搜索、筛选与历史

- 全局搜索事项、复盘、当前可用方法及方法历史版本；回收站期内方法和墓碑不参与正常方法搜索。
- 支持状态筛选、回收站和仪表盘下钻定位。
- 事项详情以右侧浮动抽屉按需展示完整状态流转历史；抽屉不进入正文文档流，支持关闭、Esc 关闭及切换事项自动关闭。
- 当前列表默认按更新时间倒序；自定义排序和标签延后到出现真实管理痛点后决定。

### 7. 删除、恢复与数据安全

- 事项删除与方法移入回收站均保留 30 天，支持从统一回收站恢复。
- 到期清理在可信事务内维护关联关系；历史关系按结构化状态诚实降级。
- 完整 JSON 备份为 v2，包含事项、复盘、方法、证据、版本、方法应用、状态事件、来源关系与方法历史墓碑。
- 系统兼容导入 v1 备份；导入前继续校验格式、版本、唯一 ID、状态与必填跨表引用。
- 恢复前自动下载当前数据安全备份；安全备份交付失败时禁止覆盖。
- 数据替换在单个 IndexedDB 事务中完成；失败时保留原数据。

### 8. 工程交付

- Windows 本地 H5 开发可运行。
- TypeScript 类型检查、自动化测试和 H5 构建稳定。
- Docker 镜像可构建和访问。
- SPA 刷新可用，提供健康检查。
- Application / Repository 分层成立，页面不直接操作 Dexie。
- 代码、设计文档和个人运行数据保持 Git 隐私边界。

## 三、第一阶段完成标准

1. 新建想法并选择“想试试”或“以后再说”。
2. 将想法转为执行，支持暂停、恢复、放弃和结束。
3. 结束执行后进入待复盘并完成事实复盘。
4. 复盘可产生新想法，且可形成或验证方法；不选择方法处理时不改变方法。
5. 新方法具备用户显式名称、可执行步骤与可选补充说明；方法可发起新行动并保留使用版本与来源关系。
6. 方法可进入统一回收站并在 30 天内恢复；永久清理后历史关系仍可被最小墓碑诚实解释。
7. 可搜索并定位事项、复盘和正常可用的方法；可查看单事项完整状态流转历史。
8. 可从仪表盘观察周期事实并下钻到记录。
9. 可导出完整 JSON；系统自产备份可安全恢复，且兼容 v1 备份。
10. 类型检查、完整测试、H5 构建和 Docker 里程碑验证通过。

完成以上标准后，第一阶段封板为 `v0.1.0`，并完成后续体验与数据安全升级。

## 四、第一阶段不做或延后

- 标签体系和自定义排序：有真实数据管理痛点后再评估。
- Markdown、ZIP、manifest 和可读导出报告：作为后续可读导出能力。
- `deviceId` 和云同步预留：进入多设备设计时统一处理。
- AI、附件、提醒、日历、多人协作和复杂权限。
- 方法停用、归档、复制、批量删除 / 恢复、重命名，及永久清理后恢复方法正文。

## 五、第二阶段主线

第二阶段不继续扩张行动表单，而是建立方向层：

```text
关于我 / 长期方向
→ 阶段目标
→ 年月周计划
→ 具体事项
→ 复盘证据
→ 反向校准方向
```

第二阶段必须在第一阶段封板后单独定义，不直接沿用第一阶段字段假设开发；先以 `docs/product/需求池.md` 中的 `KB-PHASE2-001` 进入产品定义。
