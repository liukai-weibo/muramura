# 本机迁移与一键启动：产品编码授权

> 日期：2026-07-27
>
> 状态：已获架构有条件可行结论；本文件授权最小范围编码与验证。
>
> 当前运行路径、数据源、阶段与禁止事项以 `docs/product/当前运行事实.md` 为准。

## 目标

让用户在新机器上以受控步骤初始化项目、恢复个人 Backup V3 数据，并在日常通过单一启动动作运行本地项目；不把个人数据、密码或数据库实例文件纳入镜像或 Git。

## 授权范围

- `scripts/kb-init.ps1`
- `scripts/kb-start.ps1`
- `scripts/kb-stop.ps1`
- README 或一份专用本机启动文档
- 上述脚本的直接测试、QA 记录和当天贡献记录

## 冻结流程

### 首次初始化

1. 用户克隆代码并显式运行 `kb-init.ps1`。
2. 脚本检查必要依赖；仅当 `.env` 不存在时，才由 `.env.example` 生成本机配置。不得覆盖已有 `.env`，不得输出密码。
3. 脚本仅通过既有 Docker Compose 启动 MySQL 服务；不得修改 compose、端口、容器权限或 `mysql-data`。
4. 脚本仅在新机器空库上执行既有 migration 初始化 Schema；不得新增、修改、回滚或对既有业务库重跑 migration。
5. 默认启动日常 API，并以 `/health` 明确确认 `ready / knowledge_base / schemaVersion=4`。
6. 用户可选地通过命名参数显式给出 Backup V3 文件。脚本必须先拒绝非 V3 文件，并仅在日常十个业务集合已确认为空时恢复；未给参数时不得自动寻找或恢复任何备份。

### 日常启动与停止

- `kb-start.ps1` 仅启动 MySQL、日常 API 与 H5；若 32146 已有 UAT 或未知 API，必须拒绝，不得静默停止、切换或覆盖。
- `kb-stop.ps1` 仅终止脚本自己记录且经路径验证的 API/H5 子进程；MySQL 仅按既有 Compose stop 规则停止。
- 子进程状态和日志必须在项目外，不得记录密码、Backup 内容或个人业务数据。

## 非目标与禁止事项

- 不做全栈 Docker 化、远程访问、公网 API、代理、隧道、云同步或多机同步。
- 不复制、提交、同步或删除 `mysql-data`、实际 `.env`、数据库账号密码或个人运行数据。
- 不执行 `down -v`、删除 volume、清库、修改 Docker Compose、端口或权限。
- 不修改 API/H5 业务能力、Contracts、Application、Repository、备份格式、数据库结构、状态机、关联语义或 migration。
- 不允许 API/H5 直连数据库、双写、同步、回填、fallback 或自动重试。

## 验收标准

1. 新克隆的空目录能完成依赖检查、空库初始化、日常服务启动，并获得 `ready / knowledge_base / schemaVersion=4`。
2. 既有 `.env` 保持原样，脚本输出不泄露密码。
3. 32146 已运行 UAT 或未知 API、依赖缺失、端口冲突时稳定拒绝且不影响既有进程。
4. 显式 Backup V3 恢复可用；非 V3 与非空日常库稳定拒绝且无写入。
5. 停止操作不删除或修改 `mysql-data`，且只终止自身记录的子进程。
6. Git 忽略检查通过；实际 `.env`、`mysql-data`、日志、临时状态与 Backup 数据均不进入 Git。
7. QA 在干净目录完成一次初始化、恢复和日常启动演练；通过后再由产品验收归档。

## 交付边界

研发完成后转 QA。未经 QA 通过与产品验收，不得称“一键启动”已完成或建议用户以它迁移日常数据。
