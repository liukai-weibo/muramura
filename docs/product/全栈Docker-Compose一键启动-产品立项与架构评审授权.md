# 全栈 Docker Compose 一键启动：产品立项与架构评审授权

日期：2026-07-27
状态：已立项，待架构评审；未授权编码

## 用户问题

用户希望在另一台机器上快速运行完整项目，而不需要分别手动启动 MySQL、API 与 H5。现有 Dockerfile 只构建 H5 静态站点；现有 `docker-compose.yml` 只运行 MySQL，二者不能构成完整业务运行环境。

## 目标

在不改变业务能力与本地优先边界的前提下，评估一个由应用镜像、官方 MySQL 镜像和 Docker Compose 组成的本机一键启动方案。新机器在满足必要前置条件和本机配置后，应能以单一 Compose 命令启动 H5、API 与空库初始化后的 MySQL。

## 已冻结产品边界

- 仅限本机 Docker Compose 运行；不得开放远程访问、公网监听、反向代理、隧道、云同步或多用户能力。
- MySQL 必须继续引用官方镜像；不得把 MySQL 数据库内容打包进应用镜像。
- 应用镜像需要覆盖现有 H5 和 loopback API 的运行需要；不得只交付静态 H5 页面而宣称完整可运行。
- 首次空库仅可复用既有 migration 初始化；不得新增、修改、回滚 migration 或改变数据库结构。
- 个人业务数据仅能由用户显式提供 Backup V3 后恢复；不得复制或提交 `.env`、密码、`mysql-data`、容器 volume 或任何个人运行数据。
- 日常运行仍应使用 `knowledge_base`；UAT 继续隔离，不得被启动器停止、替换或静默切换。
- 现有 API、H5、Contracts、Application、Repository、业务对象、字段、状态机、关联、Backup V3 格式与 unknown-outcome 语义均不得因部署方式改变。

## 非目标

- 不追求单一 Docker 镜像同时承载应用与可持久化 MySQL 数据。
- 不新增线上部署、域名、HTTPS、账户、权限、监控、CI/CD、镜像仓库、自动数据同步或一键导入个人数据。
- 不以 Docker 化为由改变端口、CORS、业务路由或 API 契约。

## 架构评审需裁决

1. 最小容器拓扑：应用镜像内 API 与 H5 的进程/反向代理安排，以及官方 MySQL 服务的连接方式。
2. 允许修改的精确文件范围，尤其 Dockerfile、Compose、Nginx、启动脚本、文档与直接测试的必要性。
3. `.env` 到 Compose 环境变量的最小安全注入方式，确保密码不进入镜像、日志或 Git。
4. 空库 migration、health 就绪条件、端口占用/UAT 保护、停止行为与 Backup V3 显式恢复流程。
5. 可与用户目标匹配的最小验收：干净目录、空库启动、健康检查、Backup V3 恢复、UAT/未知端口拒绝、停止保留数据卷，以及 Git 忽略检查。

## 当前裁决

允许架构师进行只读评审和输出任务书；不允许任何代码、Docker 配置、镜像、容器、运行库或数据改动。
