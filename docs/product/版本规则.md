# Muramura 版本规则

## 目的

版本号只表达「这次改动对外是什么级别」，不再按发布次数递增。新增一个完整模块不能只升 Patch，纯 UI 打磨也不应该升 Minor。

## 三段定义

版本号形如 `MAJOR.MINOR.PATCH`。

### Patch：第三位 +1（`0.2.1 → 0.2.2`）

适用于不新增完整功能、对外能力不变的改动：

- Bug 修复；
- UI 微调：颜色、间距、字体、图标、文案、按钮位置；
- 交互摩擦优化、页面冗余删减；
- 内部重构、测试补充、依赖与构建调整；
- 数据、API、备份格式完全不变。

### Minor：中间位 +1，Patch 清零（`0.2.9 → 0.3.0`）

适用于新增「兼容的完整能力」：

- 新增一个独立模块（例如睡眠记录、情绪轮换、天气卡）；
- 新增一条完整可用流程，老数据与老入口不受破坏；
- 较大的界面改版，但旧功能仍可用；
- 一批功能迭代合并发布，而不是零散修补；
- 数据结构/API 只做向后兼容扩展。

### Major：第一位 +1，后两位清零（`0.y.z → 1.0.0`；`1.4.5 → 2.0.0`）

适用于：

- 产品核心定型、正式发布稳定版；
- 数据库结构不兼容、老记录无法读取；
- API 大改、核心流程推倒重写；
- 产品定位或底层架构彻底重构。

## 判定表

| 这次改了什么 | 升哪一位 | 示例 |
|---|---|---|
| 修一个报错、调间距、改文案 | Patch | `0.2.3 → 0.2.4` |
| 新增首页睡眠卡、完整情绪轮换 | Minor | `0.2.9 → 0.3.0` |
| 新增天气卡这类完整模块 | Minor | `0.2.9 → 0.3.0` |
| 删除/隐藏一个模块的入口 | Patch（能力暂时下线、可恢复） | `0.2.4 → 0.2.5` |
| 隐藏模块同时新增另一个完整功能 | Minor（按最高级别） | `0.2.4 → 0.3.0` |
| 备份/数据库不兼容 | Major | `1.4.5 → 2.0.0` |

多个改动合并发布时，按其中**最高**的级别升版。

## 发布检查清单

1. 判断级别并写明理由（提交信息或发布说明里写一句「Minor：新增睡眠模块」）；
2. 同步版本号：
   - `src-tauri/Cargo.toml`；
   - `src-tauri/Cargo.lock` 中 `name = "marumaru"` 的版本；
   - `src-tauri/tauri.conf.json`；
3. 构建签名安装包，拿到 `.exe` 与 `.sig`；
4. 更新仓库根 `updater.json`（version / notes / pub_date / signature / url）；
5. 提交、打 tag（`vX.Y.Z`）、推送；
6. 上传 GitHub Release 资产；
7. 在 `docs/product/当前运行事实.md` 记录版本与验证结果。

## 历史纠正

- `0.1.49 → 0.1.50` 包含睡眠系统这类完整模块，按本规则应属于 **Minor**，不是 Patch；
- 从本规则启用起，新增完整模块一律升 Minor；只有修补与打磨才升 Patch；
- 当前待发布批次包含「情绪轮换」这一完整功能，下一版定为 **`0.2.0`**（Minor，Patch 清零）。
