# 探索主线 V1.1.5：子项改名低摩擦交互产品任务书

日期：2026-07-27

## 用户问题

子项改名依赖“保存 / 取消”双按钮，完成一次小改名的操作成本偏高。

## 目标

保留用户对写入结果的知情与保护，同时减少完成改名所需的显式操作。

## 冻结产品规则

- 点击“改名”后进入编辑态，移除“取消”按钮，仅保留“保存”。
- 点击“保存”或点击当前改名编辑区外，均触发同一单次保存动作。
- 不得通过定时器、单纯 input `blur`、窗口关闭或浏览器卸载自动写入。
- 点击主线切换、导航或会改变上下文的控件时，具体行为须由架构确认；不得以旧上下文、旧请求或本地推断写入新上下文。
- 保存失败或结果未知时，保留原输入与编辑态；不得伪造成功、自动重试或静默丢弃输入。用户仅能明确再次保存或显式重读确认。
- 保存成功后才退出编辑态并展示服务端确认的名称。

## 非目标

- 不新增自动草稿、批量改名、键盘快捷写入、路由、字段、状态、对象或关系。
- 不改变探索主线的删除、恢复、关联、历史或 unknown-outcome 既有语义。

## 架构评审与产品编码授权

- 架构结论：有条件可行；仅复用既有冻结 `PATCH /exploration-tracks/:id` 改名契约。
- 编辑区外 pointer 点击与保存按钮调用同一个单次保存函数。
- 编辑区外首次点击主线切换、导航或其他上下文控件时，必须消费该点击：只保存当前冻结主线，不执行原点击动作，也不得在成功后自动补执行。
- 实现绑定 `editingTrackId` 与会话序号；旧响应不得影响新上下文。不得使用 timer、单纯 blur、窗口关闭或卸载自动写入。

## 授权范围

- `apps/client/src/pages/index/exploration-prototype.tsx`
- 直接前端测试
- 必要 QA / 产品记录与当天贡献记录

## 明确禁止

- `api-client.ts`、`index.tsx`、样式、API、DTO、Application、Repository、Contracts、Migration、配置、数据库、备份及其他业务语义修改。
- 自动重试、自动补执行被消费的外部点击、自动草稿或任何新写入契约。

## 验收标准

- 普通改名可通过保存按钮或编辑区外点击完成，且仅发出一次既有改名请求。
- 切换主线或导航不会造成错对象写入、重复写入或草稿静默丢失。
- 失败、503、Abort、响应丢失和过期请求均保留编辑输入，不自动重试或伪造成功。
- 不引入 API、DTO、Application、Repository、Contracts、数据库、状态机、迁移、配置或业务语义扩张。
