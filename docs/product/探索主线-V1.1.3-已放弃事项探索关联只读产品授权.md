# 探索主线 V1.1.3：已放弃事项探索关联只读产品授权

日期：2026-07-27

## 产品裁决

架构评审结论为“有条件可行”。现授权实施已放弃事项的探索主线关联只读展示和 Repository 硬门禁；本授权不包含 V1.1.4 启动动作覆盖。

## 规则

- 当前事项结构化 `status` 为 `abandoned` 时，继续展示 API 返回的真实探索主线关联事实。
- `abandoned` 时不得显示或启用“调整”“移除”“归入”及关联选择器入口。
- 仅当真实刷新结果已为 `idea_to_try`，恢复既有可调整、移除或归入能力。
- `track-deleted`、`unavailable` 与 unknown-outcome 的既有只读、草稿保留和不自动重试规则保持不变。

## 授权范围

- `apps/client/src/pages/index/item-exploration-state.ts`
- `apps/client/src/pages/index/index.tsx`
- `apps/client/src/pages/index/index.scss`（仅“查看已放弃记录”与“探索历史”字号一致性）
- `packages/storage-mysql/src/**`
- `tests/exploration-h5-visual.test.ts`
- 与 MySQL Repository 硬门禁直接对应的 `tests/**`
- 必要 QA/产品记录与当天贡献记录

## 明确禁止

- API、DTO、Application、Contracts、数据库、状态迁移、migration、备份、配置或业务写入语义的任何修改。
- 新增对象、字段、状态、关系、路由、缓存、重试、fallback 或本地成功推断。

## 验收

- 覆盖 `abandoned` 下 `available`、`no-association`、`track-deleted`、`unavailable` 四种关联事实。
- 覆盖真实刷新为 `idea_to_try` 后恢复入口。
- 覆盖 MySQL Repository 在事务锁定事项后，对 abandoned 关联调整与移除稳定返回既有 `400 VALIDATION_FAILED + requestId`，且零写入。
- 覆盖竞态硬门禁及 unknown-outcome 回归。
- 定向测试、typecheck、build:h5 与 `git diff --check` 通过。
