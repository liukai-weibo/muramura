# 探索主线 V1 S3：可信运行时接入产品范围冻结

> 冻结日期：2026-07-24
>
> 状态：**产品范围冻结；待架构评审；当前禁止 S3 编码。**
>
> 依据：`当前运行事实.md`、`探索主线-V1-产品评审结论.md`、`探索主线-V1-API契约产品确认结论.md`、`探索主线-V1-设计冻结正式验收结论.md`、`探索主线-V1-S1-Schema004与基础Contracts封板结论.md`、`探索主线-V1-S2-RepositoryApplication与原子工作流封板结论.md`。

## 【结论】

启动探索主线 V1 的 S3 产品立项。S3 是一次性将已封板的 S1 / S2 可信能力接入现有运行闭环的交付阶段：

```text
Backup V3
→ API 路由与稳定错误语义
→ H5 从原型 fixture 切换至真实 API 读模型
→ 浏览器级 UAT
```

S3 不新增探索主线业务语义；它只将已冻结的主线、事项 `0..1` 关联、软删除、原子创建、结构化读模型与诚实降级能力暴露给用户。

## 【目标】

用户可在当前 H5 通过 loopback API 使用探索主线 V1 的完整已冻结闭环：

- 创建、改名、软删除、恢复探索主线；
- 快速捕获时选择已有主线，或暂存新主线名称并在提交事项时原子创建并归入；
- 在事项详情查看、调整或移除允许调整的主线关联；
- 查看主线当前关联事项、探索历史、已放弃记录和已删除主线历史；
- 通过 JSON Backup V3 安全导出和恢复探索主线与事项关联；
- 在 API / 网络异常与 unknown-outcome 下不伪造成功，不自动重试，并重新读取真实事实确认。

## 【范围】

### 1. Backup V3

- 新增 `BackupDocumentV3` / `explorationTracks`；
- V1 / V2 导入时，主线集合和事项主线关联安全降级为空，不失败、不猜测、不回填；
- V3 导出保留主线、软删除状态和 Item `explorationTrackId`；
- V3 断裂引用、非法 ID / 名称 / 规范名 / 时间、名称冲突或既有集合不可信时，事务前整体拒绝，十个业务集合零写入；
- `replaceData()` 对十个业务集合保持单一 MySQL DML transaction，末端失败整体回滚；
- `system_metadata` 不导出、不清理、不恢复、不覆盖。

### 2. API

只实现已确认的 API 路由矩阵、DTO、body 限制、错误码与 unknown-outcome 策略：

```text
GET    /api/v1/exploration-tracks
GET    /api/v1/exploration-tracks/selectable
GET    /api/v1/exploration-tracks/deleted
GET    /api/v1/exploration-tracks/:id/history
POST   /api/v1/exploration-tracks
PATCH  /api/v1/exploration-tracks/:id
DELETE /api/v1/exploration-tracks/:id
POST   /api/v1/exploration-tracks/:id/restore

POST   /api/v1/items（仅扩展 explorationTrack 可选选择）
GET    /api/v1/items/:id/exploration-track
PUT    /api/v1/items/:id/exploration-track
DELETE /api/v1/items/:id/exploration-track
GET    /api/v1/items?status=<冻结状态>&explorationTrackId=<id>
```

稳定错误语义固定为：`VALIDATION_FAILED`、`NOT_FOUND`、`CONFLICT`、`MYSQL_SCHEMA_NOT_READY`、`MYSQL_UNAVAILABLE`、`INTERNAL_ERROR`，并保留既有 `413`、`415`、`405` 与 `NOT_FOUND_ROUTE`。失败响应脱敏并包含 `requestId`。

### 3. H5 真实接入

- 用 API Client / Adapter 取代探索主线原型 fixture；不得直连 MySQL、IndexedDB 或 SQLite；
- 逐项解除控件禁用，只调用已冻结 API；
- 显示真实 loading、空态、读取失败、结构化业务错误、已删除和 unavailable 降级；
- unknown-outcome 时保留草稿，但禁止自动重试、禁止按本地输入判断成功或失败；仅重新读取真实 API 数据；
- 保护用户明确输入和选择，旧请求、默认值、列表刷新不得覆盖当前草稿或关联选择；
- 前端不得从标题、时间、状态文案、计数、历史或缓存推断关系、当前事项、历史或复盘摘要。

### 4. 一次浏览器 UAT 与回归

在隔离 `knowledge_base_uat` 完成：

- 主线生命周期；
- existing / new 关联捕获及取消零写入；
- 已删除 / unavailable 关联的诚实降级与拒绝写入；
- 当前关联事项、定位跳转、历史与已放弃记录；
- JSON V1 / V2 / V3 导出、清库、恢复及失败恢复零写入；
- API / MySQL 重启、`MYSQL_UNAVAILABLE`、unknown-outcome；
- 运行库隔离与无 IndexedDB fallback。

## 【验收标准】

1. Backup V3 保持 V1 / V2 安全降级、V3 关系保留、断裂关系整体拒绝和十集合原子恢复；
2. API 只暴露冻结路由和错误语义，不泄露底层信息，不新增任意筛选、计数或管理能力；
3. H5 不再使用探索主线 fixture，所有显示与操作来自真实 API 结构化读模型；
4. 所有写入由 API → Application → MySQL 完成，H5 不直接操作 MySQL 或底层 Repository；
5. 浏览器 UAT 在 `knowledge_base_uat` 通过，日常 `knowledge_base` 前后快照不变；
6. 不出现 IndexedDB / MySQL 双写、同步、回填或 fallback；
7. 本阶段完成后，探索主线 V1 才可进入最终 QA 与产品验收；构建通过不替代 UAT。
