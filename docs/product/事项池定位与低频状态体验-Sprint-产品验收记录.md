## 一、验收结论

本 Sprint 已完成并封板。

本轮修复事项自动定位默认落入“全部事项”的问题，补齐快速捕获打开后的输入焦点，并为低频但有效的“已放弃”状态提供不干扰日常运行阶段的可见入口。

```text
自动定位事项
→ 进入事项真实状态对应的池
→ 不再默认跳到全部事项

快速捕获打开
→ 一句话输入框自动聚焦

活跃事项存在已放弃记录
→ 更多状态
→ 已放弃低频决策档案
```

## 二、已验收能力

### 1. 真实状态池定位

- 系统自动定位事项时，使用事项真实 `status` 切换筛选池并基于该状态列表计算页码。
- 快速捕获创建“想试试”后定位至“想试试”；创建“以后再说”后定位至“以后再说”。
- 从方法发起行动后定位至“想试试”。
- 非行动模块创建后保持原模块；用户点击 Toast 的“查看事项”后，才进入新事项真实状态对应的池。
- 搜索、仪表盘与历史定位不再无条件落入“全部事项”。
- “全部事项”只作为用户主动横向浏览的入口，不再作为系统自动定位默认值。

### 2. 快速捕获输入焦点

- 顶部“＋快速捕获”与行动模块“＋捕获”共用同一自动聚焦逻辑。
- 浮层打开并完成 H5 DOM 渲染后，焦点进入“一句话记录你想做什么”输入框，用户可直接输入。
- 恢复锁定、搜索与捕获互斥、草稿放弃确认及创建失败保留草稿等既有保护不受影响。

### 3. 已放弃低频决策档案

- “已放弃”保留为真实历史决策状态，不与“以后再说”“已暂停”或回收站混同。
- 仅当活跃事项中存在已放弃记录时，事项池显示低强调“更多状态”入口。
- 菜单当前仅包含“已放弃（n）”，不混入全部事项、回收站、归档、停用或新状态。
- 进入后只读取活跃事项中的已放弃状态，标题为“已放弃 · n 件”，并提供“返回运行阶段”。
- 返回运行阶段回到“想试试”第一页，不进入全部事项。
- 本轮未新增“重新启动”或任何已放弃状态迁移；既有可信操作保持不变。

### 4. 回收站隔离与草稿保护

- 回收站上下文仅展示删除后 30 天恢复语义，不显示更多状态、已放弃视图或返回运行阶段。
- 回收站数据源与活跃已放弃事项数据源严格隔离。
- 进入已放弃、返回运行阶段均经过未保存复盘草稿保护；用户未确认放弃草稿时不切换上下文。

## 五、范围确认

本轮仅调整前端页面的事项池筛选、自动定位、局部菜单与捕获输入焦点行为。

本轮未修改：

- Application / Repository、事项状态机或创建写入语义；
- Schema、Migration、JSON 备份格式；
- 已放弃事项的历史迁移、重命名或重新启动能力；
- 回收站数据生命周期与方法生命周期治理语义。

## 六、封板结论

事项池定位与低频状态体验 Sprint 已完成并关闭。

“已放弃”状态是否在长期进一步收敛仍保留在需求池观察；在新的真实使用证据出现前，不得通过前端自动迁移、隐藏或合并该状态。
