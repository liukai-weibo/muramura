## 一、评审结论

Layout Sprint 2 可以进入实施，但必须按以下顺序：

```text
最小只读证据详情能力
→ 自动化测试通过
→ UI 实施方法工作台与复盘交互
→ 产品验收
```

原因：方法详情的“来源与验证证据”需要完整、结构化且可诚实表达关系类型的数据。页面不得自行读取多个存储表并猜测关系，也不得用文案、时间或版本号推断。

批准的最小底层变更仅限于：

- Contracts：增加只读方法证据详情类型与查询契约。
- Application：增加只读查询入口。
- Repository：实现按方法读取证据详情的关联查询。

明确不变：

- Domain 与事项状态机。
- 方法形成、验证、修订写入语义。
- IndexedDB Schema、Migration 和索引。
- JSON 备份格式。
- 备份恢复流程。
- 路由、全局状态库和后端服务。

## 二、五项产品裁决

### 决策 1：历史关系未知

**裁决：采纳。**

早期迁移数据无法可靠还原形成、仅验证或修订关系时，展示：

```text
历史证据
关系类型无法从旧数据中确定
```

规则：

- 不得以时间、文案、当前版本或验证次数猜测关系。
- `unknown` 是对历史数据能力的诚实表达，不是错误状态。
- 不启动人工数据校正项目。
- 不为补历史语义新增持久化字段或迁移。

### 决策 2：来源方法事项允许切换验证方法

**裁决：采纳方案 B。**

事项由方法 A v1 发起时：

```text
默认验证：方法 A
实际使用版本：v1
```

用户允许改为验证方法 B，但切换后必须持续明确展示：

```text
本事项由「方法 A」v1 发起
本次复盘将验证「方法 B」
```

并在首次切换为非来源方法时展示中性提示：

```text
你选择的方法不是本次行动的来源方法。
本次复盘会为所选方法增加证据，原方法应用关系保持不变。
```

规则：

- 方法应用关系继续代表实际行动来源，不得被覆盖或改写。
- 本次复盘证据只关联用户最终选择的验证方法。
- 用户取消验证时不增加任何方法证据、次数或版本。
- 提示不是阻断确认，不增加额外审批流程。

### 决策 3：方法局部搜索排除当前方法

**裁决：采纳方案 A。**

当前选中方法被局部搜索排除时：

```text
清除工作台当前选择
→ 右侧展示未选择状态
```

不保留左侧没有选中项、右侧却展示隐藏方法详情的状态。

清空局部搜索后：

- 当前选择仍为空。
- 右侧维持未选择状态，或由技术方案的首次进入规则选择当前排序第一条。
- 不尝试恢复一个隐藏选择，避免增加不透明状态。

外部定位优先于局部搜索：全局搜索和仪表盘定位方法时，自动清空阻挡目标的局部搜索词并选中目标。

### 决策 4：仪表盘修订下钻的版本精度

**裁决：采纳方案 A。**

本轮最低承诺：

```text
仪表盘修订下钻
→ 正确定位所属方法
```

只有当下钻记录拥有可靠的结构化版本号时，才展开和定位具体版本。

禁止继续从展示文案解析版本号。若现有记录没有结构化版本号：

- 不伪造精确版本定位。
- 不修改 Dashboard 契约以追求本轮精确版本定位。
- 继续显示正确方法详情即可。

全局搜索命中历史版本仍必须准确定位该版本。

### 决策 5：取消默认验证后的记忆范围

**裁决：采纳方案 A。**

用户取消来源方法默认验证后：

- 在当前页面会话内按事项 ID 记住该明确选择。
- 数据刷新、切换模块、切换到其他事项再返回，都不得重新自动选中验证。
- 浏览器刷新后允许重新应用默认建议。
- 不新增持久化草稿。

产品原则：系统默认值用于减少重复输入，不能覆盖用户已经明确做出的取消决定。

## 三、补充产品约束

### 1. 证据关系读模型

只读详情至少应返回：

- 方法 ID。
- 证据 ID。
- 复盘 ID。
- 所属事项 ID 与标题。
- 复盘时间。
- 必要复盘摘要。
- 关系类型：形成、仅验证、修订、历史关系未知。
- 对应版本号（若可靠）。

页面只消费该结构化结果，不自行判断关系。

### 2. UI 实施不得提前开始依赖部分

UI 可以并行准备不依赖证据详情的静态结构，但以下内容必须在只读能力与测试完成后接入：

- 完整来源与验证证据区。
- 形成 / 验证 / 修订 / unknown 关系标签。
- 证据反向定位事项复盘。

### 3. PRD 中的底层边界更新

`Layout-Sprint-2-PRD.md` 中“除表现层外不修改 Contracts / Application / Repository”的原预期，现根据技术评审更新为：允许为完整证据详情增加**最小只读查询能力**；不允许修改任何写入语义和持久化结构。

## 四、实施流转

```text
阶段 A：数据 / 应用实现
→ 只读证据详情契约、查询实现、自动化测试
→ 架构核验

阶段 B：前端 / UI 实施
→ 方法列表—详情
→ 复盘两项方法动作
→ 来源方法默认验证
→ 流转历史抽屉
→ 集成证据详情

阶段 C：产品验收
→ 自动化验证
→ KKK 人工 UAT
→ Sprint 2 封板
```

## 五、暂停条件

任一情况发生必须停止并回流产品 / 架构：

1. 只读证据详情无法在不改 Schema 的前提下实现。
2. 新查询需要更改方法写入、验证次数或版本生成语义。
3. 来源方法默认验证无法避免覆盖用户草稿。
4. 需要修改备份格式或恢复流程。
5. UI 需要依赖非结构化文案推断版本或证据关系。
6. 范围进入关系型搜索、Dashboard 契约扩展或 Layout Sprint 3。
