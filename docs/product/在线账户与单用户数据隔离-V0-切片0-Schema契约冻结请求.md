# 在线账户与单用户数据隔离 V0：切片 0 Schema 契约冻结请求

日期：2026-07-29  
状态：阻断切片 0 实施；仅允许架构师只读裁决

## 已冻结产品边界

- 账户仅服务于注册、登录、退出和单用户数据隔离；不引入角色、团队、共享或协作。
- 十个业务集合必须拥有可信的归属字段；现有业务读写语义在切片 0 不得改变。
- 密码与会话秘密均不得以明文、可逆密文或可直接重放值存储、输出或写入日志。
- 初始归属 claim 是独立受控能力，不得在切片 0 自动执行。
- 任何 migration 和测试仅能在随机独立临时数据库执行；日常库、UAT 与云端运行库禁止触碰。

## 待架构冻结的最小 Schema 契约

1. `users`：主键、登录标识列、密码哈希列、时间列、精确 SQL 类型/长度、唯一约束及命名。
2. `user_sessions`：主键、用户外键、会话秘密安全表示、过期/失效/创建时间、精确 SQL 类型/长度、唯一约束、索引、外键删除策略及命名。
3. `initial_owner_claims`：主键、关联用户列、时间列、单例或每用户唯一规则、精确约束/索引/外键删除策略及命名。
4. 十个业务集合：`owner_user_id` 的 NULL 规则、回填前后约束策略、外键删除策略，以及逐表索引名称和列顺序。
5. Storage owner scope：切片 0 只增加类型/连接基础设施，或 Repository 即刻接受 scope；无论何者，明确不得改变现有读写结果或先行开启隔离。
6. 密码与会话秘密：明确采用的哈希/KDF、编码形式和字段长度；若会话仅存摘要，明确摘要算法、随机原始秘密的最小熵及存储边界。

## 当前裁决

现有 migration 草案不得合入、不得运行、不得转 QA。切片 1–5 继续不得开始。架构冻结记录完成并经产品确认后，才恢复切片 0 编码授权。
