# Layout Sprint 1 PRD：应用骨架重构

> 状态：待 KKK 确认后进入研发。
>
> 上位依据：`功能清单-v2.md`、`整体布局设计-v1.md`、`产品经理工作基线-v1.md`。
>
> 本轮只重组页面与导航，不修改已验收业务规则、数据语义、备份格式和应用用例。

## 一、产品结论

当前 `v0.1.0` 核心闭环已经成立，现阶段最大产品问题不是功能缺失，而是所有能力堆积在同一长页面：

```text
搜索
→ 仪表盘
→ 快速捕获
→ 事项池
→ 备份恢复
→ 方法库
```

用户需要依靠纵向滚动寻找工作上下文，高频行动、周期观察、方法资产和低频数据治理混在一起。随着真实数据增加，该结构会持续恶化。

本轮目标：

> 将“单页功能演示”升级为“按工作上下文切换的个人系统工作台”。

本轮不是视觉翻新，也不是业务重构。

## 二、成功标准

完成后必须满足：

1. 用户进入系统后直接处于“行动”工作上下文。
2. 用户不需要通过长页面滚动寻找搜索、方法、观察或备份能力。
3. 行动、方法、观察、数据与设置四个模块边界清晰。
4. 所有 `v0.1.0` 已验收功能仍可到达、操作且结果不变。
5. 搜索结果、仪表盘下钻能够自动切换模块并定位目标记录。
6. 本轮不改变业务状态机、复盘字段、方法规则和备份格式。

## 三、范围

### 本轮必须完成

- 建立桌面端应用骨架。
- 增加左侧一级导航。
- 增加顶部全局栏。
- 建立行动、方法、观察、数据与设置四个模块。
- 将现有功能区块移动到对应模块。
- 行动作为默认模块。
- 全局搜索和快速捕获在任意业务模块可到达。
- 保持搜索、仪表盘下钻和方法定位能力。
- 移除 Sprint 演示式标题和大 Hero。
- 提供四个模块的空状态、加载状态和错误反馈基线。

### 本轮明确不做

- 不重构事项内部业务逻辑。
- 不重构复盘表单字段。
- 不把方法卡片改成完整列表—详情工作台；留给 Layout Sprint 2。
- 不把搜索改成完整顶部浮层；允许第一轮先复用现有搜索结果展示。
- 不把快速捕获改成完整折叠面板；允许第一轮先移动入口并复用现有表单。
- 不完成平板和移动端最终响应式；留给 Layout Sprint 3。
- 不增加标签、分类、排序、计划、AI、附件或云同步。
- 不修改 Domain、Application、Repository、IndexedDB Schema 和备份格式。

## 五、应用骨架

### 桌面端结构

```text
┌──────────────┬────────────────────────────────────────────┐
│ 个人系统     │ 当前模块         搜索        ＋ 快速捕获  │
│              ├────────────────────────────────────────────┤
│ ● 行动       │                                            │
│   方法       │                                            │
│   观察       │                 当前模块内容               │
│              │                                            │
│ 数据与设置   │                                            │
│              │                                            │
│ ● 本地正常   │                                            │
└──────────────┴────────────────────────────────────────────┘
```

### 左侧导航

一级入口：

1. 行动
2. 方法
3. 观察
4. 数据与设置

规则：

- 行动、方法、观察属于业务模块。
- 数据与设置作为低频治理模块，与前三项视觉分组。
- 当前模块必须有明确选中状态。
- 左侧底部只显示简洁的本地状态，不放完整备份操作。
- 一级导航不展示复杂统计，避免成为第二个仪表盘。

建议文案：

```text
个人系统

行动
方法
观察

数据与设置

本地数据正常
```

### 顶部全局栏

必须包含：

- 当前模块标题。
- 全局搜索入口。
- 快速捕获入口。

规则：

- 在行动、方法、观察三个业务模块中持续可见。
- 在数据与设置模块中仍可访问，但不能遮挡恢复确认等高风险操作。
- 移除当前 Sprint 标识、营销式口号和大标题。
- 当前模块标题用于说明工作上下文，不用于重复产品理念。

## 六、模块需求

### 1. 行动

目标：处理具体事项，是默认首页和最高频工作区。

本轮承载现有：

- 状态筛选。
- 回收站入口。
- 事项列表与分页。
- 事项详情。
- 状态操作。
- 方法应用上下文。
- 状态流转历史。
- 待复盘与已复盘内容。

本轮规则：

- 默认进入“想试试”筛选，维持当前已验收行为。
- 从搜索或观察定位事项时，允许系统清除默认筛选并选中目标事项。
- 删除等危险操作继续与主操作分开。
- 本轮不强制重新设计事项列表—详情，只要求功能被正确归入行动模块且不再与仪表盘、备份、方法库纵向混排。

### 2. 方法

目标：查看方法资产、证据和版本，并用方法发起新行动。

本轮承载现有：

- 方法卡片。
- 方法版本历史。
- 来源复盘证据。
- 用方法发起行动。

本轮规则：

- 暂时允许沿用现有方法卡片结构。
- 从搜索或观察定位方法时，必须切换到方法模块并定位目标方法。
- 版本历史和方法应用规则保持不变。
- 列表—详情重构不在本轮完成。

### 3. 观察

目标：按周期观察事实、堵塞和方法复利，并下钻定位。

本轮承载现有：

- 7 天、30 天、全部时间窗口。
- 七类运行指标。
- 当前堵塞。
- 方法复利。
- 事实提示。
- 指标下钻结果。

本轮规则：

- 仪表盘进入观察模块后默认展开，不再作为行动页折叠卡片。
- 时间窗口切换与下钻结果必须使用同一统计口径。
- 点击堵塞状态：进入行动模块并应用对应状态筛选。
- 点击事项记录：进入行动模块并选中目标事项。
- 点击方法记录：进入方法模块并定位目标方法。

### 4. 数据与设置

目标：管理低频但高风险的数据安全操作。

本轮承载现有：

- 当前有效事项、当前方法和回收站数量。
- 完整 JSON 导出。
- 选择备份文件。
- 恢复前安全备份。
- 恢复确认、结果和错误说明。

本轮规则：

- 数据状态和备份恢复不再常驻行动页面。
- 恢复前安全备份规则不得因移动模块而改变。
- 安全备份失败时仍必须禁止覆盖。
- 恢复操作必须保留高风险视觉提示和二次确认。

## 七、跨模块定位规则

跨模块定位是本轮核心验收项，不允许只完成“模块切换”。

### 定位事项

```text
搜索结果 / 仪表盘下钻
→ 切换到行动
→ 退出回收站或清除不兼容筛选
→ 选中目标事项
→ 目标事项详情可见
```

### 定位复盘

```text
搜索结果
→ 切换到行动
→ 选中所属事项
→ 复盘区域可见或获得定位提示
```

### 定位方法

```text
搜索结果 / 方法复利 / 指标下钻
→ 切换到方法
→ 定位目标方法
→ 必要时展开命中的历史版本
```

### 定位堵塞状态

```text
观察模块堵塞条目
→ 切换到行动
→ 应用目标状态筛选
→ 展示对应事项
```

## 八、页面状态规则

每个模块至少处理以下状态：

| 状态 | 产品要求 |
|---|---|
| 加载中 | 告知正在读取本地数据，不能误显示为空 |
| 空数据 | 说明当前没有什么，并给出符合模块目标的下一步 |
| 操作中 | 防止重复提交，保留明确反馈 |
| 成功 | 反馈操作结果，并刷新到正确上下文 |
| 错误 | 说明失败动作；可重试时给出重试入口 |
| 目标不存在 | 搜索或下钻定位失败时说明记录可能已删除，不停留在错误选中状态 |

空状态建议：

- 行动 / 想试试为空：`还没有想试试的事项，可以快速捕获一个想法。`
- 方法为空：`还没有形成方法。先完成真实行动和复盘，不必为了填满方法库而创建。`
- 观察无周期数据：`该时间窗口还没有运行记录。`
- 数据与设置：不使用空状态隐藏备份入口。

## 九、交互约束

1. 切换一级模块不应清空当前未提交表单；如技术上必须清空，应先提示用户。
2. 搜索或下钻跨模块定位优先于目标模块原有筛选上下文。
3. 用户手动返回模块时，应尽量保留上次选中对象和筛选，减少重复定位。
4. 高风险恢复确认不能被普通模块切换意外绕过。
5. 模块切换不产生业务数据和状态事件。
6. 本轮不能为了布局方便复制事项、复盘或方法数据。
7. 页面刷新后默认进入行动模块和“想试试”；其他导航持久化不作为本轮必须项。

## 十、研发交付拆分建议

### L1-01 应用外壳

- 左侧导航。
- 顶部全局栏。
- 四模块容器。
- 默认行动模块。
- 移除旧 Hero。

验收：四模块可切换，当前模块明确，旧功能暂不丢失。

### L1-02 现有功能归位

- 事项相关内容移入行动。
- 方法相关内容移入方法。
- 仪表盘移入观察。
- 备份恢复移入数据与设置。

验收：不通过长页面滚动寻找一级功能；每项能力只出现在正确模块。

### L1-03 全局入口

- 搜索入口进入顶部全局栏。
- 快速捕获入口进入顶部全局栏。
- 第一轮可复用现有表单和结果组件。

验收：任意业务模块可开始搜索和捕获，已有输入规则不变。

### L1-04 跨模块定位

- 搜索定位事项、复盘和方法。
- 仪表盘下钻定位事项和方法。
- 堵塞状态跳转行动筛选。

验收：目标模块、筛选和选中对象同时正确。

### L1-05 状态与回归验收

- 模块加载、空状态、错误状态。
- 未提交表单保护。
- 全部 `v0.1.0` 主路径回归。

验收：不存在因为页面归位造成的核心闭环中断。

## 十二、封板条件

以下条件同时成立，Layout Sprint 1 才可封板：

1. 四模块工作台正式替代单页长页面。
2. 所有 `v0.1.0` 功能回归通过。
3. 搜索、仪表盘与方法的跨模块定位通过。
4. 备份恢复业务规则无回归。
5. 未修改业务状态机、核心表单语义和备份格式。
6. 没有混入 Layout Sprint 2、Layout Sprint 3、AI 或第二阶段方向层需求。

## 十三、后续但不属于本轮

Layout Sprint 1 封板后，按顺序评估：

1. Layout Sprint 2：方法列表—详情工作台。
2. Layout Sprint 3：顶部搜索浮层、折叠捕获、视口工作区和响应式。
3. 真实使用验证后再决定观察增强和 AI 能力。
