探索主线 V1 设计冻结稿已按产品确认的 API 契约完成修订。原设计冻结验收结论中列出的三项阻断均已关闭，设计冻结正式通过。

## 【三项阻断关闭确认】

### 1. 快速捕获“创建并归入”：通过

设计稿第 6.3 节已明确：新主线名称在输入、切换选择、打开选择层、确认选择或取消选择时都只是未提交表单数据，零业务写入。

仅当用户点击“加入想试试”或“加入以后再说”时，才调用一次 `POST /api/v1/items`。该请求以单一原子事务完成主线、事项、初始状态事件和关联；全部成功后才显示成功。失败保留事项输入、新主线名称和初始状态，未知写入结果不自动重试且必须重新读取真实 API 数据确认。

独立“新建探索主线”入口仍可创建空主线，未与快速捕获语义混淆。

### 2. 当前关联事项读模型：通过

设计稿已将当前关联事项的唯一来源冻结为：

```text
GET /api/v1/exploration-tracks/:id/history
→ currentAssociatedItems
```

设计明确固定状态顺序 `doing → idea_to_try → idea_later → paused`、每状态最多 3 条、空态“还没有关联行动。”，以及仅在 API 返回 `hasMore + moreLocator` 时显示状态定位入口。

该入口使用 `moreLocator` 调用受限 Items 查询并重新读取真实事项。前端不得从历史、本地缓存、标题、时间或状态文案自行筛选、截断、排序或推断；未引入事项数量、完成率、进度、计划或日期。

### 3. 已删除主线管理：通过

设计稿已将已删除主线管理的唯一来源冻结为：

```text
GET /api/v1/exploration-tracks/deleted
```

设计明确只读、按 `deletedAt DESC, id ASC` 展示，不显示数量，不进入活跃主线列表或选择器，不提供永久删除。已删除主线详情只允许查看历史与恢复；不允许主线内捕获、改名或关联调整。

## 【范围确认】

本轮仅修订设计文档，未新增或变更以下业务语义：

- 探索主线仍是长期行动事实历程，不是项目、计划、进度或 Todo 容器；
- 一个事项仅可关联 0 或 1 条主线；
- 关联仅由用户明确建立、调整或移除；
- 主线仅软删除与恢复，不做物理永久清理；
- 不新增进度、完成率、事项计数、计划、日期、提醒、子任务、看板、自动下一步、AI 推荐或自动关联；
- 不改变事项状态机、复盘工作流、方法语义、回收站、备份取舍或运行数据源边界。

## 【阶段门与后续授权】

设计正式冻结不等于允许实施。

当前仍处于 MySQL 快速接入 Sprint。其浏览器级完整主流程、JSON 导出—清库—恢复、API / MySQL 重启后页面验证、写入失败阻断根因修复与复验尚未完整封板。

因此：

- 当前正确口径仍为“MySQL 是当前 H5 运行数据源”；
- 当前禁止探索主线的任何数据层、API 或前端业务编码；
- 在 MySQL 快速接入 Sprint 正式封板后，架构师须补齐并确认 `004 Migration`、`Backup V3`、Application / Repository / API 自动化测试实施任务书；
- 上述前置全部完成后，才可流转数据 / Application / Repository 工程师实施；前端继续等待结构化能力与 API 实现完成后再进入实施。
