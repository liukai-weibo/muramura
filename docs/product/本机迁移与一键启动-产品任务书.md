# 本机迁移与一键启动：产品任务书

日期：2026-07-27

## 用户问题

用户更换电脑后，需要在不暴露凭据、不复制运行数据库目录的前提下，尽快恢复项目与个人数据，并在之后以一条本机命令启动。

## 目标

将换机流程收敛为“代码拉取、受控初始化、Backup V3 恢复、日常一键启动”四步，不要求用户手工拼接环境变量和多个终端命令。

## 冻结产品流程

1. 新机器通过 Git 获取代码，不包含运行数据或实际凭据。
2. 本机初始化动作检查 Node、Corepack、Docker 与依赖；从示例生成本机 `.env`，要求用户自行填写本机密码；启动本机 MySQL、执行必要迁移并通过健康检查。
3. 用户通过既有 Backup V3 恢复个人数据；Backup 文件由用户自行携带，不进入 Git 或 Docker 镜像。
4. 日常启动动作只启动既有本机 MySQL、loopback API 与 H5，并明确验证 API 实际为 `knowledge_base`；不自动执行恢复、不自动切换 UAT、不重写数据。

## 非目标

- 不上传或同步 `mysql-data`、`.env`、密码、个人导出文件或运行数据库。
- 不增加远程访问、云同步、登录、多设备协作、0.0.0.0、反向代理或隧道。
- 不改变 Backup V3 格式、业务 API、H5 业务功能、数据库语义、migration 内容或 UAT 流程。
- 不要求首期完成完整 Docker Compose 应用化。

## 验收标准

- 新机器可按一份 Windows 文档完成初始化，并由脚本清晰报告缺失前置条件与下一步。
- 日常启动为单一明确动作，health 确认为 `ready / knowledge_base / schemaVersion=4` 后才提示可打开 H5。
- Git 与镜像中不包含实际 `.env`、密码、运行数据或个人 Backup 文件。
- 本机运行入口继续仅限 `127.0.0.1:10086` 与 `127.0.0.1:32146`。

## 待架构裁决

- 最小脚本边界、Windows 下 `.env` 的安全加载方式及进程生命周期处理。
- 初始化时迁移的安全门，以及与日常启动动作的严格分离。
- 是否只提供前置条件检测，还是允许脚本调用系统包管理器安装 Node / Docker。
