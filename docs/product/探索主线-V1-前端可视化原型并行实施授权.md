# 探索主线 V1：前端可视化原型并行实施授权

> 授权日期：2026-07-24
>
> 结论：**授权与 S2 并行实施前端可视化原型；不授权前端业务能力。**
>
> 依据：`当前运行事实.md`、`探索主线-V1-设计冻结正式验收结论.md`、`探索主线-V1-S2-RepositoryApplication编码授权.md`、`../design/探索主线-V1-交互与视觉设计冻结.md`。

## 【目标】

在 S2 的 MySQL Repository / Application 实施期间，前端可先将探索主线 V1 已冻结的页面结构和视觉状态落地为可见原型，供用户直接查看信息层级、页面节奏、桌面 / 小屏布局和空态表达，并据此收集真实使用灵感。

本授权的目的为缩短反馈周期，不是绕过 API 契约或提前上线探索主线业务能力。

## 【允许范围】

允许在 `apps/client/src/**` 内实现以下纯展示、无业务写入的内容：

- 工作台一级低频导航入口与页面壳；
- 桌面端主线列表—详情布局、小屏列表—全屏详情—返回层级；
- 已冻结的标题、说明、间距、截断、滚动、视觉层级与响应式规则；
- 静态或本地 fixture 驱动的主线列表、详情、当前关联事项、探索历史、已放弃收纳；
- 空态、加载态、读取失败态、已删除主线只读态与不可用关联降级态；
- 创建、改名、删除、恢复、归入主线等 UI 外观，可展示为禁用、只读或“功能准备中”；
- 纯展示切换，例如列表 / 详情、小屏返回、已放弃记录展开收起；
- 原型反馈所需的视觉微调，但不得扩张业务对象或业务语义。

## 【原型数据与交互边界】

- 仅可使用组件内 fixture、前端 mock module 或明确的只读原型数据；不得连接 MySQL、API、IndexedDB、SQLite 或浏览器存储作为业务数据源。
- 原型数据必须显式标识为非真实业务数据；不得伪装成已从 API 获取的用户事实。
- 涉及创建、改名、删除、恢复、关联调整、快速捕获、查看真实事项定位的控件均不得调用写入；应禁用，或显示“功能准备中，待数据能力接入”。
- 不得伪造成功、失败、持久化、事务完成、恢复完成或未知写入结果。
- 不得在前端根据标题、时间、状态文案、计数或缓存推断关联、当前事项、历史或复盘摘要。
- 不得以原型 mock 替代 S2 的 MySQL 临时库测试，或成为 S2 / S3 验收证据。

## 【仍然禁止】

```text
API / HTTP 调用或 DTO 映射
任何真实业务读写、写入模拟或浏览器存储持久化
Backup V3、运行库 DDL / DML、migrations/**
IndexedDB / SQLite 接入、双写、同步、回填、fallback
自动关联、多主线、进度、完成率、计划、日期、提醒、子任务、物理清理
对状态机、复盘、方法、回收站、ItemLink 业务语义的改动
将原型视为探索主线 V1 已交付或允许上线
```

## 【并行与后续衔接】

- S2 后端实施仍严格按 `探索主线-V1-S2-RepositoryApplication编码授权.md` 执行；
- 前端原型与 S2 可并行，但不得相互突破冻结边界；
- 用户针对原型提出新灵感时，先由产品判断是视觉调整还是新增业务语义：纯视觉可迭代；新增字段、状态、关系、计划、进度或自动化必须另行评审；
- S2 封板后，仍需完成 S3 的 Backup V3 / API 契约阶段并获得独立授权，前端才可将 fixture 替换为真实 API 读模型并逐项解除控件禁用状态。
