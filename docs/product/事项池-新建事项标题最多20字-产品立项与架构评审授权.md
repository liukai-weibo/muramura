# 新建事项标题最多 20 字：产品立项与架构评审授权

> 日期：2026-07-27
>
> 状态：产品范围已冻结；仅授权架构评审，不授权任何编码或运行库操作。
>
> 当前运行路径、数据源、阶段与禁止事项以 `docs/product/当前运行事实.md` 为准。

## 用户问题

新建“想试试”事项的标题过长时，列表与探索历史难以快速扫读；若只在某个前端入口限制，直接调用既有创建 API 又会产生不一致事实。

## 目标

使所有既有新建事项入口的标题均不超过 20 个用户可见字符，并在前端与服务端得到一致保护。

## 产品冻结规则

1. 标题上限为 20 个 Unicode 字素簇（grapheme cluster），即用户可见字符数；中文单字计 1，组合 emoji 计 1。计数在复用既有标题规范化规则之后进行，不新增新的去空白或大小写语义。
2. 统一适用于所有既有新建事项路径，而非仅限最终为 `idea_to_try` 的入口：全局快速捕获、捕获入口、长期探索内“加入想试试”、方法模块“用此方法开始行动”、“加入以后再说”及其他既有 `POST /api/v1/items` 创建入口均受限。
3. 前端输入达到 20 个字符后不得再接受额外字符；始终显示当前计数 `n/20`。粘贴或输入法提交导致超限时，保留原有合法输入，提示“标题最多 20 个字符”。
4. 服务端必须在任何业务写入前拒绝超限标题，以防直接 API 调用绕过前端。错误复用既有 `400 VALIDATION_FAILED` 与 `requestId` 语义；是否已有适用错误文案和具体映射由架构确认，不新增错误 DTO。
5. 已存在的超过 20 字事项是历史事实：读取、展示、关联、状态迁移、备份与恢复均兼容保留；不迁移、不截断、不清库。既有事项改名行为不属于本项范围。

## 范围

- 新建事项标题的前端输入约束、计数和稳定提示。
- 既有创建契约的服务端前置校验与零写入拒绝保护。
- 覆盖所有既有创建入口及直接 API 绕过的自动化测试。
- 必要产品、架构、QA 记录和当天贡献记录。

## 非目标

- 不改变事项状态机、创建后定位、开始行动、方法应用、探索关联、unknown-outcome 或重试语义。
- 不新增字段、对象、状态、关系、路由、DTO、Migration、数据库结构、备份格式或配置。
- 不限制既有事项，不以标题长度推断业务关系。
- 不实施日程、Todo、标签、优先级、分类或标题自动摘要。

## 验收标准

1. 中文、英文、组合 emoji 与混合文本均按冻结的用户可见字符口径计算；20 个可创建，21 个稳定拒绝。
2. 所有既有创建入口的前端都不可提交超过 20 个字符的标题，并显示一致的计数与提示。
3. 直接调用既有创建 API 发送超限标题返回既有 `400 VALIDATION_FAILED + requestId`；任何业务集合零写入。
4. 合法标题的创建、已有状态定位、方法开始行动、探索刷新及 unknown-outcome 边界不回归。
5. 历史超限标题可正常读取与展示；不发生截断、迁移或写入。

## 当前授权与下一步

本文件仅授权架构师评审最小可信实现方案：确认可复用校验能力、是否必须调整既有输入契约、允许修改的层与文件范围，以及直接测试策略。未经架构结论和后续独立产品编码授权，前端、API、Application、Repository、Contracts、Migration、配置、数据库和运行库均不得修改。
